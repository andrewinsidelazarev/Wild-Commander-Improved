# CORE32: единый API и текущее поведение

Этот документ является цельным справочником по файловому ядру CORE32 в
улучшенной сборке `Wild Commander v1.10i 2026-08-05`. Он описывает:

- официальный файловый API плагинов Wild Commander;
- внутреннюю таблицу WildDOSFileCore по адресу `#4000`;
- API 76 `APPEND` и единый позиционный API 77 `FILEX`;
- исправленное поведение FAT32, каталогов, LFN, FSInfo и потоков;
- ограничения, которые текущая сборка намеренно не скрывает.

Документ соответствует текущему `exe/boot.$C` размером 31761 байт и SHA-256
`76f9b8d18c01684c4fb326549362695377293f62316f72be9159296d5967922b`.
Провайдер API 77 поставляется отдельным `WC/FILEX.WMF`, но входит в штатный
`exe/WC/wc.ini` и устанавливается автоматически. Журнал предыдущих
доказательств и история дефектов находятся в
[`CORE32_audit.md`](CORE32_audit.md).

В обозначениях ниже `#` означает шестнадцатеричное число, `LE32` — четыре
байта little-endian, `Z/NZ` и `CF` — флаги Z80 после возврата.

## 1. Какой интерфейс вызывать

| Вызывающий код | Точка вызова | Как передаётся функция | Назначение |
|---|---:|---|---|
| Обычный плагин WC | `WLD=#6006` | номер `0..86` в `A` | Официальный и рекомендуемый интерфейс |
| Код менеджера/тесно связанный модуль | `#4000+offset` | прямой `CALL` в 31-элементную таблицу | Внутренний ABI CORE32 |
| Само ядро CORE32 | `EXTENSION_GATE=#5123` | приватный байт ID после `CALL` | Деталь реализации, не API плагинов |

Плагин должен вызывать `#6006`. Сам диспетчер только выбирает адрес из таблицы
по номеру в `A`; подключение рабочей файловой страницы, преобразование
состояния менеджера и восстановление отображения выполняют соответствующие
файловые `X*`-обёртки. Прямые вызовы `#40xx` требуют ручного управления
страницами и не являются безопасной заменой публичному API.

Общий шаблон плагинного вызова:

```asm
        ; Остальные входные регистры подготовлены согласно функции.
        LD A,api_number
        CALL #6006
        ; Проверить документированные флаги до любых команд, меняющих F.
```

Если функции нужен входной `A`, плагин передаёт его через `A'`: основной `A`
занят номером API, а диспетчер выполняет `EX AF,AF'` перед целевой процедурой.

Важно: `#6004` — флаг Esc менеджера плагинов. Это не внутренний `ABT` CORE32,
который находится в рабочей файловой странице по адресу `#384A`.

## 2. Модель памяти и состояния

| Диапазон/адрес | Содержимое |
|---:|---|
| `#0000..#1FFF` | Буферы перечисления каталога |
| `#3000..#31FF` | Сектор FAT (`SECBU`) |
| `#3200..#33FF` | Основной секторный буфер (`LOBU`) |
| `#3400..#35FF` | Второй секторный буфер (`LOBU2`) |
| `#37F8..#37FE` | Состояние итератора каталога |
| `#3800` | Таблица и код выбранного драйвера |
| `#3848..#38CC` | Поток, `EOC`, `ABT`, `ENTRY`, BPB/FAT и текущий каталог |
| `#4000..#5BF1` | Установленный код CORE32; `END=#5BF2` |
| страница `#E8`, `#C000..#CE30` | Приватный runtime `CORE32_EXT` во время шлюза |
| страница провайдера, `#C000..#D8FD` | Runtime `FILEX.WMF` во время API 77 |

CORE32 рассчитан на FAT32 с 512-байтовыми секторами. Его секторные буферы,
поток, текущий каталог, `ENTRY`, обработчик `NW0` и контекст APPEND глобальны.
API не является повторно-входимым и не поддерживает параллельные файловые
операции.

Верхние физические страницы распределены по общему системному контракту:

| Полуинтервал страниц | Владелец |
|---:|---|
| `[#A1,#C0)` | временные страницы TAP/SNA-плагина (`#A1..#BF`) |
| `[#C0,#E8)` | RAM-диск Mounter, 40 страниц (`#C0..#E7`) |
| `[#E8,#F0)` | приватные расширения Improved (`#E8..#EF`); сейчас CORE32_EXT использует `#E8` |
| `[#F0,#100)` | штатные страницы Commander/системы (`#F0..#FF`) |

Машиночитаемый источник истины —
[`PHYSICAL_MEMORY_MAP.ASM`](PHYSICAL_MEMORY_MAP.ASM). CORE32, TAP/SNA и оба
исходника Mounter подключают его напрямую; сборочные `ASSERT` запрещают
пересечение или односторонний сдвиг границ. Диапазон `#E8..#EF` резервируется
целиком, поэтому новые приватные страницы Improved должны выделяться только
внутри него.

Перед прямым вызовом `#40xx` рабочая файловая страница должна быть подключена к
окну `#0000`. В текущем WC это делает пара `CORE_PAGE_IN=#6B7A` и
`CORE_PAGE_OUT=#6B8B`. Пара одноуровневая: вложенный вход перезаписывает
единственный сохранённый номер страницы. Все выходы, включая ошибочные, должны
быть сбалансированы.

Обычному плагину нельзя вызывать эту пару напрямую. Файловые `X*`-обёртки API
48–52, 54–63 и 72–77 выполняют переключение сами. API 53 и 55 являются прямым
пустым `FEX` и страниц не меняют. Приватные ID из
[`CORE32_EXT_API.ASM`](CORE32_EXT_API.ASM), адрес страницы `#E8` и внутренние
процедуры `CORE32_EXT` не входят в стабильный ABI.

## 3. Публичный файловый API плагинов WC

Это фактическая файловая часть таблицы `PLUGIN_API_TABLE` из
[`MD20.ASM`](MD20.ASM). Десятичный номер передаётся в `A` при вызове `#6006`.
Номера плагинного API не совпадают с индексами внутренней таблицы CORE32.

| API | Имя | Основной контракт |
|---:|---|---|
| `48 (#30)` | `LOAD512` | `HL` — буфер, `B` — число 512-байтовых блоков; читает текущий поток, возвращает новый `HL` и потоковый статус |
| `49 (#31)` | `SAVE512` | Как `LOAD512`, но записывает существующую цепочку; файл не расширяет и размер не меняет |
| `50 (#32)` | `GIPAGPL` | Позиционирует поток по сохранённому менеджером кластеру |
| `51 (#33)` | `TENTRY` | `DE` — буфер; копирует в него сохранённую 32-байтовую FAT32 ENTRY |
| `52 (#34)` | `CHTOSEP` | `DE` — начало списка LBA32, `BC` — исключающая верхняя граница; раскладывает сохранённую цепочку в сектора |
| `53 (#35)` | reserved | Пустой обработчик; это не APPEND |
| `54 (#36)` | `TMRKFL` | Найти/отметить объект через внутреннее состояние менеджера |
| `55 (#37)` | reserved | Пустой обработчик |
| `56 (#38)` | `ADIR` | Открыть каталог, описанный сохранённым состоянием менеджера |
| `57 (#39)` | `STREAM` | Управление потоком: `D` — поток, `B` — устройство, `C` — раздел; `BC=#FFFF` включает поток `D` |
| `58 (#3A)` | `NXTETY2` | `DE` — выходной буфер, входная маска в `A'`; получить следующую запись каталога |
| `59 (#3B)` | `FENTRY` | `HL` → `[flag,name,0]`; `Z` — не найдено, `NZ` — найдено; сохраняет метаданные и контекст APPEND |
| `60 (#3C)` | `LOAD256` | Потоковое чтение через 256-байтовый обработчик драйвера; поддержка зависит от драйвера |
| `61 (#3D)` | `LOADNONE` | Линейно продвигает поток без копирования данных |
| `62 (#3E)` | `GFILE` | После успешного `FENTRY` позиционирует поток на начало найденного файла |
| `63 (#3F)` | `GDIR` | После успешного `FENTRY` делает найденный каталог активным |
| `72 (#48)` | `MKFILE` | `HL` → `[attr,size_le32,name,0]`; `Z` — создан, `NZ` — ошибка |
| `73 (#49)` | `MKDIR` | `HL` → имя с нулём; `Z` — создан, `NZ` — ошибка |
| `74 (#4A)` | `RENAME` | `HL` → старое `[flag,name,0]`, `DE` → новое имя с нулём |
| `75 (#4B)` | `DELFL` | `HL` → `[flag,name,0]`; удаляет запись и цепочку, но не защищает непустой каталог |
| `76 (#4C)` | `APPEND` | `HL` — буфер, `BC=0..#4000` (16 КиБ); дописывает в конец последнего успешно найденного файла |
| `77 (#4D)` | `FILEX` | `HL` → 32-байтовый блок; позиционное чтение/запись, EOF32, сведения о томе, move/rename и metadata |

Формат поиска `FENTRY`/`DELFL`: первый байт `#00` означает файл, `#10` —
каталог, затем идёт имя и завершающий ноль. Текущий валидатор принимает имя до
255 байт, отвергает 256 байт, управляющие символы и `"*/:<>?\|`. Конечные
пробелы и точки отрезаются с изменением входного буфера. Любой пробел заставляет
создать LFN; начальные пробелы при поиске LFN игнорируются симметрично, а
внутренние остаются значимыми.

`MKFILE` поддерживает нулевой размер: создаётся пустой файл с `size=0`,
`cluster=0` и без выделенной FAT-цепочки. Публичный путь проверяет ноль до
входа в `MKSG`. Прямой внутренний `MKSG` рассчитан только на положительный
размер и не должен вызываться с `DE:HL=0`.

Сохранившиеся C-копии `wc_api.h` содержат исторические неточные подписи:
`API 58` является `NXTETY2`, а создание файла выполняет `API 72`; `LOAD256` и
`LOADNONE` подключены, хотя были помечены `reserved ???`. Фактическими
источниками истины являются таблица `MD20.ASM` и этот документ.

## 4. API 76 APPEND

### 4.1 Назначение и выбор файла

`APPEND` дописывает один диапазон длиной до 16 КиБ в файл, найденный последним
успешным `FENTRY`.
Официальный вызов плагина — `A=76`, `CALL #6006`; внутренний вход CORE32 —
`+#27/#4027`.

Обязательная последовательность для ненулевой записи:

1. Вызвать API 59 `FENTRY` для нужного файла.
2. Немедленно проверить `NZ`.
3. Подготовить `HL/BC` и вызвать API 76.
4. После каждого APPEND немедленно проверить `Z/NZ`.

`GFILE` для APPEND не нужен. Последовательные успешные вызовы используют
кэшированное положение EOF и базовый LBA текущего кластера, поэтому не обходят
FAT от начала и не повторяют `GIPAG`, пока остаются в том же кластере. Ключ
кэша содержит номер кластера, `BSECPC`, `SDFAT` и `ADDTOP`; несовпадение
превращается в безопасный промах. Повторный успешный `FENTRY` того же файла
заново вычисляет EOF из 32-битного размера и цепочки и инвалидирует LBA-кэш.

Контекст один на всё ядро и заменяется каждым успешным `FENTRY`. Неуспешный
`FENTRY` старый контекст не очищает. Если проигнорировать его `Z`, последующий
APPEND способен дописать предыдущий успешно найденный файл.

### 4.2 Вход и результат

| Регистр/флаг | Контракт |
|---|---|
| `HL` | Начало исходного буфера |
| `BC` | Число байт `0..#4000` (16 КиБ) |
| Диапазон | Весь полуинтервал `[HL,HL+BC)` должен лежать в `#4000..#C000` |
| Успех | `Z`, `A=0`; при `BC>0` `HL` указывает сразу за использованными данными |
| Ошибка | `NZ`, `A` содержит код; число фактически изменённых байт не сообщается |

Последний читаемый байт не может находиться выше `#BFFF`; конец ровно
`#C000` допустим. Переполнение 16-битного адреса является ошибкой. Текущая
реализация сохраняет `DE`; `BC` и незаявленные регистры следует считать
разрушенными. `CF` результатом APPEND не является и нормализуется в ноль.

Особый случай: `BC=0` безусловно возвращает `Z/A=0`, не проверяя `HL`, контекст
`FENTRY`, тип объекта или состояние цепочки. Это только пустая операция, а не
способ проверить готовность файла.

### 4.3 Порядок записи

Для ненулевого диапазона CORE32 выполняет:

1. Только на первом APPEND после успешного `FENTRY`: полную сверку SFN,
   проверку типа/размера, обход FAT до EOF и создание кэшированного контекста.
2. Вычисление нового 32-битного размера.
3. Вычисление места, оставшегося в текущем кластере. Если его недостаточно —
   единое выделение всей недостающей FAT-цепочки через `MKSG`; новая цепочка
   остаётся отсоединённой от прежнего файла до commit.
4. Запись данных: неполные секторы проходят через read-modify-write, а полные
   последовательные секторы внутри одного кластера передаются драйверу одним
   многоблочным вызовом. Успешный commit сохраняет базовый LBA для следующего
   APPEND; на каждой границе кластера либо при смене геометрии он вычисляется
   заново.
5. Во время commit — связывание старого хвоста с головой заранее выделенной
   цепочки.
6. Обновление FSInfo.
7. Полную сверку сохранённой SFN-записи с каталогом на диске.
8. Последней операцией — запись первого кластера и нового 32-битного размера.

Максимальный вызов `BC=#4000` содержит 32 сектора и при минимальном
одно-секторном кластере может выделить 32 кластера. Пустой файл с `cluster=0`
получает первый кластер только при первой ненулевой записи. Время изменения и
атрибуты файла APPEND не обновляет; отдельной проверки атрибута read-only нет.

После первого успешного вызова последующие вызовы доверяют кэшированному EOF до
фазы commit и не выполняют предварительную сверку SFN перед записью данных.
Если другой код изменит запись между блоками, commit обнаружит это только
после записи очередных данных и вернёт `#23`. Контекст не является блокировкой.

Этот порядок публикует новый размер последним, но не является атомарной
транзакцией и не обеспечивает устойчивость к потере питания.

### 4.4 Откат

Если была выделена новая цепочка и последующая стадия завершилась ошибкой,
APPEND пытается восстановить прежнюю EOC-ссылку, освободить всю новую цепочку
и обновить FSInfo. Признак связанной цепочки выставляется до записи FAT:
неоднозначный отказ драйвера также запускает восстановление старой ссылки.
При успешном откате возвращается исходная ошибка; при ошибке компенсации —
`APPEND_ERR_ROLLBACK`.

Откат не восстанавливает уже записанные секторы данных. При сбое записи
каталога, потере питания или неоднозначном ответе устройства нельзя по одному
коду возврата определить, был ли новый размер опубликован. Журнала и ключа
идемпотентности API не предоставляет.

### 4.5 Коды ошибок

| Код | Имя | Значение |
|---:|---|---|
| `#20` | `APPEND_ERR_CONTEXT` | Нет действительного контекста успешного `FENTRY` или положение SFN недопустимо |
| `#21` | `APPEND_ERR_BUFFER` | Буфер вне `#4000..#BFFF`, пересекает `#C000` или адрес переполняется |
| `#22` | `APPEND_ERR_LENGTH` | `BC>#4000` |
| `#23` | `APPEND_ERR_ENTRY_CHANGED` | 32-байтовая SFN-запись изменилась после `FENTRY` |
| `#24` | `APPEND_ERR_SIZE_OVERFLOW` | Новый размер превысил `#FFFFFFFF` |
| `#25` | `APPEND_ERR_BAD_CHAIN` | Недопустимый кластер/ссылка, преждевременный EOC либо любой отказ `CURIT`, включая границу FAT или чтение; это не обязательно доказанная порча на диске |
| `#26` | `APPEND_ERR_IS_DIRECTORY` | Контекст относится к каталогу |
| `#27` | `APPEND_ERR_INTERNAL` | Внутренне противоречивое состояние выделения/фиксации |
| `#2A` | `APPEND_ERR_ROLLBACK` | Компенсирующий откат FAT/FSInfo не завершился |

Список не исчерпывает все `NZ`: наружу могут пройти `#10` от `MKSG`
(нет места/ошибка выделения), `#01` и иной ненулевой код `ABT` драйвера.
Вызывающий код обязан считать ошибкой любое `NZ`, а не только известные
константы.

Слепой повтор блока после ошибки запрещён. До записи носителя гарантированно
возникают `#21/#22/#24`: после `#21/#22` можно исправить аргументы, а после
`#24` — уменьшить положительный блок, только если он ещё помещается в
`#FFFFFFFF`. Во всех неоднозначных случаях нужно заново выполнить успешный
`FENTRY`, проверить фактический размер и при необходимости содержимое. После
`#2A` состояние FAT считается неопределённым до проверки файловой системы.

### 4.6 Минимальный пример

```asm
WLD             EQU #6006

        LD HL,FILE_QUERY
        LD A,59                  ; FENTRY
        CALL WLD
        JR Z,.not_found          ; обязательно: старый APPEND-контекст жив

        LD HL,DATA_BUFFER
        LD BC,DATA_SIZE          ; 1..512
        LD A,76                  ; APPEND
        CALL WLD
        JR NZ,.append_error      ; A содержит код; блок вслепую не повторять
        ; успех

FILE_QUERY:
        DB #00,"LOG.BIN",0

DATA_BUFFER:
        DS 512
DATA_SIZE       EQU 512
```

`DATA_BUFFER` в реальном плагине должен целиком находиться в разрешённом
runtime-диапазоне `#4000..#BFFF`, а не только иметь подходящий файловый offset.

## 5. API 77 FILEX

### 5.1 Установка и общий вызов

API 77 — единая расширяемая точка для операций, которых нет в историческом
регистровом ABI. Канонические константы находятся в
[`CORE32_FILEX_API.ASM`](CORE32_FILEX_API.ASM). Провайдер
`WC/FILEX.WMF` должен быть первой строкой секции `[PLUGINS]`: это одноразовый
плагин типа `#06`, который публикует свою физическую страницу и удаляется из
пользовательского меню. Если провайдер не установлен, возвращается
`FILEX_STATUS_NO_CONTEXT`.

Вызов:

```asm
        LD HL,FILEX_BLOCK
        LD A,77
        CALL #6006
        ; Z и A=0 — успех; NZ и A=status — EOF или ошибка.
```

`HL` указывает на блок ровно из 32 байт. Блок, буферы данных, имена и выходные
структуры обязаны целиком находиться в постоянном окне `#8000..#BFFF` и не
пересекать блок параметров. Максимальная длина одного чтения или записи —
`#4000` байт, конец диапазона ровно `#C000` допустим. Нулевой буфер допустим
только для операции с нулевой длиной.

На выходе `A` и поле `status` содержат один код; `Z` установлен только для
`OK=#00`. `result_count` — 32-битный результат операции. AF, BC, DE, HL и IX
считаются разрушенными, IY сохраняется. API глобален и нереентерабелен: один
сериализованный вызов может использовать CORE32 и VFS за раз.

### 5.2 Блок параметров версии 1

| Смещение | Размер | Поле | Назначение |
|---:|---:|---|---|
| `0` | 1 | `size` | Ровно `32` |
| `1` | 1 | `version` | Ровно `1` |
| `2` | 1 | `operation` | Номер `0..7` |
| `3` | 1 | `flags` | Флаги выбранной операции |
| `4` | 4 | `offset` | Позиция файла либо новый EOF, LE32 |
| `8` | 2 | `buffer` | Данные, выходная структура либо исходное имя |
| `10` | 2 | `length` | Длина `buffer` |
| `12` | 2 | `aux` | Второе имя для move/rename |
| `14` | 2 | `aux_length` | Длина `aux` |
| `16` | 4 | `source_dir` | Кластер родительского каталога источника |
| `20` | 4 | `dest_dir` | Кластер родительского каталога назначения |
| `24` | 4 | `result_count` | Фактические байты, новый размер или capabilities |
| `28` | 1 | `status` | `FILEX_STATUS_*` |
| `29` | 1 | `result_flags` | Дополнительный результат операции |
| `30` | 2 | `reserved` | На входе обязательно ноль |

Перед каждым вызовом следует занулить весь блок, затем записать `size`,
`version`, `operation` и нужные поля. Неиспользуемые биты `flags` запрещены.

### 5.3 Операции

| Код | Операция | Контракт |
|---:|---|---|
| `0` | `QUERY_CAPS` | `flags=0`; `result_count.low=#FF` сообщает семь операций, current-directory replace и чтение активной FAT, `result_flags=1` — версия ABI |
| `1` | `READ_AT` | После успешного `FENTRY`: `offset`, `buffer`, `length=0..#4000`; не читает предшествующие сектора, `result_count` — реально прочитанные байты |
| `2` | `WRITE_AT` | После `FENTRY`: позиционная RMW-запись; разрыв за старым EOF заполняется нулями, `result_count` — записанные байты |
| `3` | `SET_EOF32` | После `FENTRY`: `offset` — новый размер; поддерживает 0, усечение и нулевое расширение; `result_count` — итоговый EOF |
| `4` | `GET_FS_INFO` | `buffer` минимум 48 байт; возвращает геометрию BPB, FAT/FSInfo, serial и label |
| `5` | `MOVE_RENAME` | Два запроса `[тип,имя,0]`, их длины и два кластера родителей; `REPLACE` разрешает безопасную замену |
| `6` | `SET_METADATA` | После `FENTRY`: 16-байтовая структура атрибутов и времён FAT |
| `7` | `READ_FAT` | Секторно выровненное окно выбранной активной FAT: `offset` от её начала, `buffer`, `length=512..#4000`; `result_count` — прочитанные байты |

`READ_AT` возвращает `EOF=#01`, если `offset>=size` или запрос выполнен лишь до
EOF; во втором случае `result_count` всё равно содержит прочитанный префикс.
Нулевая длина возвращает `OK` и ноль. Позиционирование вычисляет нужный кластер
и сектор непосредственно; линейный `LOADNONE` не используется.

Перед любым ростом `WRITE_AT` или `SET_EOF32` провайдер проверяет всё требуемое
место до первой изменяющей записи. Проверка ограничена реальным числом
data-кластеров из BPB и не принимает нулевой padding последнего сектора FAT за
свободное место. При полном томе возвращается `NO_SPACE=#22`, размер и первый
кластер пустого файла остаются нулевыми. Новый размер публикуется только после
успешной записи данных, FAT и FSInfo. Уже перезаписанные байты внутри старого
EOF при позднем I/O-сбое не откатываются.

При усечении неиспользуемый хвост последнего сектора зануляется, новая ENTRY
публикуется до отсоединения лишней цепочки, затем хвост освобождается и
обновляется FSInfo. Ошибка очистки после уже опубликованного размера
возвращается как `COMMITTED_CLEANUP=#25`; это успешный commit с незавершённой
служебной очисткой, а не старый размер.

Для `MOVE_RENAME` оба имени имеют тот же формат, что `FENTRY`: первый байт
`#00` для файла или `#10` для каталога, затем непустое имя и ноль внутри
переданной длины `3..257`. Типы источника и назначения должны совпадать.
Флаг `FILEX_FLAG_REPLACE=#01` разрешает заменить объект назначения; непустой
каталог не заменяется, а перенос каталога в собственного потомка запрещён.
При переносе каталога между родителями обновляется его запись `..`. Активный
каталог CORE32 восстанавливается перед возвратом.

Флаг `FILEX_FLAG_CURRENT_DIR=#02` подставляет активный каталог WildDOS сразу
как source и destination, не заставляя обычный плагин читать приватный
`LSTCAT`. Перед использованием проверяется capability
`FILEX_CAP_MOVE_CURRENT_DIR=#40`; без него вызывающий оставляет прежний путь.

`READ_FAT` читает FAT0 при включённом зеркалировании либо копию, выбранную
`BPB_ExtFlags`, когда зеркалирование отключено. Смещение и длина кратны 512,
а конец окна не может выходить за `BFTSZ`. Операция предназначена для точного
внешнего кэша состояния кластеров без подмены неизвестного `FSInfo.Free_Count`
условной ёмкостью.

### 5.4 GET_FS_INFO и metadata

Структура `GET_FS_INFO` имеет `size=48`, `version=1` и содержит:

- флаги media present, writable/write-state-known, free-known и label-valid;
- 512 байт на сектор, секторов на кластер, общее число кластеров и секторов;
- `free_clusters` и `next_free` либо `#FFFFFFFF`, если FSInfo не даёт
  проверяемого значения;
- serial, 11-байтовый label с завершающим нулём;
- число FAT, активную FAT, младший байт `BPB_ExtFlags` и размер FAT в секторах.

Текущий драйверный ABI не сообщает надёжный аппаратный write-protect, поэтому
`WRITE_STATE_KNOWN` выставляется только при появлении такого источника; его
отсутствие означает «неизвестно», а не «носитель только для чтения». Флаг
вызова `REFRESH_FREE=#01` зарезервирован в версии 1; текущий результат берётся
из проверенного FSInfo, а неизвестное значение не подменяется условным числом.

Структура `SET_METADATA` имеет `size=16`. `attr_mask/attr_value` разрешают
только FAT-биты `read-only`, `hidden`, `system`, `archive` (`#27`), а
`time_mask` независимо выбирает create/access/write. Далее передаются create
tenth, create time/date, access date и write time/date в формате FAT.
`applied_attr` возвращает фактически сохранённые атрибуты. Для read-only файла
сначала разрешено снять сам read-only; прочие изменения до этого возвращают
`READ_ONLY=#18`.

### 5.5 Стабильные статусы

| Код | Имя | Значение |
|---:|---|---|
| `#00` | `OK` | Операция полностью завершена |
| `#01` | `EOF` | Конец файла, включая частичное чтение |
| `#10..#16` | `BAD_BLOCK`…`ENTRY_CHANGED` | Ошибка ABI, диапазона либо изменившегося контекста |
| `#17/#18` | `IS_DIRECTORY` / `READ_ONLY` | Запрещённый тип или атрибут |
| `#19..#1D` | `NOT_FOUND`…`INVALID_MOVE` | Ошибки имени, collision, непустого каталога или цикла |
| `#20` | `FAT` | Недопустимая FAT-цепочка или геометрия |
| `#21` | `MEDIA` | Низкоуровневый отказ чтения/записи |
| `#22` | `NO_SPACE` | Недостаточно реальных data-кластеров/слотов |
| `#23` | `SIZE_OVERFLOW` | Смещение, длина или новый размер вышли за LE32 |
| `#24` | `ROLLBACK` | Компенсация после ошибки сама не завершилась |
| `#25` | `COMMITTED_CLEANUP` | Результат опубликован, последующая очистка не завершилась |
| `#26` | `INTERNAL` | Внутренне противоречивое состояние |

Полный машинно-читаемый список смещений, флагов и кодов следует брать из
`CORE32_FILEX_API.ASM`, а не дублировать числовые литералы в плагине.

## 6. Внутренняя таблица CORE32

`START=#4000` содержит 31 стабильный трёхбайтовый `JP`. Адрес входа равен
`#4000+offset`; таблица предназначена для WC/WildDOS и требует подключённой
рабочей страницы `#0000`.

| Offset / адрес | Имя | Фактический контракт |
|---:|---|---|
| `+#00 / #4000` | reserved | Пустой `RET`; `SELDEV` находится в драйвере `#3800` |
| `+#03 / #4003` | `DEVINI` | Инициализировать установленный драйвер; обычно `Z` — успех |
| `+#06 / #4006` | reserved | Пустой `RET`; `REINI` находится в драйвере `#3806` |
| `+#09 / #4009` | `HDD` | Найти FAT32 и заполнить BPB/FAT-параметры; `Z` — успех, `NZ` — не найдено/ошибка |
| `+#0C / #400C` | `RDD` | `DE:HL=LBA`, `BC=буфер`, `A=секторы`; `Z/NZ` по `ABT` |
| `+#0F / #400F` | `SDD` | Как `RDD`, но запись |
| `+#12 / #4012` | `GIPAG` | `HL` → `cluster32`, ноль означает root; позиционировать на первый сектор |
| `+#15 / #4015` | `LOAD512` | `HL=буфер`, `B=секторы`; потоковое чтение и статус EOC/error |
| `+#18 / #4018` | `SAVE512` | Как `LOAD512`, но запись существующей цепочки без изменения размера |
| `+#1B / #401B` | `DOS_SWP` | `A=0..6`: Nemo master, SD-ZC, SD-NGS, SMUC master/slave, Nemo slave, второй ZC |
| `+#1E / #401E` | `GLSTCAT` | Историческое имя: фактически копирует `cluster32` из `HL` в `LSTCAT` и сбрасывает итератор |
| `+#21 / #4021` | `TLSTCAT` | Историческое имя: фактически копирует текущий `LSTCAT` в четыре байта по `DE` |
| `+#24 / #4024` | `SRHFCL` | Найти свободный кластер от `FSTFRC`; успех `DE:HL/Z`, ошибка `CF=1` |
| `+#27 / #4027` | `APPEND` | Внутренний вход API 76; контракт раздела 4 |
| `+#2A / #402A` | `MKSG` | `DE:HL=положительный размер`; создать цепочку, первый кластер вернуть через `FCTS`; ноль запрещён |
| `+#2D / #402D` | `FILEX_GATE` | Внутренний шлюз API 77 к одностраничному провайдеру `FILEX.WMF` |
| `+#30 / #4030` | `RFRH` | Проверить и обновить FSInfo; `Z` — успех, `NZ` — сигнатуры/I/O |
| `+#33 / #4033` | `GENTRY` | Фактически копирует 32 байта из `HL` во внутреннюю `ENTRY` |
| `+#36 / #4036` | `TENTRY` | Копирует `ENTRY` в `DE`, сохраняет `A/S/Z/C` и фиксирует контекст APPEND; `LDIR` меняет остальные флаги |
| `+#39 / #4039` | `MKFILE` | `HL` → `[attr,size_le32,name,0]`; `Z` — успех |
| `+#3C / #403C` | `MKDIR` | `HL` → `name,0`; создаёт `.`/`..`, `Z` — успех |
| `+#3F / #403F` | `DELFL` | `HL` → `[flag,name,0]`; удалить запись и цепочку |
| `+#42 / #4042` | `RENAME` | `HL` → старое `[flag,name,0]`, `DE` → новое `name,0` |
| `+#45 / #4045` | `DLSG` | `HL` → `cluster32`; освободить цепочку, стабильного прикладного статуса нет |
| `+#48 / #4048` | `CHTOSE` | `HL` → `cluster32`, `DE` — список LBA32, `BC` — конец буфера |
| `+#4B / #404B` | reserved | Пустой `RET` |
| `+#4E / #404E` | `SRHDRN` | `HL` → `[flag,name 1..255,0]`; `NZ` — найдено, `ENTRY` заполнена |
| `+#51 / #4051` | `LOAD256` | Поток через драйверный 256-байтовый обработчик; не все драйверы реализуют его |
| `+#54 / #4054` | `LOADNON` | `B` — число секторов; пройти поток без копирования |
| `+#57 / #4057` | `NXTETY` | `DE` — выход полной записи каталога |
| `+#5A / #405A` | `NXTETY2` | `DE` — выход, `A` — маска полей и типа записи |

Направления `GLSTCAT/TLSTCAT` и `GENTRY/TENTRY` приведены по фактическим
`LDIR`, а не по исторической букве в имени.

Для `NXTETY2` маска имеет следующий вид:

- бит 7 — выдавать только короткое имя;
- бит 4 — добавить время создания;
- бит 3 — добавить дату создания;
- бит 2 — добавить размер;
- биты 1..0: `0` — любой объект, `1` — файл, `2` — каталог.

Прямые `SRHDRN/NXTETY/NXTETY2` не дают отдельного надёжного прикладного кода
для каждой ошибки чтения: часть отказов исторически выглядит как «не найдено»
или конец перечисления. Публичные обёртки сохраняют совместимость с этим ABI.

## 7. Контракт потоков

Для нормального потока и явно возвращённой драйвером ошибки `ABT` у
`LOAD512`, `SAVE512`, `LOAD256` и `LOADNON` действует результат:

| Состояние | `A` | `CF` | Значение |
|---|---:|---:|---|
| Запрос завершён внутри цепочки | `#00` | `0` | Можно продолжать поток |
| Достигнут физический EOC FAT | `#0F` | `0` | Штатный конец цепочки |
| Возвращённая ошибка I/O/FAT | `#FF` | `1` | Операцию остановить |

`#0F` означает конец FAT-цепочки, а не отдельный 32-битный логический offset.
При нескольких секторах на кластер завершённый короткий запрос может вернуть
`A=0`, если EOC ещё не читался.

Известное исключение внутреннего пути: при переходе к следующему кластеру
последовательность `CALL CURIT,GIPAG` пока не проверяет `CF` от `CURIT`
отдельно до `GIPAG`. Поэтому отказ чтения/границы FAT именно на этом переходе
не доказан как обязательный `#FF/CF=1`. Таблица выше является контрактом
нормализованных путей, но не заменяет проверку размера и состояния носителя.

`SAVE512` намеренно сохраняет историческую семантику: он пишет только уже
существующую цепочку, не выделяет новый кластер и не обновляет размер SFN.
Для роста файла используется только APPEND.

Низкоуровневые `RDD/SDD` возвращают `Z/NZ` по внутреннему `ABT`; их `CF` не
является потоковым результатом. Старый драйвер, который зависает до возврата
или не выставляет `ABT`, не может быть превращён высокоуровневой обёрткой в
управляемую ошибку.

## 8. Исправленное поведение FAT32

### FAT и кластеры

- При включённом зеркалировании изменения записываются во все FAT.
- При `BPB_ExtFlags.bit7=1` изменяется и читается только выбранная активная FAT.
- Служебный старший полубайт FAT32 маскируется при чтении и сохраняется при записи.
- Обычный кластер, EOC `#0FFFFFF8..#0FFFFFFF` и недопустимый диапазон
  `#0FFFFFF0..#0FFFFFF7` различаются явно.
- Доступ к FAT ограничен полным 32-битным `BFTSZ`; поиск свободного кластера
  корректно переходит между секторами и один раз оборачивается к кластеру 2.
- Нулевой файл создаётся с `size=0`, `cluster=0` и без выделенной цепочки.

### FSInfo

- Перед записью проверяются lead, structure и trail signatures.
- `FSI_Free_Count` записывается как `#FFFFFFFF` («неизвестно, пересчитать»).
- `FSI_Nxt_Free` получает безопасную подсказку `FSTFRC` либо `#FFFFFFFF`.
- При плохих сигнатурах сектор не перезаписывается и возвращается `NZ`.

### Каталоги, SFN и LFN

- Удаление LFN проверяет sequence/checksum и гасит до 20 связанных LFN-слотов
  через максимум три секторных буфера; SFN записывается последней.
- Имя длиной 255 байт принимается, 256 — отвергается.
- 255-байтовая LFN может быть найдена и удалена через три сектора каталога.
- Пробел в имени принудительно выбирает LFN; начальные пробелы поиска
  нормализуются с обеих сторон, внутренние пробелы остаются значимыми.
- Полностью заполненный каталог без маркера `#00` корректно заканчивает поиск
  по EOC вместо повторного разбора устаревшего буфера.
- `MKDIR` прекращается при ошибке записи и зануляет хвост выделенного кластера.

### Ошибки и монтирование

- Высокоуровневые чтения/записи используют единый `ABT` и прекращают операцию
  после возвращённой ошибки драйвера.
- `LOAD256/LOADNON` временно устанавливают свой `NW0` и восстанавливают
  прежний обработчик с сохранением `AF/CF`.
- Прямой `LOAD512` нормализует `NW0` к `SAFE_RDDSE`; `SAVE512` временно ставит
  `SAFE_SDDSE`, а общий эпилог возвращает `SAFE_RDDSE`, не произвольную прежнюю
  цель.
- Страница расширения `#E8` отключается на время PIO-записи Nemo, поэтому
  драйвер видит исходный буфер, а не код расширения.
- Неверный superfloppy BPB возвращает ошибку вместо бесконечного повторного
  чтения сектора 0.

## 9. Ограничения и обязательные предостережения

- Боевой `DR2` использует точный штатный `DOSpSDZC35.CPD` без runtime-патча.
  Его ожидания `WTDO/WAIT/WTBY/DRESP` могут быть бесконечными; аналогичный риск
  есть у `DSDNGS`. Физический timeout текущего boot не считается пройденным.
- `DELFL` не запрещает удаление непустого каталога. Кроме того, его
  исторические флаги не позволяют надёжно отличить некоторые ошибки записи от
  «не найдено/удалено». Проверку пустоты должен выполнить вызывающий код.
- Исторические API 48–76 сами по себе по-прежнему не дают `TRUNCATE` и
  позиционную запись. Эти операции доступны только через API 77 и требуют
  установленного `FILEX.WMF`; `LOADNONE` остаётся линейным старым путём.
- `APPEND` принимает не более 16 КиБ, хранит один глобальный контекст и не
  обновляет timestamp/read-only policy.
- `NW0`, итератор каталога, APPEND и FILEX нереентерабельны; параллельные или
  вложенные файловые операции не поддерживаются.
- Откат метаданных best-effort. Нет журнала, recovery после потери питания и
  гарантированно атомарной публикации между FAT, FSInfo и каталогом.
- `WRITE_AT` гарантирует безопасную публикацию размера, но не восстанавливает
  уже перезаписанные байты внутри прежнего EOF после поздней ошибки носителя.
- Аппаратный write-protect текущие драйверы достоверно не сообщают; отсутствие
  `WRITE_STATE_KNOWN` в `GET_FS_INFO` следует трактовать как неизвестность.
- `LOAD256` зависит от драйвера; в текущем SD-NGS его вход `RDD256` пустой.
- Для API 77 инъектированы отказы каталога, metadata, FAT и FSInfo, а полный
  FAT доказан на образе. Потеря питания, реальные очень большие носители,
  NGS/SMUC/slave и одновременные операции не проверялись.
- Текущий `76f9b8d1…` собран и проверен в патченном Unreal. Это не является
  доказательством работы FILEX на реальном ZX Evolution; UI-циклы F5/F8 и
  аппаратные накопители для этого exact-бинарника отдельно не проверялись.

## 10. Подтверждённое тестовое покрытие

Исторический exact `boot.$C` с SHA-256
`f1234d96552c5b61f4bf3b091472279d5fd24983fd9a8cea5ff1bd82323ee498` прошёл в
патченном Unreal:

- `SPC=1`, mirrored FAT;
- `SPC=1`, active FAT1 без зеркалирования;
- `SPC=8`, mirrored FAT;
- `SPC=8`, active FAT1 без зеркалирования;
- штатные UI-циклы F5/F8 на SD-ZC и между SD-ZC/Nemo.

Во всех четырёх CORE32T-режимах основной результат равен
`stage=8 completed=8`, LFN-результат — `completed=10`. APPEND проверен блоками
`3+509+1+511+512+17+100+400=2053` байта, включая повторный `FENTRY`, переходы
секторов/кластеров, точный payload, пять кластеров и нулевой хвост последнего
сектора.

CORE32T дополнительно содержит вызов `BC=#4000` из точного окна
`#8000..#BFFF`, проверку размера 16 КиБ и ожидаемой цепочки из 32 кластеров при
`SPC=1`, а также отказы для `BC=#4001` и диапазона, пересекающего `#C000`.
Базовый exact-бинарник APPEND 16 КиБ прошёл этот сценарий в четырёх режимах: `SPC=1/8`,
mirrored FAT и active FAT1. Во всех образах основной результат равен
`stage=8 completed=8`, LFN-результат — `stage=255 completed=10`;
`APP16K.BIN` имеет размер 16 384 байта и цепочку из 32 либо четырёх кластеров.

Рабочая версия с постоянным LBA-кэшем добавляет runtime-счётчик: два APPEND
`3+509` байт в одном кластере должны вызвать внутренний `GIPAG` ровно один раз.
Собранный машинный код отдельно прошёл
`tests/core32_unreal/test_append_lba_cache.py`: межвызовное попадание и промахи
после смены кластера/`BSECPC`/`SDFAT`/`ADDTOP`. CORE32-базис `55dfe646…`
прошёл полный CORE32T во всех четырёх режимах `SPC=1/8`, mirrored FAT и active
FAT1: основной результат `stage=8 completed=8 append_gipag=1`, LFN-результат
`stage=255 completed=10`. Текущий машинный код повторно проходит тест кэша.

Для текущего `boot.$C` (`76f9b8d18c01684c4fb326549362695377293f62316f72be9159296d5967922b`)
провайдер FILEX проверен отдельным плагином `FILEXT.WMF` после штатного
F10/Enter и нормального `File -> Exit` Unreal:

- `SPC=1`, mirrored FAT: `status=#01`, `completed=7`, четыре вызова чтения для
  фрагментированного позиционного диапазона, все четыре отказа `#21`;
- `SPC=8`, active FAT1 (`BPB_ExtFlags=#0081`): тот же результат всех семи
  операций и проверка только активной копии FAT;
- после нового открытия образов совпали размеры, побайтовое содержимое и
  SHA-256 результата `WRITE_AT`;
- отдельный полностью заполненный `SPC=1`-образ вернул API/block status
  `NO_SPACE=#22`; пустой файл сохранил `size=0/cluster=0`, свободных кластеров
  и orphan-цепочек — ноль, размер образа не вырос.

`test_filex_abi.py` проверяет адреса `XFILEX=#6AFD`, шлюза `#6A47`, операнда
страницы `#6A48`, внутренний слот `#402D`, типы плагинов, размер блока и восемь
кодов операций. `FILEXT.WMF` покрывает QUERY_CAPS, READ_AT, WRITE_AT,
SET_EOF32, GET_FS_INFO, MOVE_RENAME, SET_METADATA, границы
секторов/кластеров, замену, циклический move и откаты после отказов
каталога/FAT/FSInfo/metadata. Отдельный машинный тест проверяет `READ_FAT` на
окнах выбранной активной FAT и отказ при выходе за `BFTSZ`.

Также проверены пустой файл, SFN/LFN и пробелы, удаление полного LFN-прогона,
границы FAT и FSInfo, полный каталог без `#00`, имена 255/256, неверный BPB и
возврат потоковой ошибки. Тест штатного бесконечного `WTDO` намеренно
пропускается и не является частью PASS отказного пути.

Эмуляторные результаты подтверждают только машинный код, FAT-образы и
эмуляторный драйвер. Они не заменяют отдельные UI- и аппаратные проверки
текущего полного бинарника.
