# UNZIP.WMF for Wild Commander Improved

Плагин запускается по `Enter` на файле с расширением `.ZIP` и извлекает его
содержимое в текущий каталог активной панели на том же устройстве. Вложенные
каталоги создаются рекурсивно. В окне отображаются процентный progress bar и
строка `unziping: <текущий путь>`.

Поддерживаются ZIP methods 0 (`Stored`) и 8 (`Deflate`), fixed/dynamic/stored
Deflate blocks, CRC32, обычные 32-битные data descriptors, имена CP866 и
UTF-8 с преобразованием русских букв в CP866. ZIP64, шифрование и иные методы
сжатия отклоняются с сообщением об ошибке. Абсолютные пути и компоненты `..`
не извлекаются за пределы текущего каталога.

Поддерживается до 63 вложенных каталогов. Полный нормализованный путь занимает
не более 383 байт CP866, один компонент имени — не более 255 байт.

Если файл уже существует, запрос `[Y] Yes  [N] No  [A] All  [Esc] Cancel`
появляется сразу после чтения имени — до распаковки, создания временного файла
и записи на устройство:
`Y` или `Enter` заменяет его, `N` оставляет старый файл и продолжает распаковку,
`A` заменяет без следующих запросов, `Esc` отменяет операцию.

После ответа `Y`/`A` данные создаются под свободным временным именем
`WCUZnnn0.$$$` и только после проверки размера и CRC32 заменяют целевой файл.
Ответ `N` не создаёт временный файл и не пишет пропущенную запись на устройство.
Через FILEX плагин сначала читает число записей из EOCD. Если отклонённый файл
последний (в том числе единственный), плагин сразу завершает работу: сжатые
данные и data descriptor вообще не читаются. Если после него есть записи или
FILEX/EOCD недоступны, используется безопасный последовательный fallback.
При известном размере данные читаются буферами `LOAD512`, но не распаковываются
и не записываются. В этот момент строка состояния показывает
`skipping: <путь>`, а процент не изображает распаковку.
`LOADNONE` здесь намеренно не используется: его смешивание с уже заполненным
входным буфером рассинхронизирует поток на реальном устройстве. Неизвестный
поток Deflate с data descriptor разбирается только в ОЗУ, чтобы найти следующую
запись ZIP. Если после `N` каталог не изменился, окно закрывается без фиктивного
экрана `100% done`.

После изменения каталога плагин штатно возвращает Wild Commander код `3`.
Commander восстанавливает страницы плагина и затем перечитывает активную панель,
из которой был запущен ZIP. Плагин не вызывает внутренний `FOLD` до возврата:
эта процедура использует область `#8000` и может затереть выполняемый плагин.

## Скорость

С сентября 2026 плагин целиком написан на ассемблере Z80 (`src/unzip.asm`,
ядро распаковки — `src/inflate.asm`) вместо прежней версии на C (SDCC).

- Коды Хаффмана длиной до 8 бит (в реальных архивах около 94 % символов)
  узнаются одним чтением таблицы, более длинные — каноническим разбором;
  повторы копируются `LDIR` прямо в кольцо истории 32 КиБ.
- CRC32 считается по таблице из четырёх 256-байтовых плоскостей.
- Файл с известным размером создаётся `MKfile` сразу нужной длины и пишется
  потоком `SAVE512` по 2 КиБ, без обновления каталога и FAT на каждом куске.
  Для записи с data descriptor файл находится `FENTRY` один раз, дальше данные
  дописываются `APPEND`. Прежняя версия звала `FENTRY` перед каждым куском, и
  ядро WC каждый раз проходило всю цепочку кластеров файла до конца.

Тактов процессора на байт распакованных данных (эмулятор Z80, без времени
носителя):

| Данные | Было (C) | Стало |
|---|---:|---:|
| текст, Deflate | 4 076 | 488 |
| код Z80 с повторами | 2 673 | 207 |
| Stored | 3 079 | 164 |
| шумные данные (много кодов длиннее 8 бит) | 11 385 | 1 100 |

В настоящем Wild Commander под патченным Unreal (14 МГц, FAT32 с кластером
512 байт, сентябрь 2026):

| Архив | Прежняя версия (C) | Новая версия |
|---|---|---:|
| образ TRD 640 КиБ (ZIP 169 КиБ) | за 10 мин 18 с записано 262 КиБ (40 %) | 51 с |
| 7 файлов, 944 КиБ (ZIP 330 КиБ) | — | 84 с |

После распаковки копии FAT совпадают, потерянных кластеров и временных файлов
нет. Мелкие кластеры (512 байт) — худший случай для прежней версии: чем
длиннее цепочка, тем дольше каждый её обход; на картах с крупными кластерами
разница меньше, но выигрыш процессорной части остаётся в 8–15 раз.

## Раскладка памяти

- `#8000..#BFFF` — страница 0 плагина: код, переменные, таблицы ядра и CRC32,
  окно чтения архива (1 КиБ) и буфер записи (2 КиБ). Файловые функции WC
  принимают буферы только из `#4000..#BFFF`.
- `#0000..#3FFF` и `#C000..#FFFF` — страницы 1 и 2 плагина: история Deflate
  32 КиБ. Логические байты `#4000..#7FFF` лежат по адресам `#C000..#FFFF`.

## Сборка

```powershell
cd 'C:\Users\Администратор\Desktop\WC\WildCommander Improved\source\plugins\unzip.wmf'
.\build.ps1
```

Нужен только `sjasmplus` (по умолчанию
`U:\Desktop\sjasmplus\sjasmplus-1.21.0.win\sjasmplus.exe`; `U:` — `subst` на
профиль пользователя, потому что sjasmplus не принимает путь с кириллицей).
Результат локальной сборки: `build\UNZIP.WMF`; образ страницы — `build\code.bin`,
символы — `build\code.sym`. Основная сборка Wild Commander устанавливает тот же
бинарник в `exe\WC\UNZIP.WMF`.

## Проверка

```powershell
.\test.ps1
```

- `tests/test_inflate_z80.py` — ядро Deflate исполняется в эмуляторе Z80
  (`tests/inflate_harness.asm`) на потоках zlib: блоки всех типов, окно
  32 КиБ, выход больше 64 КиБ, 48 случайных потоков всеми стратегиями zlib,
  испорченные потоки.
- `tests/test_plugin_z80.py` — весь плагин в эмуляторе Z80 с виртуальным API
  Wild Commander (`LOAD512`, `SAVE512`, `MKfile`, `APPEND`, `FENTRY`, FILEX,
  окна): извлечение, вопросы замены, пропуск, индикатор, число поисков
  временного файла.
- `tests/test_inflate_streaming.py` — заголовки несжатых блоков Deflate на
  границах входного окна 1 КиБ, с FILEX и без него, с data descriptor и
  известным размером, пустой и максимальный блок, неверный NLEN и обрыв
  заголовка. Исправлена потеря младшего байта NLEN при пополнении входа:
  она вызывала ложную ошибку `invalid Deflate stream` в `is-dos.zip`.
- `tests/test_wmf_contract.py` — заголовок WMF и карта памяти.
- `tools/run_unzip_unreal.ps1` — прогон в настоящем Wild Commander под
  патченным Unreal (клавиши через `vkey.req`): готовит образ из `wc.img`,
  распаковывает архив и проверяет образ (`tools/unreal_zip_check.py`: файлы,
  временные файлы, совпадение копий FAT). Параметр `-Plugin` подставляет
  другой `UNZIP.WMF` для сравнения.

Для запуска скопируйте `UNZIP.WMF` в каталог `WC` загрузочного устройства и
добавьте активную строку `UNZIP.WMF` в секцию `[PLUGINS]` файла `WC\wc.ini`.
Провайдер `FILEX.WMF` должен быть зарегистрирован перед `UNZIP.WMF`; без него
распаковка остаётся рабочей, но последний отклонённый файл читается fallback-ом.
Расширение `ZIP` уже записано в заголовок плагина; отдельный пункт F10 не нужен.

Построение и чтение канонических кодов Хаффмана выполнено по алгоритму
`puff.c` Марка Адлера (`zlib/contrib/puff`, лицензия zlib).
