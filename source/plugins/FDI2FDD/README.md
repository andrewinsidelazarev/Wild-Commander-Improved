# FDI2FDD.WMF

Файловый плагин Wild Commander Improved для записи UKV FDI (сигнатура
`FDI`) на **настоящую DD-дискету** через ВГ93/FD1793 ZX Evolution,
TS-Conf. Заголовок type=`#00`, расширение `FDI`, запуск по Enter.
В меню F10 не появляется, резидентного кода не устанавливает.

## Как пользоваться

1. Enter на FDI открывает горизонтальное меню **A, B, C, D** в окне `REAL DRIVE`.
   Начальный выбор — A. Left/Right меняют привод; Left на A и Right на D
   ничего не меняют, перехода по кругу нет. Enter подтверждает выбор,
   Esc возвращает в WC без обращений к контроллеру. Up/Down игнорируются.
2. Сразу после выбора появляется `Checking drive...` на строке 2.
   ProbeDisk проверяет FDC, привод, дискету и защиту записи, затем закрывает
   контроллер и возвращает частоту/кэш WC и маску `#29AF`. FDI ещё не читается.
   `Drive not found`, `No disk in drive` и `Disk is write protected` выводятся
   до вопроса; строка 4 — `Press any key to select drive`. Любая клавиша снова
   открывает меню с прежней буквой выделенной. Esc в этом меню возвращает в WC.
   При `Floppy disk controller not found` строка 4 — `Press any key to exit`,
   любая клавиша возвращает в WC. Esc во время ProbeDisk выходит без сообщения.
3. При успешной проверке появляются строки `All data on disk A will be destroyed!`
   (буква выбранного привода) и `Continue? (Y/N)`.
   Только клавиша Y продолжает; любая другая сразу возвращает в WC.
   Исходный Enter выбора привода подтверждением не считается.
   Предупреждение находится на строке 2, белым по красному (`#2F`),
   вопрос — на строке 4 в цвете окна (`#5F`); строки 1, 3 и 5 пустые.
   После Y строка 2 очищается и возвращается к `#5F`, затем очищается
   строка 4. Любой другой ответ закрывает окно без дополнительной перекраски.
4. После Y плагин проверяет таблицу образа и допустимость всех дорожек.
   Warning и Validate выполняются на частоте WC, при закрытом FDC.
   RunDisk открывает контроллер повторно и снова проверяет дискету:
   если её вынули после ProbeDisk, `No disk in drive` и `Press any key to exit`
   возвращают в WC. После принятия образа выполняются запись и
   **обязательная проверка** каждой дорожки.
   Переключателя Verify нет.
5. После автоматических повторов ошибка сектора показывает
   `Retry / Ignore / Abort` внутри того же окна.
   R или Enter повторяет операцию над этим сектором; I пропускает сектор
   и учитывает его как незаписанный/непроверенный; A или Esc прекращает
   работу и сразу возвращает в WC. При ошибке проверки Retry снова запускает
   проверку и до трёх циклов записи сектора с последующей проверкой.
   Сектор с намеренно плохим CRC только перечитывается, без WRITE SECTOR. Ошибки отсутствия привода/дискеты, защиты от записи,
   непригодного образа и неудавшегося форматирования показываются сообщением;
   любая клавиша закрывает окно.
6. После обработки всего образа появляется `Done`, а при пропусках —
   `Done; Ignored 0001`. Если у CRC-error секторов пришлось менять байты,
   строка 3 имеет вид `CRC changed: 0001 / 000007 bytes`.
   Первая величина — число таких секторов, вторая — число изменённых байтов.
   Итог больше не содержит счётчика и полосы прогресса. При успехе и ошибке
   строка 4 содержит `Press any key to exit`; любая клавиша возвращает в WC.
   Возврат к выбору предусмотрен только для ERR_DRIVE/ERR_DISK/ERR_WP из ProbeDisk.

Esc во время работы ничего дополнительно не спрашивает. Контроллер
останавливается, восстанавливаются его физический track register,
маска виртуальных приводов и настройки CPU WC. Уже записанные дорожки
остаются на дискете; отмена не восстанавливает её прежнее содержимое.

## Окно и запись

Окно выбора привода: тип `#84`, размер **42×7**, цвет `#5F`, заголовок
`REAL DRIVE`, без списочного курсора и API 6/7. На строке 3 центрирована
строка `A      B      C      D`: буквы в клетках 10, 17, 24, 31,
поля слева и справа по 9 клеток из 40. При перерисовке API 3 печатает всю
строку, API 4 красит её в `#5F`, снимая прежнее выделение. Затем API 3
печатает три клетки ` X ` вокруг выбранной буквы (X=9+7×Drive), API 4
красит их в `#F0`. Выделен ровно один привод, `Drive` хранит 0..3.

Рабочее окно повторяет окно копирования/удаления WC: **42×7**, цвет `#5F`,
заголовок `FDI2FDD`, пустая строка, центрированное имя файла/сообщение,
центрированный счётчик `<0000 of 0160>`, пустая строка и одна полоса
**40 клеток**: `█` (`#DB`) и `▒` (`#B1`).
Счётчик учитывает дорожки всего образа, включая обе стороны.
К концу обработки счётчик достигает M of M, полоса — 40 заполненных клеток.
Затем Summary заменяет строки в том же открытом окне:

| Строка | Итоговый экран |
|---|---|
| 2 | `Done`, `Done; Ignored NNNN` или сообщение об ошибке |
| 3 | `CRC changed: NNNN / NNNNNN bytes` только при успехе с заменами bad-CRC данных; иначе пусто |
| 4 | `Press any key to select drive` для ERR_DRIVE/ERR_DISK/ERR_WP из ProbeDisk; иначе `Press any key to exit` |
| 5 | Пусто; полоса удалена |

Каждая строка печатается целиком на 40 клеток; прежние счётчик и полоса
полностью стираются. Строка 1 остаётся пустой, цвет всех строк — `#5F`.
Все строки центрируются как CP_CENTER; окно центрируется в 80×25,
80×30 и 90×36 через API WC. Плагин не вызывает внутренний код WCINI.

Обычные сектора предварительно проверяются по таблице и размеру файла,
без отдельного чтения их данных. Файл читается потоком LOAD512 `#30`;
LOADNONE `#3D` пропускает только полные ещё не прочитанные блоки.
READ_AT используется для предварительного осмотра CRC-error секторов
и для обратных смещений в необычном образе. Данные каждой дорожки
полностью загружаются до её форматирования.

Сохраняются порядок ID, C/H/R/N, длины, данные обычных секторов и deleted DAM.
Чужие C/H в ID не нормализуются. Пустая дорожка стирается без секторных ID.
Плохой CRC **сохраняется всегда**: сектор помещается в форматный поток
с намеренно неправильным CRC и не переписывается WRITE SECTOR.
Только F5/F6/F7 в данных такого сектора заменяются на E5/E6/E7, поскольку
первые три байта являются командами WRITE TRACK. Проверка требует CRC error
и точного совпадения с изменёнными данными. Для `voron1.fdi` это
**1 сектор, 7 байтов**. Запуск защищённой игры на реальном приводе не проверен.

Сначала применяется обычный формат с пределом 5900 физических байтов.
Если он не помещается, применяется плотный формат с пределом 6160:
без IAM, начальный gap 32, синхронизация ID 8 нулей, DAM 12 нулей,
три A1, GAP2=22, GAP3=24. Дорожки 5×1024+1×512 у `IS-HUM1.FDI`
занимают 6156 байтов и принимаются. Подробное обоснование допуска,
числа чтений и оценки времени — в [REPORT.md](REPORT.md).

После форматирования все обычные сектора записываются за один проход
в порядке ID. Затем проверяются весь порядок ID и все данные в двух
чередующихся проходах. Нефатальный отказ VerifyIDs или VerifyFast сначала
вызывает полное форматирование, запись и проверку дорожки ещё до двух раз
без диалога. После третьего неудачного прохода выполняются VerifyIDsWithChoice
и VerifySlow. Для обычного сектора VerifyWithChoice сначала проверяет данные,
затем до трёх раз записывает сектор заново и проверяет его. Диалог появляется
после четвёртой неудачной проверки; Retry повторяет этот цикл. Разовую ошибку
даже третьей записи дорожки секторное восстановление может исправить без
диалога. Bad-CRC сектор только перечитывается. Число изменённых CRC-байтов
и секторов учитывается один раз на завершённую дорожку.

## Проверка контроллера и сообщения

OpenFDC сохраняет маску виртуальных приводов из NVRAM B0, открывает порты
через `#29AF=#80`, выбирает сторону и ждёт около 1 мс (256 DJNZ).
После FORCE INTERRUPT `D0` с паузой 16 DJNZ выполняется до восьми попыток:
запись `#55` в sector register (`#5F`), пауза 16 DJNZ (около 60 мкс), чтение;
при совпадении — та же проба с `#AA`. Между неудачными попытками около 1 мс.
Контроллер принимается после первой полностью успешной пары, включая попытку 8.
Только отказ всех восьми возвращает `ERR_NOFDC=11` и сообщение
`Floppy disk controller not found` до RESTORE.
До выхода из этой ветви командный порт получает только `D0`, без RESTORE,
SEEK и WRITE. CloseFDC восстанавливает сохранённый `#29AF` до ожидания клавиши.
При наличии FDC проверка не меняет запись и Verify: перед каждой READ/WRITE
SECTOR регистр `#5F` снова загружается номером нужного сектора.

Сообщения итогового экрана об ошибках:

| Код | Текст |
|---|---|
| 1, ERR_IMAGE | `Invalid or unsupported FDI` |
| 2, ERR_FILE | `File read failed` |
| 3, ERR_DRIVE | `Drive not found` |
| 4, ERR_DISK | `No disk in drive` |
| 5, ERR_WP | `Disk is write protected` |
| 6, ERR_SEEK | `Seek failed` |
| 7, ERR_WRITE | `Write failed` |
| 8, ERR_VERIFY | `Verification failed` |
| 10, ERR_TIMEOUT | `Controller timeout` |
| 11, ERR_NOFDC | `Floppy disk controller not found` |

Для ERR_IMAGE уточнение причины может заменить общий текст на
`FDI offset beyond EOF`, `Track exceeds safe DD capacity` или
`Unsupported sector size`. Все эти экраны имеют пустые строки 3/5
и `Press any key to exit` на строке 4. Код 9 (ERR_BREAK) означает
отмену с немедленным возвратом в WC без итогового сообщения.

## Ограничения и проверки

Образ: до 1 МиБ, 1..86 цилиндров, 1..2 стороны, до 32 секторов на дорожке,
N=0..3 (128/256/512/1024 байта), область до начала данных до 16128 байтов.
Требуются три свободные страницы пула WC. FILEX READ_AT требуется только
для плохого CRC или обратных смещений; обычный FDI читается без API 77.
Дубли C/R на одной физической дорожке и F5/F6/F7 в полях ID отвергаются.
FDI не хранит исходные gaps, углы и flux; точная магнитная копия не заявляется.

StartFDC вызывается из ProbeDisk и повторно из RunDisk. Он очищает `#6004`
и вызывает WC API 14 (TURBOPL) с **B=0, C=0** до первого FDC I/O:
CPU работает при **3,5 МГц**, кэш выключен. На физической ZX Evolution владелец
обнаружил слишком короткие стробы ВГ93 при 14 МГц. CloseFDC последним действием
вызывает API 14 с **B=#FF**; WC возвращает прежние частоту и настройку кэша.
Это проверено для успеха, ошибок открытия/записи/проверки, Esc и Abort.
Esc в первом меню не меняет частоту. При хорошем диске последовательность
API 14: **B=0, FF, 0, FF**; между открытиями FDC работает обычная частота WC.

| Путь DRQ | Между опросами, T | DRQ → OUTI, T | DRQ → INI в модели, T |
|---|---:|---:|---:|
| Пять опросов после байта | 25 | 60 | 67 |
| Пятый быстрый опрос → обычное ожидание | 35 | 70 | 77 |
| Ожидание, включая второй уровень счётчика | 39 | 74 | 81 |
| Третий уровень, раз в 65536 основных опросов | 47 | 82 | 89 |

Максимумы измерены фазовым перебором на готовом WMF, один T = 1/3,5 мкс.
У записи предел 23,5 мкс (82 T), у чтения 27 мкс (94 T).
Измеренный READ на 1 T больше табличного расчёта комментария (66/80/88 T);
для проверки использованы 67/81/89 T. Худшие задержки — 23,429/25,429 мкс.
Полное форматирование, запись и чтение N=0..3 проходят без Lost Data при
DRQ 32 мкс и в стресс-профиле 32/1,03 = 31,068 мкс (+3% скорости).
Дополнительный `JR Z` после каждого INI/OUTI учтён отдельным фазовым перебором:
от предыдущего доступа к данным до первого опроса — 29/21 T (WRITE/READ),
на границе блока — 56/48 T. Если искусственно потребовать следующий байт
сразу после предыдущего, диагностические максимумы на границе блока —
91/90 T; в таком переборе дедлайн выключен. Полные прогоны используют
штатные дедлайны и период DRQ 32 либо 31,068 мкс и проходят без Lost Data.
Этот профиль проверяет обслуживание DRQ; физический допуск ёмкости плотной
дорожки при +3% вращения из него не следует.

Watchdog прерывает передачу без DRQ/INTRQ примерно через 2,93 с;
проверена также остановка после одного успешно переданного байта:
4×65536 основных опросов плюс отдельные опросы уровней счётчика.
WaitCommand ограничен 4×65536 итерациями, WaitIndex — 3×65536 на ребро;
пустой привод определяется примерно за пять секунд.
**F7-1 исправлен, подтверждено 2026-10-01:** InitTransferCount задаёт B для
первого блока (0 означает 256) и C' для количества блоков с округлением вверх.
Постоянный DRQ без INTRQ заканчивается ошибкой после ровно TransferLimit
доступов к данным, без чтения/записи байта за буфером. После заполнения
TransferFull ждёт INTRQ без доступа к `#7F`; лишний DRQ — ошибка,
молчание — прежний timeout. Лимиты 6/128/256/512/1024/6656, недостача/перебор,
INTRQ на границах всех блоков и лишний OUTI при B=0 проверены.
TransferLeft при CF=0 по-прежнему равен пределу минус принятые байты;
при CF=1 прежнее значение не обновляется. EI и состояние WC восстанавливаются.

По сообщению второго разработчика в седьмом заходе, IS_BASE записан и сверился полностью
в настоящем WC (Unreal с реальными таймингами WD1793) за **223 с машинного
времени**, около 3 мин 43 с, при 3,5 МГц. Это внешнее измерение прежнего кандидата;
в этом заходе WC, эмулятор и физический привод не запускались.

Стартовая раскрутка ждёт пять полных интервалов INDEX..INDEX (около секунды
при 300 об/мин), после синхронизации с первым индексом. Перед SEEK и каждой
командой данных EnsureMotor проверяет два условия: флаг NeedSpin после
принятого Retry/Ignore и разность счётчика кадров WC `#6009` (50 Гц) и LastCmd
не меньше **75 кадров (1,5 с)**. Любое из них запускает SEEK к текущему
физическому цилиндру с загрузкой головки и ожидание пяти полных оборотов.
Прежний ID.C в track register затем восстанавливается: защита с C=55
не ломается. При паузе меньше 75 кадров без NeedSpin добавочной раскрутки нет.
Решение не зависит от HLD после D0. Stamp обновляет LastCmd в TransferDone,
TransferFail, после WaitCommand в SeekTrack, после успешной повторной раскрутки
и в конце OpenFDC. Под DI счётчик кадров стоит; это сокращает только учтённое
время занятых передач, а не файловых пауз и ожиданий пользователя с EI.

Ожидания контроллера ограничены. Клавиши меню и ReadKey опрашиваются
через EI/HALT раз в кадр; NUSP перед проверками не используется, ANYK
спрашивается последним. Перед возвратом в WC выполняется API 46 (USPO).
Защёлка Esc `#6004` очищается в StartFDC перед ProbeDisk/RunDisk и при Retry/Ignore.
В предварительной проверке boot-мусор в ней не читается. Во время записи
живой и уже отпущенный, но защёлкнутый Esc прерывают работу на границе
команд/в ожиданиях type I и INDEX. В цикле DRQ действует DI; Esc в байтовом
пути не проверяется, при тайм-ауте проверяется после выхода из него.

**Машина с активной ZXM-MoonSound несовместима с этим доступом к FDC.**
Вне TR-DOS порт `#7F` занят также картой ZXM-MoonSound (`#7E/#7F`,
`#C4..#C7`): байты попадают в звуковую карту, форматирование получает
Lost Data. Ограничение относится также к TRDUMP. Требуется отключить карту
или её декодирование этих портов; плагин не перенастраивает MoonSound.

**7168 байтов**, SHA-256 до/после
`25f20eb5dc9e343fa109d130a1fa6640d4ccdaf4c8c434b65a90ed525bb1e747`.
