# TXTVIEW.WMF — Text & HEX Viewer v0.26

`TXTVIEW.WMF` просматривает текст в CP866, CP1251 и UTF-8, а также исходные байты
в HEX. Файл читается по частям через буфер 4 КиБ. Размер и позиции —
32-битные, до `0xFFFFFFFF` байт (4 ГиБ минус один байт); файл целиком
в память не загружается. Расширения обрабатываются по F3; просмотрщик также
доступен через Shift+F3. F10 показывает подсказку о выборе файла.

## Кодировки и управление

При открытии проверяются первые 4096 байт. BOM определяет UTF-8; без BOM
проверяются правильность UTF-8 и наличие многобайтовых символов. CP866 и
CP1251 различаются по русским буквам и частым сочетаниям. Для чистого ASCII
и равных оценок выбирается CP866. Короткие, смешанные и нетипичные тексты
могут определяться ошибочно; ручной выбор доступен всегда.

| Клавиши | Действие |
|---|---|
| F8 | Авто → CP866 → CP1251 → UTF-8 → Авто |
| Tab | Переключить текст/HEX |
| Вверх / Вниз | Предыдущая / следующая экранная строка |
| PgUp / PgDn | Предыдущая / следующая страница |
| Home / End | Начало / конец файла |
| Ctrl+F / Ctrl+G | Найти текст / найти следующее совпадение |
| F1 | Помощь на английском языке |
| Esc / Пробел | Закрыть просмотрщик |
| Esc во время долгой команды | Отменить поиск или проход назад |

F8 и Tab открывают выбранный режим с начала файла. Внизу постоянно видны
режим автоматического/ручного выбора и действующая кодировка.
Нижний бар всегда подписан на английском: `Auto`, `Man.`, `F8:Enc`,
`Tab:Mode`, `F1:Help`, независимо от раскладки ENG/RUS. Страница помощи,
её заголовок и подсказка закрытия также всегда на английском. Смещение
первой строки и размер файла выводятся восемью шестнадцатеричными разрядами.
Кодировка влияет только на отображение и подготовку поискового запроса;
просмотрщик ничего не записывает в исходный файл.

Длинные строки переносятся по ширине окна. Поддерживаются CR, LF, CRLF и
табуляция с шагом восемь колонок экрана. На правом краю оставшаяся часть
табуляции ограничивается текущей строкой. NUL и управляющие байты отображаются
точкой. UTF-8 BOM скрывается только в текстовом режиме UTF-8. Используется
штатный шрифт CP866: русские буквы, Ё/ё и доступная псевдографика отображаются
полностью, отсутствующий в шрифте Unicode-символ заменяется одним `?`.
Повреждённые UTF-8-последовательности не поглощают следующий ASCII/CR/LF.

Поиск учитывает регистр, поддерживает 40 вводимых символов и совпадения через
границы буфера. Строка ввода WC находится в CP866; перед поиском она переводится
в текущую кодировку файла. HEX показывает исходные байты независимо от F8.

## Исправления прежнего просмотрщика

- Убран предел загрузки в 64 видеостраницы, который молча обрезал файлы после
  1 МиБ при значительно большем максимальном размере в заголовке плагина.
- Текст ограничен логическим размером файла, а не первым нулём либо случайным
  содержимым памяти после последнего прочитанного сектора.
- HEX отдельно проверяет каждый байт последней строки и не показывает
  секторный хвост. Вверх/вниз и End ограничены действительным размером.
- Длинные строки больше не обрезаются буфером/шириной с последующим пропуском
  невидимой части при прокрутке.
- Исправлены переходы между буферами, включая CRLF и многобайтовые символы.
- Меню выбора просмотрщика больше не вызывает повторную загрузку текста
  из уже продвинутого потока. При F10 не используются неопределённые файловые
  параметры и не открывается сырой каталог вместо выбранного файла.
- Проверяются результат FENTRY, ошибки чтения, ранний EOC и короткие передачи.
- Поиск доступен в обоих режимах, корректно проверяет перекрывающиеся
  совпадения и заканчивается на EOF; строка поиска преобразуется в выбранную
  кодировку.
- Исправлено расширение `NF0` на `NFO`. `TXTVIEW.WMF` собирается из исходника
  штатной `build.ps1`, вместо копирования старого бинарника из эталона.

## Реализация и сборка

| Файл | Назначение |
|---|---|
| `TXTVIEW.ASM` | WMF-заголовок, запуск, основной цикл и состояние |
| `STREAM.INC` | Буфер файла, последовательное/позиционное чтение, LE32 |
| `ENCODING.INC` | Автодетект и декодирование в экранный CP866 |
| `VIEW.INC` | Переносы, HEX, навигация и история строк |
| `UI.INC` | Строка состояния, помощь и поиск |
| `TABLES.INC` | Сгенерированные таблицы и строки интерфейса |

Подробные комментарии ASM на русском описывают входы, выходы, сохранение
регистров и причины проверок. Код/строки ограничены адресом `#A800` через
ASSERT, кольцо 256 переходов занимает `#A800..#AFFF`, кэш — `#B000..#BFFF`.
Это одна страница плагина; обмен данными не зависит от отображения `#C000`.

Обычная прокрутка вперёд использует `LOAD512`, сохраняя последовательный
поток. Для произвольного перехода используется `FILEX.READ_AT`, если загружен
штатный `FILEX.WMF`. Без него файл перечитывается от начала до нужного окна:
совместимость сохраняется, но обратные переходы медленнее. История ускоряет
Up/PgUp; при её промахе границы переносов восстанавливаются от начала
физической строки. Очень длинная строка при End/проходе назад требует линейного
сканирования; его можно отменить Esc. Задержка отдельного чтения зависит от
носителя и FAT-цепочки. На время долгой операции внизу показано `READING..`.
Короткое нажатие Esc сохраняется защёлкой прерывания WC; отмена выполняется
после завершения текущего вызова файлового API, а не внутри обращения к диску.

Из корня проекта:

```powershell
python tools\make_txthex_tables.py --check
.\build.ps1
python tests\core32_unreal\test_txthex_viewer.py
```

Генератор без `--check` обновляет таблицы. Готовый файл:
[`exe/WC/TXTVIEW.WMF`](../../../exe/WC/TXTVIEW.WMF).

Прежнее имя этого плагина — `RE.WMF`. Для обновления существующего Improved:

1. Скопируйте `TXTVIEW.WMF` в каталог `WC`.
2. В секции `[PLUGINS]` своего `wc.ini` замените `RE.WMF` на `TXTVIEW.WMF`.
3. Удалите старый `WC/RE.WMF`; оставьте остальные настройки без изменений.

В поставляемом `exe/WC/wc.ini` имя уже исправлено. Штатная сборка исключает
старый бинарник из эталона и повторяет замену имени после обновления конфигурации.
Версия повышена с 0.25 до 0.26. Переименование и номер в заголовке не меняют
исполняемый код или формат просматриваемых файлов.

Машинные тесты выполняют собранные инструкции Z80, подменяя только публичный
API WC. Проверки диапазона почти 4 ГиБ используют виртуальный файл, а не
физический носитель такого размера. Материалы отдельной проверки настоящего
WC в Unreal находятся в `Build/txthex-audit-20260914/`. Эти проверки не являются
подтверждением работы на физическом ZX Evolution.
