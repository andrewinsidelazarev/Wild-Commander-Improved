# Панельный менеджер: устройство и программное использование

Панельный менеджер связывает интерфейс, текущий каталог, драйвер и состояние
CORE32. Для плагина панель представлена указателем `IX`; для кода самого WC —
это две 36-байтовые структуры и два независимых файловых контекста.

## 1. Карта подсистемы

```text
                         WC_ENTRY #6011
                               │
             ┌─────────────────┼──────────────────┐
             │                 │                  │
       WildDOS #4000      интерфейс/INI      плагины из INI
             │                 │                  │
             └─────────────────┴──────────────────┘
                               │
                         PATH: обе панели
                               │
                        MAIN LOOP #6049
                               │
      ┌─────────────── клавиша / команда ────────────────┐
      │                                                   │
   GETEN                                              FOLDER
выбранная запись                                 перечитать каталог
      │                                                   │
      ├─ viewer/plugin                                   NEWDIR
      ├─ copy/move/delete                                  │
      └─ enter directory                         NXTETY → индекс → SORT
```

Основные точки текущего образа:

| Адрес | Имя | Назначение |
|---:|---|---|
| `#6011` | `WC_ENTRY` | Одноразовый старт, установка CORE32, INI и панелей |
| `#6049` | `WC_MAIN_LOOP` | Кадровый цикл и диспетчер клавиш |
| `#6149` | `Xpan` | Служебно заменить `IX` на другую панель |
| `#6160` | `XPAN` | Полное пользовательское переключение по Tab |
| `#62EB` | `PANELI` | Сброс вычисляемого состояния панели |
| `#62FE` | `GETEN` | Получить объект под курсором |
| `#63FE` | `FOLDER` | Перестроить активную панель |
| `#6407` | `NEWDIR` | Перечислить каталог и построить индекс |
| `#65BB` | `WLIT` | Нарисовать видимую часть списка |
| `#6715` | `I_N_T` | IM2: таймер, экран, клавиатура, часы |
| `#6868` | `DRACT` | Подключить файловый контекст и драйвер панели |

Эти адреса — внутренняя раскладка текущего `boot.$C`, не публичные входы для
`.WMF`. Плагин пользуется `#6006` и входным `IX`.

## 2. Две панели — два файловых контекста

```text
                 активная панель определяется IX

        LEFT                                      RIGHT
  WINDOW = #7EA0                            WINDO2 = #7EC4
        │                                          │
        ├─ устройство 0..6                         ├─ устройство 0..6
        ├─ DOS/driver page #F0                     ├─ DOS/driver page #F1
        ├─ catalog pages #0B..#13                  ├─ catalog pages #14..#1C
        ├─ screen page #1E                         ├─ screen page #1F
        └─ path at #F7:#1000                       └─ path at #F7:#2000
```

Страница `#F0` или `#F1` отображается в логическое окно `#0000..#3FFF`. В ней
находятся:

- буферы перечисления `#0000..#1FFF`;
- FAT-буфер `#3000` и секторные буферы `#3200/#3400`;
- текущий распакованный драйвер по `#3800`;
- поток, BPB, FAT32 ENTRY и текущий каталог.

Поэтому панели могут показывать разные устройства и каталоги: переключение
меняет не только `IX`, но и рабочую физическую страницу DOS. Глобальный код
CORE32 остаётся по `#4000`, а его данные меняются вместе с панельной страницей.

## 3. Структура панели, 36 байт

Структуры `WINDOW` и `WINDO2` имеют одинаковый формат. Offset дан одновременно
в hex и decimal.

| Offset | Размер | Поле | Назначение |
|---:|---:|---|---|
| `#00 / 0` | 1 | `style` | Тип окна и флаги рамки |
| `#01 / 1` | 1 | `cursor_mask` | Маска цвета курсора |
| `#02 / 2` | 1 | `x` | X панели: 0 слева, 40 справа |
| `#03 / 3` | 1 | `y` | Y панели |
| `#04 / 4` | 1 | `width` | Ширина |
| `#05 / 5` | 1 | `height` | Высота, меняется по текстовому режиму |
| `#06 / 6` | 1 | `color` | Цвет paper+ink |
| `#07 / 7` | 1 | reserved | Ноль |
| `#08 / 8` | 2 | `restore_buffer` | Для панелей `#FFFF`: фон отдельно не сохраняется |
| `#0A / 10` | 1 | `separator_1` | Первая горизонтальная линия |
| `#0B / 11` | 1 | `separator_2` | Вторая линия |
| `#0C / 12` | 1 | `cursor` | Видимая позиция курсора, от 1 |
| `#0D / 13` | 1 | `cursor_limit` | Нижняя граница/число доступных видимых строк |
| `#0E / 14` | 1 | `cursor_color` | Цвет активной строки |
| `#0F / 15` | 1 | `under_cursor` | Исходный цвет под курсором |
| `#10 / 16` | 2 | `list_top` | Номер первой видимой записи, от 0 |
| `#12 / 18` | 2 | `entry_count` | Общее число записей каталога |
| `#14 / 20` | 1 | `at_end` | Внутренний признак конца списка |
| `#15 / 21` | 1 | `at_start` | Внутренний признак начала списка |
| `#16 / 22` | 1 | `screen_page` | `#1E` слева, `#1F` справа |
| `#17 / 23` | 2 | `saved_offset` | Сохранённое экранное/страничное смещение |
| `#19 / 25` | 1 | `catalog_base` | 0 слева, 9 справа |
| `#1A / 26` | 1 | `catalog_page` | Текущая страница записей `0..8` |
| `#1B / 27` | 1 | `dos_page` | 0 слева, 1 справа; физически `#F0+value` |
| `#1C / 28` | 1 | `activated` | Файловый контекст/драйвер уже активирован |
| `#1D / 29` | 1 | `device` | Номер устройства `0..6` |
| `#1E / 30` | 2 | `path_begin` | Начало строки пути на странице `#F7` |
| `#20 / 32` | 2 | `path_cursor` | Место добавления следующего компонента пути |
| `#22 / 34` | 1 | `restoring` | Защита во время восстановления пути |
| `#23 / 35` | 1 | `sort_mode` | 0 off, 1 name, 2 extension, 3 size |

Первые 16 байт совместимы с общей структурой окна SOW. Поля после `#10` —
расширение именно панели. Они являются внутренним ABI: обычный плагин может
читать их для диагностики, но должен менять панель только через публичные
операции и код возврата.

### 3.1 Вычисление выбранного объекта

```text
absolute_index = panel.list_top + panel.cursor - 1
               = word(IX+#10) + byte(IX+#0C) - 1
```

`GETEN` находит четырёхбайтовый элемент индекса, подключает страницу исходной
записи и заполняет два резидентных кэша:

| Адрес | Размер | Содержимое |
|---:|---:|---|
| `#7F28` | 4 | Первый кластер объекта (`BRRR`) |
| `#7F2C` | 4 | Размер файла (`ARRR`) |
| `#7F6B` | 32 | Текущая FAT32 ENTRY/нормализованная запись |

После `GETEN` файловый просмотрщик получает размер из `ARRR`, имя из записи и
сохранённый кластер для API 50. Эти области глобальны: любой следующий выбор
или файловый вызов может их заменить.

## 4. Каталожные страницы и индекс

Один каталог хранится не как массив одинаковых 32-байтовых FAT ENTRY. CORE32
выдаёт нормализованные записи переменной длины; панель отдельно строит компактный
индекс.

```text
Левая панель                              Правая панель

#0B  index window                        #14  index window
#0C  entry data page 1                   #15  entry data page 1
 ...                                      ...
#13  entry data page 8                   #1C  entry data page 8

при чтении index отображается в #8000
при чтении записи data page отображается в #C000
```

Четырёхбайтовый элемент индекса:

```text
+0  относительная data page
+1  адрес записи, low
+2  адрес записи, high
+3  длина/служебное значение записи для внутренних проходов
```

`NEWDIR` выполняет следующий конвейер:

```text
PPATH
  │  сообщает CORE32 текущий кластер каталога
  ▼
GLSTCAT #401E
  │
  ▼
NXTETY #4057 ──► запись в #C000 ──► 4-byte index в #8000
  ▲                                      │
  └──────────── до конца каталога ───────┘
                                         │
                                  SORT → WLIT
```

На панель выделено девять физических страниц. При исчерпании буфера построение
останавливается; публичный API отмеченных объектов документирует номера
`1..2047`, и код плагина не должен предполагать больший доступный индекс.

Нельзя сохранять адрес записи из `#C000` и использовать его после следующего
`GETEN`, сортировки или файлового вызова: это адрес в переключаемой странице.
Копируйте требуемые поля в память плагина.

## 5. Путь и устройство панели

Строки путей хранятся на физической странице `#F7`:

```text
#1000  путь левой панели
#2000  путь правой панели

формат: "1:\DIR\SUBDIR\", #FF
```

Ключевые операции:

| Процедура | Действие |
|---|---|
| `RPATH` | Создать корень `<device>:\`, сбросить файловое состояние |
| `MPATH` | Добавить каталог или обработать `..` |
| `PPATH` | Вывести/передать текущий путь и подключить DOS-контекст |
| `PATH/SIMUL` | Восстановить сохранённые пути обеих панелей из `wc.ini` |

Номера устройств:

| `device` | Драйвер |
|---:|---|
| `0` | IDE Nemo master |
| `1` | SD Z-Controller, первый интерфейс |
| `2` | SD через NGS |
| `3` | IDE SMUC master |
| `4` | IDE SMUC slave |
| `5` | IDE Nemo slave |
| `6` | SD Z-Controller, второй интерфейс |

`DRACT` сначала подключает `#F0 + dos_page` в окно `#0000`. Если панель ещё не
активирована, она получает корневой путь и вызывает внутренний `DOS_SWP` с
номером устройства. Инициализация накопителя и поиск FAT32 выполняются до
первого построения каталога.

## 6. Переключение панелей

Есть две похожие, но разные процедуры:

```text
Xpan                         XPAN
─────                        ────
только меняет IX             гасит старый курсор
ставит status dirty          сохраняет состояние UI
для внутренней операции      меняет активную отметку/страницу
не рисует интерфейс          рисует новую активную панель
```

Используйте `Xpan`, когда команда должна ненадолго обратиться к противоположной
панели, например получить каталог назначения. Обязательно вызовите его второй
раз перед возвратом либо сохраните/восстановите исходный `IX`.

В плагине не вызывайте ни одну из них по внутреннему адресу. Входной `IX`
уже указывает на активную панель, а переключение пользователя должно остаться
за менеджером.

## 7. Навигация и главный цикл

Главный цикл синхронизирован с кадром через `EI/HALT`. Порядок обработки важен:

```text
cursor
  → Alt/Ctrl
  → arrows, PgUp/PgDn, Home/End
  → Delete/Insert/Space, Backspace
  → status, Shift
  → F1, F3, F10, Tab
  → F2, F4, F5, F6, F7, F8, F9
  → Enter
  → печатный символ / '*'
```

Состояние прокрутки образуют три значения:

```text
word (IX+#10)   первая видимая запись
byte (IX+#0C)   строка курсора от 1
word (IX+#12)   всего записей
```

Home/End и PgUp/PgDn меняют их, затем `WLIT` перерисовывает видимую область.
Флаги `+20/+21` не являются заменой этой арифметике; это кэш внутреннего
отрисовщика.

## 8. Как плагину работать с панелью

### 8.1 Получить файл, на котором запущен плагин

При вызове по расширению WC уже:

1. заполнил текущую ENTRY;
2. передал размер в `DE:HL` и имя по `BC`;
3. спозиционировал файловый поток на начало.

Можно сразу вызывать API 48 `LOAD512`. Если перед чтением выполнялся другой
файловый вызов, восстановите позицию API 50 `GIPAGPL`.

### 8.2 Найти объект по имени в активном каталоге

```asm
        LD      HL,Name
        LD      A,59                  ; FENTRY
        CALL    #6006
        JR      Z,.not_found
        ; DE:HL = размер. Для чтения затем API 62 GFILE.

Name:   DB      #00,"FILE.BIN",0
```

### 8.3 Обработать отмеченные файлы

API 54 не требует разбирать внутренний каталог панели:

```text
HL=0       → NZ, BC=число отмеченных; Z, если отмеченных нет
HL=1..2047 → DE получает name,0; Z = имя получено
```

На каждом успешном объекте API также позиционирует поток в начало файла, если
bit 7 регистра H не был установлен. `IX` должен оставаться адресом панели,
полученным при входе.

### 8.4 Изменить каталог и обновить экран

После MKFILE, MKDIR, DELFL, RENAME, APPEND или FILEX завершите плагин с `A=3`:

```asm
        LD      A,3                   ; WC сам выполнит FOLDER/NEWDIR/SORT
        RET
```

Это единственный безопасный публичный способ согласовать число записей,
индекс, сортировку, курсор и строку статуса. Прямое увеличение `(IX+#12)` не
создаёт запись и повреждает представление панели.

### 8.5 Перебирать каталог отдельно от панели

Клонируйте поток API 57, `D=#FE`, затем сбросьте перечислитель API 56,
`A'=1`, и вызывайте API 58. Так переход в подкаталог или FENTRY не меняет
живой поток, которым менеджер продолжит пользоваться после возврата.

## 9. Как добавить команду в сам менеджер

Для изменения `MD20/WCFX/WCVW` используйте такой порядок:

```text
клавиша в MAIN
   │
   ├─► GETEN, если нужен выбранный объект
   │
   ├─► DRACT/файловая операция в контексте активной панели
   │
   ├─► Xpan дважды, если нужен контекст второй панели
   │
   ├─► FOLDER для каждой изменённой панели
   │
   └─► пометить STUS и вернуться в кадровый цикл
```

Правила внутренней команды:

- сохраняйте `IX`, если временно меняете панель;
- не держите указатели в `#8000/#C000` через вызов, который меняет страницу;
- считайте `#7F28/#7F2C/#7F6B` одноэлементным глобальным кэшем;
- перед прямым `#40xx` подключайте правильную страницу `#F0/#F1` и на каждом
  выходе восстанавливайте прежнее отображение;
- после изменения каталога перестраивайте индекс, а не редактируйте его
  частично;
- учитывайте, что F5/F6 используют обе панели и два разных DOS-контекста.
- при F5 храните оставшееся логическое число байт из `FENTRY` и передавайте
  последнему `LOAD512/SAVE512` только `ceil(bytes_left/512)` секторов; FAT EOC
  ограничивает выделенную цепочку, но не обозначает логический конец файла.

## 10. Типичные ошибки

| Ошибка | Почему проявляется | Правильное действие |
|---|---|---|
| Сохранён указатель на запись в `#C000` | Следующий GETEN подключил другую страницу | Скопировать имя/метаданные в страницу плагина |
| Плагин изменил `(IX+#12)` | Изменилось число, но не индекс и каталог | Выполнить файловую API и вернуть `A=3` |
| После FENTRY сразу вызван LOAD512 | FENTRY только нашёл запись | Вызвать API 62 `GFILE` |
| F5 ждёт EOC для маленького файла | Выделенный кластер длиннее логического файла | Ограничить последний обмен размером из FENTRY |
| GDIR выполнен в исходном потоке панели | Активный каталог панели заменён изнутри плагина | Сначала клонировать STREAM `D=#FE` |
| Служебный Xpan вызван один раз | `IX` остался на другой панели | Вызвать второй раз или восстановить IX |
| Один файловый адрес используется в обеих панелях | `#0000` отображает разные физические страницы | Копировать данные через постоянное окно/явный буфер |
