# Панельный менеджер: устройство и программное использование

Панельный менеджер связывает интерфейс, текущий каталог, драйвер и состояние
CORE32. Для плагина панель представлена указателем `IX`; для кода самого WC —
это две 36-байтовые структуры и два независимых файловых контекста.

## 1. Карта подсистемы

```text
                         WC_ENTRY #6011
                               │
             ┌─────────────────┼──────────────────┐
             │                 │                  │
       WildDOS #4000      интерфейс/INI      плагины из INI
             │                 │                  │
             └─────────────────┴──────────────────┘
                               │
                         PATH: обе панели
                               │
                        MAIN LOOP #6049
                               │
      ┌─────────────── клавиша / команда ────────────────┐
      │                                                   │
   GETEN                                              FOLDER
выбранная запись                                 перечитать каталог
      │                                                   │
      ├─ viewer/plugin                                   NEWDIR
      ├─ copy/move/delete                                  │
      └─ enter directory                         NXTETY → индекс → SORT
```

Основные точки текущего образа:

| Адрес | Имя | Назначение |
|---:|---|---|
| `#6011` | `WC_ENTRY` | Одноразовый старт, установка CORE32, INI и панелей |
| `#6049` | `WC_MAIN_LOOP` | Кадровый цикл и диспетчер клавиш |
| `#6149` | `Xpan` | Служебно заменить `IX` на другую панель |
| `#6160` | `XPAN` | Полное пользовательское переключение по Tab |
| `#62EB` | `PANELI` | Сброс вычисляемого состояния панели |
| `#62FE` | `GETEN` | Получить объект под курсором |
| `#63FE` | `FOLDER` | Перестроить активную панель |
| `#6407` | `NEWDIR` | Перечислить каталог и построить индекс |
| `#65BB` | `WLIT` | Нарисовать видимую часть списка |
| `#6715` | `I_N_T` | IM2: таймер, экран, клавиатура, часы |
| `#6868` | `DRACT` | Подключить файловый контекст и драйвер панели |

Эти адреса — внутренняя раскладка текущего `boot.$C`, не публичные входы для
`.WMF`. Плагин пользуется `#6006` и входным `IX`.

## 2. Две панели — два файловых контекста

```text
                 активная панель определяется IX

        LEFT                                      RIGHT
  WINDOW = #7EA0                            WINDO2 = #7EC4
        │                                          │
        ├─ устройство 0..6                         ├─ устройство 0..6
        ├─ DOS/driver page #F0                     ├─ DOS/driver page #F1
        ├─ catalog pages #0B..#13                  ├─ catalog pages #14..#1C
        ├─ screen page #1E                         ├─ screen page #1F
        └─ path at #F7:#1000                       └─ path at #F7:#2000
```

Страница `#F0` или `#F1` отображается в логическое окно `#0000..#3FFF`. В ней
находятся:

- буферы перечисления `#0000..#1FFF`;
- FAT-буфер `#3000` и секторные буферы `#3200/#3400`;
- текущий распакованный драйвер по `#3800`;
- поток, BPB, FAT32 ENTRY и текущий каталог.

Поэтому панели могут показывать разные устройства и каталоги: переключение
меняет не только `IX`, но и рабочую физическую страницу DOS. Глобальный код
CORE32 остаётся по `#4000`, а его данные меняются вместе с панельной страницей.

## 3. Структура панели, 36 байт

Структуры `WINDOW` и `WINDO2` имеют одинаковый формат. Offset дан одновременно
в hex и decimal.

| Offset | Размер | Поле | Назначение |
|---:|---:|---|---|
| `#00 / 0` | 1 | `style` | Тип окна и флаги рамки |
| `#01 / 1` | 1 | `cursor_mask` | Маска цвета курсора |
| `#02 / 2` | 1 | `x` | X панели: 0 слева, 40 справа |
| `#03 / 3` | 1 | `y` | Y панели |
| `#04 / 4` | 1 | `width` | Ширина |
| `#05 / 5` | 1 | `height` | Высота, меняется по текстовому режиму |
| `#06 / 6` | 1 | `color` | Цвет paper+ink |
| `#07 / 7` | 1 | reserved | Ноль |
| `#08 / 8` | 2 | `restore_buffer` | Для панелей `#FFFF`: фон отдельно не сохраняется |
| `#0A / 10` | 1 | `separator_1` | Первая горизонтальная линия |
| `#0B / 11` | 1 | `separator_2` | Вторая линия |
| `#0C / 12` | 1 | `cursor` | Видимая позиция курсора, от 1 |
| `#0D / 13` | 1 | `cursor_limit` | Нижняя граница/число доступных видимых строк |
| `#0E / 14` | 1 | `cursor_color` | Цвет активной строки |
| `#0F / 15` | 1 | `under_cursor` | Исходный цвет под курсором |
| `#10 / 16` | 2 | `list_top` | Номер первой видимой записи, от 0 |
| `#12 / 18` | 2 | `entry_count` | Общее число записей каталога |
| `#14 / 20` | 1 | `at_end` | Внутренний признак конца списка |
| `#15 / 21` | 1 | `at_start` | Внутренний признак начала списка |
| `#16 / 22` | 1 | `screen_page` | `#1E` слева, `#1F` справа |
| `#17 / 23` | 2 | `saved_offset` | Сохранённое экранное/страничное смещение |
| `#19 / 25` | 1 | `catalog_base` | 0 слева, 9 справа |
| `#1A / 26` | 1 | `catalog_page` | Текущая страница записей `0..8` |
| `#1B / 27` | 1 | `dos_page` | 0 слева, 1 справа; физически `#F0+value` |
| `#1C / 28` | 1 | `activated` | Файловый контекст/драйвер уже активирован |
| `#1D / 29` | 1 | `device` | Номер устройства `0..6` |
| `#1E / 30` | 2 | `path_begin` | Начало строки пути на странице `#F7` |
| `#20 / 32` | 2 | `path_cursor` | Место добавления следующего компонента пути |
| `#22 / 34` | 1 | `restoring` | Защита во время восстановления пути |
| `#23 / 35` | 1 | `sort_mode` | 0 off, 1 name, 2 extension, 3 size |

Первые 16 байт совместимы с общей структурой окна SOW. Поля после `#10` —
расширение именно панели. Они являются внутренним ABI: обычный плагин может
читать их для диагностики, но должен менять панель только через публичные
операции и код возврата.

### 3.1 Вычисление выбранного объекта

```text
absolute_index = panel.list_top + panel.cursor - 1
               = word(IX+#10) + byte(IX+#0C) - 1
```

`GETEN` находит четырёхбайтовый элемент индекса, подключает страницу исходной
записи и заполняет два резидентных кэша:

| Адрес | Размер | Содержимое |
|---:|---:|---|
| `#7F28` | 4 | Первый кластер объекта (`BRRR`) |
| `#7F2C` | 4 | Размер файла (`ARRR`) |
| `#7F6B` | 32 | Текущая FAT32 ENTRY/нормализованная запись |

После `GETEN` файловый просмотрщик получает размер из `ARRR`, имя из записи и
сохранённый кластер для API 50. Эти области глобальны: любой следующий выбор
или файловый вызов может их заменить.

## 4. Каталожные страницы и индекс

Один каталог хранится не как массив одинаковых 32-байтовых FAT ENTRY. CORE32
выдаёт нормализованные записи переменной длины; панель отдельно строит компактный
индекс.

```text
Левая панель                              Правая панель

#0B  index window                        #14  index window
#0C  entry data page 1                   #15  entry data page 1
 ...                                      ...
#13  entry data page 8                   #1C  entry data page 8

при чтении index отображается в #8000
при чтении записи data page отображается в #C000
```

Четырёхбайтовый элемент индекса:

```text
+0  относительная data page
+1  адрес записи, low
+2  адрес записи, high
+3  длина/служебное значение записи для внутренних проходов
```

`NEWDIR` выполняет следующий конвейер:

```text
PPATH
  │  сообщает CORE32 текущий кластер каталога
  ▼
GLSTCAT #401E
  │
  ▼
NXTETY #4057 ──► запись в #C000 ──► 4-byte index в #8000
  ▲                                      │
  └──────────── до конца каталога ───────┘
                                         │
                                  SORT → WLIT
```

На панель выделено девять физических страниц. При исчерпании буфера построение
останавливается; публичный API отмеченных объектов документирует номера
`1..2047`, и код плагина не должен предполагать больший доступный индекс.

Нельзя сохранять адрес записи из `#C000` и использовать его после следующего
`GETEN`, сортировки или файлового вызова: это адрес в переключаемой странице.
Копируйте требуемые поля в память плагина.

Элемент списка в `#C000`: `+0` — отметка, `+1..+3` — расширение для
сортировки, `+4..+7` — первый кластер, `+8..+11` — размер, `+12..+13` — время
изменения, `+14..+15` — дата изменения, `+16` — признак (`0` — каталог),
`+17` — имя с нулём. Время и дата идут подряд, как в записи FAT, и вместе дают
32-битный ключ сортировки по дате.

Сортировка переключается Ctrl+F3 (по имени), Ctrl+F4 (по расширению), Ctrl+F5
(по дате изменения, новые сверху) и Ctrl+F6 (по размеру); повторное нажатие
выключает её. В `wc.ini` это `CSORT` 1..4. Каталоги во всех режимах идут
отдельно от файлов. Сортировка по размеру до 2026-09-24 сравнивала младший
байт размера с байтами кластера, и 256 байт стояли раньше 100 — исправлено.

Строка информации под панелью (`INFO=1`) включена по умолчанию: и в
поставляемом `wc.ini`, и в шаблоне, который создаёт WC Setup. Она занимает всю
ширину панели без рамки. В текстовых режимах на 80 колонок это 38 знаков: имя,
размер справа в десяти знаках (с пробелами между тысячами, если в числе не
больше восьми цифр) или `<DIR>`, дата изменения `ДД.ММ.ГГ` и время `ЧЧ:ММ`. В
режиме 90 колонок — 43 знака: размер в тринадцати знаках и всегда с пробелами
между тысячами, дата `ДД.ММ.ГГГГ`. У записи без времени (нули) дата не
показывается. Хвост строки собирает функция расширения WildDOS `STATUS_TAIL`;
ширину она берёт из окна панели (байт +4: 40 или 45), время и дату элемента
`WCFX.STATUS` кладёт ей в `LOBU+44..+47`, за пределы строки.

## 5. Путь и устройство панели

Строки путей хранятся на физической странице `#F7`:

```text
#1000  путь левой панели
#2000  путь правой панели

формат: "1:\DIR\SUBDIR\", #FF
```

Ключевые операции:

| Процедура | Действие |
|---|---|
| `RPATH` | Создать корень `<device>:\`, сбросить файловое состояние |
| `MPATH` | Добавить каталог или обработать `..` |
| `PPATH` | Вывести/передать текущий путь и подключить DOS-контекст |
| `PATH/SIMUL` | Восстановить сохранённые пути обеих панелей из `wc.ini` |

Номера устройств:

| `device` | Драйвер |
|---:|---|
| `0` | IDE Nemo master |
| `1` | SD Z-Controller, первый интерфейс |
| `2` | SD через NGS |
| `3` | IDE SMUC master |
| `4` | IDE SMUC slave |
| `5` | IDE Nemo slave |
| `6` | SD Z-Controller, второй интерфейс |

`DRACT` сначала подключает `#F0 + dos_page` в окно `#0000`. Если панель ещё не
активирована, она получает корневой путь и вызывает внутренний `DOS_SWP` с
номером устройства. Инициализация накопителя и поиск FAT32 выполняются до
первого построения каталога.

## 6. Переключение панелей

Есть две похожие, но разные процедуры:

```text
Xpan                         XPAN
─────                        ────
только меняет IX             гасит старый курсор
ставит status dirty          сохраняет состояние UI
для внутренней операции      меняет активную отметку/страницу
не рисует интерфейс          рисует новую активную панель
```

Используйте `Xpan`, когда команда должна ненадолго обратиться к противоположной
панели, например получить каталог назначения. Обязательно вызовите его второй
раз перед возвратом либо сохраните/восстановите исходный `IX`.

В плагине не вызывайте ни одну из них по внутреннему адресу. Входной `IX`
уже указывает на активную панель, а переключение пользователя должно остаться
за менеджером.

## 7. Навигация и главный цикл

Главный цикл синхронизирован с кадром через `EI/HALT`. Порядок обработки важен:

```text
cursor
  → Alt/Ctrl
  → arrows, PgUp/PgDn, Home/End
  → Delete/Insert/Space, Backspace
  → status, Shift
  → F1, F3, F10, Tab
  → F2, F4, F5, F6, F7, F8, F9
  → Enter
  → печатный символ / '*'
```

Состояние прокрутки образуют три значения:

```text
word (IX+#10)   первая видимая запись
byte (IX+#0C)   строка курсора от 1
word (IX+#12)   всего записей
```

Home/End и PgUp/PgDn меняют их, затем `WLIT` перерисовывает видимую область.
Флаги `+20/+21` не являются заменой этой арифметике; это кэш внутреннего
отрисовщика.

### 7.1 Файловые операции панелей

- F5 копирует текущий объект или отмеченные (Insert, пробел, «*» по маске) в
  каталог другой панели; каталоги — рекурсивно. Существующее имя не
  перезаписывается: «Name already exists!», диск не меняется. MKFILE сразу
  выделяет файлу цепочку нужной длины, данные идут кусками по 16 КиБ. Копия
  получает атрибут 0 (R/H/S/A источника не переносятся — так было и в
  исходном WC).
- Ход F5 и F8 (с 2026-09-26) — одно окно на всю операцию, цветом прежней полосы
  (PBWND, заголовок «COPY», у F8 — «DELETE»; с 2026-09-28 окно 42×7 по центру
  экрана в любом текстовом режиме — X/Y сбрасываются в «центр» перед каждым
  показом, прежде 66×5). После Enter диалог «Copy N files/dirs?»
  закрывается, и сразу, пока ищутся файлы и читается FAT, в строке 2 —
  «Copying started...»; с первой порции данных — «Copying имя» (по центру,
  до 40 знаков с префиксом); строка 3 — «<n of M>», строка 5 — полоса по всей
  операции (40 клеток: доля в 64-х·40/64); строки 1 и 4 пустые. С 2026-09-27 n и
  M — файлы операции: до первого действия WC считает их (WCINI.CP_COUNT:
  отмеченный файл — один, каталог — все файлы его дерева; обход только на
  чтение, как у копии, с той же проверкой подкаталога; каталог панели — как
  был), n растёт на каждом начатом файле — и в каталогах. Прежде там был номер
  объекта панели: у каталога «0001 of 0001» на всё дерево. Больше 9999 —
  9999; отказ чтения или испорченное дерево при счёте — «of ????», ошибку
  покажет сама операция. Каталог, где записей больше 65535 (стандартный FAT32
  столько не допускает), тоже «of ????»: 16-битный индекс перечисления
  переполнился бы, и счёт после подъёма из подкаталога шёл бы по кругу
  (у самого обхода F5 — прежний предел). Счёт и номер — не
  больше 65535; дальше полоса стоит полной. M файлов делят полосу поровну: файл заполняет свою
  долю по уже переданным байтам (перед каждой порцией — по сумме прежних
  порций, без текущей; до конца файла доля не больше 63/64, у файла короче 64
  байт до передачи — 0, полная — по концу файла: при отказе полоса не бывает
  полной раньше времени); в конце успешной операции полоса доходит до 64
  перед закрытием окна (у каталогов без файлов). Прежде внутри каталога шли
  ступени 64·j/(j+8): число файлов дерева WC не знал. Полоса только растёт — и у
  файла размером около 4 ГиБ, где счётчик байтов упирается в #FFFFFFFF. Окно
  не открывается и не закрывается на каждом файле, сообщения об ошибках и
  «Abort operation?» открываются поверх него. Прежде диалог с кнопками
  [OK]/[CANCEL] стоял, пока ищутся файлы и читается FAT (у большого файла —
  секунды без перемен), а окно полосы мигало поверх него на каждом файле,
  начиная полосу с нуля. F8 (удаление) — то же окно: заголовок «DELETE»,
  «Deleting started...», затем «Deleting имя»; прежде после Enter в диалоге
  стояло «Deleting is in Progress!». Счёт и доли — те же, по файлам:
  удалённый файл закрывает свою долю, и в каталоге, и отмеченный (имя файла —
  до его удаления, у первого файла — после: до первого удалённого в строке
  «Deleting started...»). В конце F8 полоса не дорисовывается до 64:
  «DIR is not empty!» удаление не прерывает. Отказ удаления отмеченного
  файла или каталога (и поиска каталога перед удалением) — «UNKNOWN
  ERROR!!», F8 останавливается (прежде отказ удаления каталога не
  проверялся, а файла — останавливал F8 молча). Внутри удаляемого дерева у
  файла (WCINI.DL_INNER, с 2026-09-27) «File not found» — только для имени,
  которого действительно нет; отказ чтения при его поиске, отказ записи
  каталога и отказ освобождения его цепочки — «UNKNOWN ERROR!!». У
  подкаталога так же (с 2026-09-27, WCINI.TREE_NOT_FOUND и DL_DIRDEL): «DIR
  not found (src)» (поиск перед входом, и в F5) и «DIR not found (dst)»
  (удаление опустевшего) — только для имени, которого нет; отказ чтения,
  записи или освобождения цепочки — «UNKNOWN ERROR!!». F8 в любом случае
  останавливается. Если
  перечисление каталога внутри дерева (файлы, подкаталоги, проверка пустоты
  перед удалением) кончилось на отказе чтения — «UNKNOWN ERROR!!», F8
  останавливается. Прежде такой конец принимался за настоящий: F8 удалял
  подкаталог с непройденными файлами, их цепочки терялись без сообщения;
  проверка пустоты говорила «DIR is not empty!» либо удаляла каталог. F5 по
  дереву так же: сообщение и остановка, прежде копия дерева молча оставалась
  неполной. Недопустимый первый кластер каталога (1, `#0FFFFFF0..#0FFFFFF7`)
  — тоже отказ: прежде ядро теряло эту ошибку (NXTINI), и F5 такого каталога
  давал пустую копию без сообщения. Перед входом в каждый каталог дерева
  (с 2026-09-27) проверяется, что он настоящий: это не корень, его цепочка
  FAT цела (все кластеры в области данных тома, без свободных и недопустимых
  ссылок, не длиннее 4096 секторов — иначе замкнутая цепочка перечислялась
  бы без конца), первый сектор начинается «.» на этот же кластер и «..» на
  каталог, откуда вошли (у корня «..» — 0 или номер корневого кластера).
  Иначе запись испорчена — отказ, «UNKNOWN ERROR!!» (WCINI.DL_ENTER/
  CP_ENTER, ID_TREE_CHILD расширения). Прежде обход
  входил куда укажет запись: кластер 0 ядро понимает как корень (так
  задумано для «..»), и F8 одного такого каталога удалял неотмеченные файлы
  корня (на стенде — все 22, с boot.$c), F5 копировал корень; кластер корня
  или чужого каталога — по корню или по чужому дереву. Подкаталог,
  указывающий на сам текущий каталог, — тоже отказ; с 2026-09-27 — и
  подкаталог, в цепочке которого есть кластер корня (хвост, ушедший в
  корень, вёл F8 дерева по именам корня). Общие цепочки — отдельным пунктом
  ниже. Замкнутую или уходящую за том цепочку любого каталога ядро с
  2026-09-27 ловит до чтения: панель показывает его пустым, поиск и создание
  отказывают — прежде панель, поиск и создание в таком каталоге висели без
  конца (исходный WC — так же). Каталог не растёт дальше 4096 секторов
  (65536 записей — предел FAT32): полный — «Not Enough Space!» при создании. Нулевая ссылка посреди цепочки файла
  (свободный кластер) — порча, поток кончается ошибкой; прежде ядро шло по
  ней в корневой каталог — F5 молча копировал байты корня вместо конца
  файла. Кластер за концом области данных тома ядро с 2026-09-27 считает
  недопустимой ссылкой везде, где идёт по цепочке (GIPAG, переходы потока,
  DLSG), — прежде испорченная цепочка вела чтение и запись за границу тома.
  Кластеры корня DLSG с 2026-09-27 тоже не освобождает (ID_CLASSIFY_DATA;
  таблица корня — в пункте об общих цепочках): запись файла на кластере
  корня (порча) F8 — и выбранную, и внутри дерева — удаляет с «UNKNOWN
  ERROR!!», корень цел; прежде F8 освобождал FAT корня, и том терял все
  имена (первый кластер) или хвост корня с его именами (второй и
  следующие). Отличает отказ признак `ABT` страницы, где
  шло перечисление (WCINI.DL_NEXT, CP_NEXT, DL_UP, DL_EMPTY, DL_NED); он
  живёт до следующего обмена с носителем. Поэтому однократный отказ при
  чтении наперёд, после которого обход сам перечитывает каталог (после
  каждого удалённого подкаталога — заново), может пройти без сообщения: итог
  тогда тот же, что без отказа. Удаление и копирование не атомарны: при
  отказе носителя посреди шага (запись файла уже убрана, а освобождение его
  цепочки отказало; новый кластер каталога назначения выделен, но не
  присоединён) остаются потерянные кластеры — всегда с сообщением и
  остановкой. Это политика ядра: лучше потерянная цепочка (её найдёт
  chkdsk), чем запись, указывающая на свободные кластеры. Код —
  WCINI.CP_*, DL_GO, DL_INNER и PBPR (WCFX), тест `test_copy_window.py`.
- Общие цепочки — две записи на одних кластерах уже испорченного тома: F8
  одной освобождал данные другой, F8 каталога шёл по чужому дереву. С
  2026-09-27 (частичная защита) ловятся
  два случая. Корень: ни один кластер его цепочки (не только первый) не
  бывает в освобождаемой цепочке (DLSG), в цепочке источника F5 и в цепочке
  подкаталога — таблицу кластеров корня (ROOT_BUILD расширения) строит
  каждая такая проверка заново, одно чтение сектора FAT на корень в один
  кластер. Записи того же каталога: F8 до первого удаления (WCINI.DL_ALIAS,
  ID_ALIAS_ADD и ID_ALIAS_SCAN) сверяет отмеченные объекты с записями их
  каталога на носителе, не с панелью: на первом кластере отмеченного не
  должна начинаться ещё одна запись — ни неотмеченная, ни отмеченная (две
  записи на одной цепочке — порча: удалить их по очереди нельзя, первое
  удаление освобождает цепочку, и второй каталог остался бы записью на
  свободном кластере), а цепочка отмеченного каталога не должна проходить
  через первый кластер ни одной записи, в том числе отмеченной, — и через
  «.» и «..» самого каталога панели. Нарушение или отказ чтения — «UNKNOWN
  ERROR!!», F8 не удаляет ничего; такой том — для chkdsk. Проход по каталогу
  — порциями по 16 секторов (между ними кадр IM2); больше ~250 разных
  кластеров в выборе (или длинный хвост отмеченного каталога) — по частям,
  каталог читается раз на часть, хвост каталога продолжается с того же
  места. Цена — проход по каталогу панели на каждую часть: обычно это доли
  секунды, но отмеченный каталог в тысячи кластеров внутри каталога в
  тысячи записей — минуты (16 частей по 16384 записи — около 5 минут при
  14 МГц, между порциями часы и клавиатура обслуживаются). Чего
  защита не ловит: общие кластеры с записями других каталогов (файл внутри
  удаляемого дерева на кластерах объекта из другого каталога), слияние
  цепочек не на первом кластере (хвосты двух файлов), корень длиннее 768
  кластеров (бывает только при кластере меньше 4 КиБ: больше 12288 записей
  при 512 байтах; дальние кластеры такого корня не в таблице). Это находит только
  проверка всего тома (chkdsk): при каждом F8 это минуты на заполненной
  карте, и её не делают ни DOS, ни Windows. F5 общие цепочки не портит
  (источник не меняется), но копирует чужие данные — кроме корня, это не
  ловится. Проверено стендом (`alias_look.py`): прежняя сборка удаляла
  файл невыбранного соседа, освобождала данные файла-двойника, копировала
  хвост корня и падала после F8 файла в хвосте корня; новая останавливает
  каждый случай сообщением, исправные каталог и файл удаляет, как прежде.
- Перед копированием файла (F5, и в дереве) проверяется его цепочка FAT на
  всю длину данных (с 2026-09-27; WCINI.CP_SOURCE, ID_FILE_CHAIN): кластеры
  заняты, ссылки допустимы, в пределах тома и не на кластер корня,
  цепочка не короче
  размера. Иначе — «UNKNOWN ERROR!!», копия не создаётся. Прежде кластер
  источника, помеченный в FAT свободным, MKFILE тут же отдавал копии:
  источник и копия делили кластер, часть копии — чужие байты, и всё без
  сообщения; файл на кластере корня давал копию сектора корня. Проверяются
  только нужные размеру кластеры и запись FAT последнего из них: хвост
  цепочки за размером не обходится, цикл внутри нужной длины не ловится
  (чтение копии всё равно кончается на размере). Обход стоит ~1400 тактов на
  кластер при сплошной цепочке и ~7000 при разбросанной (сектор FAT на
  кластер; с 2026-09-27 — со сверкой с таблицей корня): у файла в 1 ГиБ при
  кластере 4 КиБ (262144 кластера) — порядка 25 с при 14 МГц до начала
  копирования. Внутри шлюза расширения прерывания
  выключены, поэтому обход идёт порциями до 1024 кластеров (первая короче,
  если длина не кратна 1024), а между ними
  WCFX.FC_LOOP отдаёт кадр обработчику IM2 (EI:HALT): часы, таймер и клавиши
  обслуживаются. Выделение цепочки копии (MKSG, ~4900 тактов на кластер) с
  того же дня идёт вне шлюза, при прерываниях, как в исходном WC: с
  2026-07-16 его звал ALLOCATE_FILE расширения, и файл в гигабайт выделялся
  при DI минуту и дольше. Поиск свободного кластера для роста каталога
  (DIR_GROW), F7 (MKDIR) и APPEND с 2026-09-27 тоже идёт вне шлюза:
  расширение зовёт MKSG и SRHFCL через резидентный блок в странице
  ядра (CORE_MKSG, CORE_SRHFCL), который на время поиска возвращает окну
  #C000 страницу вызывающего и его прерывания, а после — снова #E8 и DI.
  Прежде на почти полном томе с далёкой подсказкой это было DI надолго:
  65536 проверенных записей FAT ≈ 11 с при 14 МГц, миллион — около 3 минут.
  Каждая запись по-прежнему проверяется коротким вызовом шлюза (~2330 тактов,
  CHECK_FREE_SCAN_LIMIT); прерывания обслуживаются между ними.
- Отказ чтения FAT при поиске свободного места — код #FF у MKFILE и MKDIR:
  F5 файла и F7 пишут «UNKNOWN ERROR!!»; прежде «Not Enough Space!», хотя
  место было (код 16 у MKSG один на оба случая; различает MKSG_CHECKED
  расширения). F5 дерева на любой отказ MKdir каталога назначения пишет свой
  текст — «Make DIR failed (dst)».
- Отказ чтения или записи посреди копирования (LOAD512/SAVE512, обёртки
  WDOS.COPY_LOAD в ядре и WCFX.COPY_SAVE, общий отказ COPY_FAIL в MD20) прерывает
  F5: «UNKNOWN ERROR!!», недописанная копия удаляется (DELFL; если откажет и
  удаление, копия может остаться в каталоге назначения под своим именем либо
  без имени, потерянными кластерами, — отказ удаления не проверяется).
  Прежде ошибки не проверялись: после отказа чтения
  в копию уходило прежнее содержимое буфера, а F5 сообщал успех. Условие —
  драйвер, который сообщает ошибки (`ABT`): штатные драйверы `boot.$C` этого
  не делают — SD-ZC при ошибке чтения ждёт без предела, а отказ записи
  проходит незамеченным (см. docs/04, раздел о `#400C RDD`).
- Каталог нельзя скопировать в него самого или в его подкаталог: «Can't copy
  DIR into itself!», диск не меняется. До 2026-09-25 такая копия уходила в
  бесконечную рекурсию TREE/SUB1/TREE/SUB1/… до конца места, а стек индексов
  DIRCOPY (2 байта на уровень в странице окна #C000) через 8192 уровня вышел
  бы в страницу ядра. Проверка — DIRCOPY_GUARD (WCFX) и
  WCINI.DIRCOPY_INSIDE: если обе панели на одном устройстве, от каталога
  назначения поднимаемся по «..» до корня; встретился исходный каталог (его
  первый кластер — BRRR, записан GETen) — отказ. «..» не нашлась — это корень,
  только если поиск прошёл без ошибки чтения и текущий каталог действительно
  корневой; иначе тоже отказ. Отказ, как любая ошибка F5, прерывает и всю
  отмеченную группу.
- Глубина рекурсивных F5 и F8 ограничена местом стеков обхода в странице окна
  #C000: за 256 байт до её конца — «DIR name too long/END of buffer»
  (WDOS.DCIN_TAIL, WDOS.RECBUF_DEPTH). Прежде очень глубокое дерево или
  зацикленный каталог испорченного тома выводили стек за #FFFF, в страницу
  потока.
- F6 — переименование на месте (перенос в другой каталог не делается);
  атрибуты записи сохраняются, если сектор новой записи удалось найти,
  перечитать и записать — при сбое на этом шаге переименование всё равно
  состоялось, а атрибут может остаться урезанным до бита каталога. Смена
  одного регистра имени («case.txt» → «CASE.TXT») отклоняется: «Name already
  exists!», диск не меняется.
- F7 — каталог. Причина отказа называется по коду MKDIR (FEEM): «Not Enough
  Space!», «Name already exists!», «Long Name is not valid!», при отказе
  носителя (в том числе записи FAT при выделении кластера) — «UNKNOWN
  ERROR!!» (с 2026-09-26; прежде сырой код драйвера давал «Long Name is not
  valid!»). Прежде на любую
  неудачу, и на нехватку места тоже, выводилось «DIR with same name already
  exists!». Тело нового каталога («.», «..», обнулённый хвост кластера)
  пишется до записи в родителе; при отказе цепочка освобождается (если
  откажет и запись FAT, могут остаться потерянные кластеры), и каталог с
  мусором свободного кластера не появляется. С 2026-09-26 так же и при
  продлении заполненного родительского каталога (любая новая запись — F5, F6,
  F7, UNZIP): новый кластер сначала обнуляется, потом вписывается в цепочку
  каталога, а отказ чтения каталога прекращает операцию, а не принимается
  за конец каталога.
- F8 и Delete — удаление, каталоги — всем деревом (DIRTREM). После удаления
  перечитываются обе панели (WCINI.DEL_REFRESH). Если соседняя панель стояла
  внутри удалённого дерева (первый кластер её каталога теперь свободен в
  FAT, не начинается записью «.» этого каталога, вторая запись не «..»
  каталога либо родитель из неё не ссылается на него живой записью каталога —
  кластер ушёл под файл, возможно ещё не писавший данных), она уходит в корень
  своего устройства; если FAT или сектор не прочитать — тоже (проверка —
  ID_DIR_ALIVE расширения; обход родителя — не больше 4096 секторов, предел
  каталога FAT32, чтобы зацикленная цепочка испорченного тома не вешала WC). Прежде она
  оставалась в освобождённом кластере: показывала удалённые файлы, а F7 и F5
  в ней писали запись в свободное место (новый объект терялся) или поверх
  файла, которому этот кластер уже отдан. Та же проверка соседней панели —
  после плагина с кодом возврата 3 (PLUGIN_REFRESH): плагин мог удалить
  каталог через API 75 и тут же создать файл на его кластере. Проверка ловит
  кластер, отданный файлу, но целостности тома не доказывает: у «..»
  сверяются два байта имени и бит каталога, сам родитель (занятость в FAT,
  путь от корня) не проверяется.
- На диске без свободных кластеров отказ приходит не сразу: поиск места
  (SRHFCL) проходит всю FAT и на каждый кластер вызывает шлюз расширения. На
  томе 48 МБ (96 760 кластеров) это около минуты на стенде, на больших картах
  дольше. Редактор всё это время показывает «Saving...», затем «Save ERROR!
  Original file preserved.»; данные не меняются.
- До 2026-09-25 F8 по каталогу с подкаталогами обрывался на «DIR not found
  (src)»: стек имён DIRTREM лежит в странице окна #C000, а поиск ядра заходит
  в расширение, и шлюз на это время ставит туда свою страницу. Имя
  подкаталога теперь копируется в LOBU+768 (переходники DIRTREM_SUBDIR и
  DIRTREM_DELETE в MD20), и дерево удаляется целиком.

- Две панели на разных устройствах — два тома разного размера. Граница
  области данных у каждого своя (страница потока, поле RECCAT). До
  2026-09-25 она была одна на все тома, в странице расширения: после
  монтирования большего тома аллокатор меньшего мог выдать кластер за концом
  его раздела.
- Обычные операции (MKFILE, MKDIR, DELFL, F5, F8) FSInfo не пишут (с
  2026-08-24: эта запись зависала на реальной SD-ZC), поэтому счётчик
  свободных кластеров в FSInfo после них устаревает. Пишет его безопасная
  RFRH (#4030, RFRH_SAFE расширения): её зовут APPEND, когда заводит файлу
  новую цепочку, FILEX после освобождения цепочки (хвоста при усечении
  SET_EOF32, старого назначения при MOVE REPLACE) и плагин, вызвавший #4030
  сам. Счётчик тогда —
  «неизвестно» (#FFFFFFFF), Next_Free — текущая подсказка аллокатора (FSTFRC,
  негодная — #FFFFFFFF). Данные это не портит; chkdsk и fsck.fat счётчик
  поправят, Windows до этого может показывать неверное свободное место.

Все операции проверены на стенде сверкой двух одинаковых образов
(`Build/plugin-ondemand-20260924/fileops`): каждый изменённый сектор
приписывается объекту операции, чужие данные — файлы, записи каталогов,
цепочки, служебные сектора — не меняются; после каждой операции том
проверяется на уровне chkdsk (копии FAT, потерянные и общие кластеры, LFN,
имена 8.3, «.»/«..», FSInfo) и независимым чекером проекта ChkDsk. Образы —
с кластером 512 байт без MBR и с MBR и кластерами 4 и 32 КиБ.

## 8. Как плагину работать с панелью

### 8.1 Получить файл, на котором запущен плагин

При вызове по расширению WC уже:

1. заполнил текущую ENTRY;
2. передал размер в `DE:HL` и имя по `BC`;
3. спозиционировал файловый поток на начало.

Можно сразу вызывать API 48 `LOAD512`. Если перед чтением выполнялся другой
файловый вызов, восстановите позицию API 50 `GIPAGPL`.

### 8.2 Найти объект по имени в активном каталоге

```asm
        LD      HL,Name
        LD      A,59                  ; FENTRY
        CALL    #6006
        JR      Z,.not_found
        ; DE:HL = размер. Для чтения затем API 62 GFILE.

Name:   DB      #00,"FILE.BIN",0
```

### 8.3 Обработать отмеченные файлы

API 54 не требует разбирать внутренний каталог панели:

```text
HL=0       → NZ, BC=число отмеченных; Z, если отмеченных нет
HL=1..2047 → DE получает name,0; Z = имя получено
```

На каждом успешном объекте API также позиционирует поток в начало файла, если
bit 7 регистра H не был установлен. `IX` должен оставаться адресом панели,
полученным при входе.

### 8.4 Изменить каталог и обновить экран

После MKFILE, MKDIR, DELFL, RENAME, APPEND или FILEX завершите плагин с `A=3`:

```asm
        LD      A,3                   ; WC сам выполнит FOLDER/NEWDIR/SORT
        RET
```

Это единственный безопасный публичный способ согласовать число записей,
индекс, сортировку, курсор и строку статуса. Прямое увеличение `(IX+#12)` не
создаёт запись и повреждает представление панели.

### 8.5 Перебирать каталог отдельно от панели

Клонируйте поток API 57, `D=#FE`, затем сбросьте перечислитель API 56,
`A'=1`, и вызывайте API 58. Так переход в подкаталог или FENTRY не меняет
живой поток, которым менеджер продолжит пользоваться после возврата.

## 9. Как добавить команду в сам менеджер

Для изменения `MD20/WCFX/WCVW` используйте такой порядок:

```text
клавиша в MAIN
   │
   ├─► GETEN, если нужен выбранный объект
   │
   ├─► DRACT/файловая операция в контексте активной панели
   │
   ├─► Xpan дважды, если нужен контекст второй панели
   │
   ├─► FOLDER для каждой изменённой панели
   │
   └─► пометить STUS и вернуться в кадровый цикл
```

Правила внутренней команды:

- сохраняйте `IX`, если временно меняете панель;
- не держите указатели в `#8000/#C000` через вызов, который меняет страницу;
- считайте `#7F28/#7F2C/#7F6B` одноэлементным глобальным кэшем;
- перед прямым `#40xx` подключайте правильную страницу `#F0/#F1` и на каждом
  выходе восстанавливайте прежнее отображение;
- после изменения каталога перестраивайте индекс, а не редактируйте его
  частично;
- учитывайте, что F5/F6 используют обе панели и два разных DOS-контекста.
- при F5 храните оставшееся логическое число байт из `FENTRY` и передавайте
  последнему `LOAD512/SAVE512` только `ceil(bytes_left/512)` секторов; FAT EOC
  ограничивает выделенную цепочку, но не обозначает логический конец файла.

## 10. Типичные ошибки

| Ошибка | Почему проявляется | Правильное действие |
|---|---|---|
| Сохранён указатель на запись в `#C000` | Следующий GETEN подключил другую страницу | Скопировать имя/метаданные в страницу плагина |
| Плагин изменил `(IX+#12)` | Изменилось число, но не индекс и каталог | Выполнить файловую API и вернуть `A=3` |
| После FENTRY сразу вызван LOAD512 | FENTRY только нашёл запись | Вызвать API 62 `GFILE` |
| F5 ждёт EOC для маленького файла | Выделенный кластер длиннее логического файла | Ограничить последний обмен размером из FENTRY |
| GDIR выполнен в исходном потоке панели | Активный каталог панели заменён изнутри плагина | Сначала клонировать STREAM `D=#FE` |
| Служебный Xpan вызван один раз | `IX` остался на другой панели | Вызвать второй раз или восстановить IX |
| Один файловый адрес используется в обеих панелях | `#0000` отображает разные физические страницы | Копировать данные через постоянное окно/явный буфер |
