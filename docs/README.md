# Wild Commander Improved: документация для разработчика

Эта папка описывает текущую архитектуру и программные интерфейсы Wild
Commander Improved. Документация рассчитана на автора плагина, драйвера или
изменения самого менеджера, а не только на пользователя готовой сборки.

Единая печатная версия всех пяти руководств:
[Wild Commander Improved — руководство программиста (PDF)](Wild_Commander_Improved_Programmer_Guide.pdf).
Она содержит общее оглавление и собирается скриптом
[`tools/build_docs_pdf.py`](../tools/build_docs_pdf.py).

Если нужна одна практическая точка входа, обычный плагин вызывает функции так:

```asm
WLD     EQU #6006

        ; Пример API без дополнительного байта в A.
        LD      HL,Text
        LD      DE,#0101
        LD      A,11                 ; API 11, TXTPR
        CALL    WLD

        ; Пример API, которому нужен собственный A.
        ; Значение передаётся через альтернативный A'.
        LD      A,#FE                ; основной текстовый экран
        EX      AF,AF'
        XOR     A                    ; API 0, MNGC_PL
        CALL    WLD
```

Номера API в тексте без префикса записаны десятичными. Префикс `#` означает
шестнадцатеричное число: API `78` — это `#4E`, а не `#78`. Это особенно важно
для старых C-заголовков, где часть поздних номеров записана ошибочно.

## Граница стабильности

В проекте есть три разных уровня входов. Они похожи внешне, но не
взаимозаменяемы.

| Уровень | Вход | Для кого | Статус |
|---|---:|---|---|
| Публичный API плагинов | `A=0..86`, `CALL #6006` | Любой `.WMF` | Основной совместимый интерфейс |
| Внутренний API CORE32 | `CALL #4000+offset` | Код WC и тесно связанный системный код | Требует файловой страницы в окне `#0000`; раскладка состояния внутренняя |
| Приватный шлюз CORE32_EXT | `CALL #5123`, затем байт ID | Только CORE32 | Деталь реализации Improved; плагинам запрещён |

Практическое правило: код, который можно оформить обычным `.WMF`, должен
использовать `#6006`. Прямой вызов `#40xx` не является ускоренной версией того
же API: он обходит обёртки страниц, состояние панели и восстановление памяти.

## Источники истины

Документы сверены с текущими исходниками. При будущих изменениях числовой ABI
нужно проверять в следующем порядке:

1. [`source/MD20.ASM`](../source/MD20.ASM) — диспетчер и фактическая таблица
   публичного API `0..86`.
2. [`source/CORE32_FILEX_API.ASM`](../source/CORE32_FILEX_API.ASM) —
   машинно-читаемые константы API 77.
3. [`source/KERNEL.ASM`](../source/KERNEL.ASM) и
   [`source/CORE32.ASM`](../source/CORE32.ASM) — внутренняя таблица `#4000`,
   память файлового ядра и фактическое поведение.
4. [`source/WCVLS.ASM`](../source/WCVLS.ASM),
   [`source/WCVW.ASM`](../source/WCVW.ASM) и
   [`source/WCINI.ASM`](../source/WCINI.ASM) — структуры панелей, загрузчик
   плагинов и конфигурация.
5. [`source/PHYSICAL_MEMORY_MAP.ASM`](../source/PHYSICAL_MEMORY_MAP.ASM) —
   обязательный контракт верхних физических страниц.

[`source/plugins/READ_ME.TXT`](../source/plugins/READ_ME.TXT) остаётся важным
историческим описанием плагинной системы. Старые копии `wc_api.h` и `wc_h.h`
полезны как примеры интеграции с C, но не считаются точным числовым ABI.

## Обозначения

- `#1234` — шестнадцатеричное значение в синтаксисе используемых ASM.
- `LE16`/`LE32` — little-endian слово/двойное слово.
- `[start,end)` — полуинтервал: `end` уже не входит в диапазон.
- `Z`/`NZ`, `CF` — флаги Z80 непосредственно после возврата из функции.
- `A'`, `BC'`, `DE'`, `HL'` — альтернативный набор регистров.
- «страница» без уточнения — физическая страница TS-Conf размером 16 КиБ.
- «окно» — одно из четырёх логических окон Z80: `#0000`, `#4000`, `#8000`
  или `#C000`.

Не полагайтесь на незадокументированные сохранённые регистры. Диспетчер
`#6006` как минимум изменяет альтернативный `BC`, а файловые расширения имеют
собственные наборы разрушаемых регистров. Результирующие флаги нужно проверять
сразу, до `OR`, `CP`, `INC` и других команд, которые меняют `F`.
