# Уровень WildDOS/CORE32: файловое API и внутренняя архитектура

WildDOSFileCore, или CORE32, реализует FAT32, каталоги, потоки и операции
изменения файлов. Этот документ показывает, как пользоваться им из плагина и
как обращаться к внутреннему API из кода самого менеджера.

## 1. Четыре уровня вызова

```text
┌─────────────────────────────────────────────────────────────┐
│ Плагин .WMF                                                │
│ A=0..86, CALL #6006                                        │
└──────────────────────────────┬──────────────────────────────┘
                               │ публичные X*-обёртки
┌──────────────────────────────▼──────────────────────────────┐
│ Wild Commander                                             │
│ подключает panel DOS page, переводит буферы, восстанавливает│
└──────────────────────────────┬──────────────────────────────┘
                               │ CALL #4000+offset
┌──────────────────────────────▼──────────────────────────────┐
│ CORE32                                                     │
│ FAT32, directory, stream, APPEND, FILEX gate               │
└──────────────────────────────┬──────────────────────────────┘
                               │ CALL #3800+offset
┌──────────────────────────────▼──────────────────────────────┐
│ Драйвер                                                    │
│ LBA32, блоки по 512 байт, IDE/SD/NGS                       │
└─────────────────────────────────────────────────────────────┘
```

Для `.WMF` допустим только верхний вход `#6006`. Внутренний `#4000` не
подключает нужную страницу и не защищает память плагина.

## 2. Установка при старте

Физический payload содержит CORE32 около `#C000`. При `WC_ENTRY` установщик
копирует рабочую часть в постоянный логический диапазон `#4000..#5BF1`:

```text
boot payload                           runtime Z80

#C00C..#CA87 (DR1..DR4, DEHR) LDIR ─► #5176..#5BF1
#CA88..#D79C (код ядра, HR) ── DEHR ─► #4000..#5175
CORE32_EXT, часть 1 ── DEHR ───────► page #E8:#C000..WDOS_EXT_PART2_START-1
CORE32_EXT, часть 2 (хвост файла
  #D79D..) ── LDIR на место части 1,
  DEHR ────────────────────────────► page #E8:WDOS_EXT_PART2_START..
packed drivers #5176..#5AA9 ─ LDIR ─► page #E8:DRIVERS_E8 (распаковывает DOS_SWP в #3800)
резидентный блок расширения ─ LDIR ─► #5176.. (на место драйверов)
```

Код `#4000..#5BF1` соседствует с менеджером `#6011..`; данные находятся в
переключаемой странице `#0000..#3FFF`. Это даёт каждой панели собственное
файловое состояние при одном общем коде.

С 2026-09-27 код ядра `#4000..#5175` лежит в файле HR-потоком (4470 байт →
3349), драйверы DR1..DR4 и DEHR — как есть: заглушка по `#C000` ставит
LDIR в `#5176..#5BF1`, затем только что поставленный DEHR (`#5AAA`)
разворачивает код. Расширение — две части (место перед `#BF60` кончилось,
docs/05, 5.3); граница частей — по месту (tools/split_extension.py): поток
части 1 влезает до `#BF60`, поток части 2 — в хвост до `#E000` и на место
потока части 1, обе части распаковываются обратно (у отдельных длин MHMT
даёт поток, который его же распаковщик не читает). Длина потока растёт с
границей не строго, поэтому за двоичным поиском просматривается окно вокруг
найденной границы и берётся первая сверху, проходящая все проверки; части —
не короче 16 байт (меньше MHMT не пакует).
Часть 2 лежит в хвосте файла за потоком кода ядра, при загрузке — в окне
`#C000` загрузочной страницы. Весь `boot.$C` — не длиннее 32768 байт: BIOS
TS-Conf читает файл целыми кластерами с `#6000`, и при кластере 32 КиБ
(обычном у SDHC после SD Formatter) второй кластер — 64 КиБ с `#6000` —
через `#FFFF` затирал `#0000..#5FFF`: экран, системные переменные и стек BIOS
в странице `#05`; машина падала до старта WC (стенд combo64 с файлом 35345
байт, 2026-09-27). Последний сектор Hobeta не добивается: 128 целых секторов с
заголовком — уже 32785 байт. Установщик до любой распаковки сверяет метку
сборки в самом конце файла (`WDOS_EXTENSION2_MARK`; загрузчик, прочитавший
файл не до конца, оставил бы чужие байты и на месте потока кода ядра, и на
месте части 2 — тогда красный бордюр и остановка DI:HALT, WC не
запускается), ставит ядро, распаковывает часть 1 в `#E8`, возвращает
загрузочную страницу, переносит поток части 2 на место потока части 1 (там
уже можно писать) и распаковывает его туда же, за часть 1. Затем
`EXT_INSTALL_TAIL` расширения (строка таблицы ID_INSTALL_TAIL, 52; за ней —
ALIAS_RESET, ALIAS_ADD, ALIAS_SCAN)
переносит упакованные драйверы DR1..DR4 ядра (2356 байт, `#5176..#5AA9`) в
`DRIVERS_E8` страницы `#E8` — `DOS_SWP` распаковывает их оттуда через шлюз
(UNPACK_DRIVER прибавляет сдвиг), а на их место в странице `#05` кладёт
резидентный блок расширения: `CORE_MKSG` и `CORE_SRHFCL` зовут MKSG и SRHFCL
ядра со страницей и прерываниями вызывающего (OUTER_PAGE, OUTER_IFF — их
запоминает шлюз при внешнем входе) и возвращают `#E8` и DI. Загрузчики:
TS-BIOS (читает файл по цепочке до конца) и второй — `WCVW.RUNHOB` (Enter
на `boot.$C` в панели) проверены на стенде; запуск из TR-DOS/Mounter — нет.

Шлюз расширения возвращает вызывающему все регистры функции, IX тоже.
Функция, которой IX не нужен для результата, обязана его сохранить: WC
держит в IX описатель окна или панели (стенд 2026-09-27: `ALIAS_ADD`,
оставлявший в IX указатель слота, давал F8 ложные отметки и зависание).

## 3. Монтирование тома

Внутренний путь панели:

```text
DOS_SWP #401B
  │ распаковать драйвер и SELDEV
  ▼
DEVINI #4003
  │ обнаружить устройство
  ▼
HDD #4009
  ├─ прочитать LBA 0
  ├─ найти primary/extended FAT-раздел или superfloppy BPB
  ├─ проверить FAT32 BPB, bytes/sector=512, SPC=power of two
  ├─ прочитать BPB_ExtFlags и FSInfo
  └─ вычислить FAT/data geometry
```

Основные вычисленные поля:

| Имя | Значение |
|---|---|
| `ADDTOP` | Абсолютный LBA начала выбранного раздела/тома |
| `BREZS` | BPB reserved sectors |
| `FSINF` | Относительный сектор FSInfo |
| `BFATS` | Число FAT |
| `BFTSZ` | Размер одной FAT в секторах, 32 бита |
| `BSECPC` | Секторов на кластер |
| `BROOTC` | Корневой кластер |
| `SFAT` | Относительное начало FAT, обычно reserved sectors |
| `SDFAT` | Относительное начало data area |
| `FSTFRC` | Подсказка первого свободного кластера |

Преобразование кластера в LBA:

```text
data_lba(cluster) = ADDTOP + SDFAT + (cluster - 2) * BSECPC
fat_lba(cluster)  = ADDTOP + SFAT  + floor(cluster * 4 / 512)
```

Кластер `0` в `GIPAG` означает root и заменяется `BROOTC`.

## 4. Рабочая память CORE32

```text
#0000 ┌─────────────────────────────┐
      │ GENBU/NXTBU: directory      │
#1000 │ две половины по 4 КиБ       │
#2000 ├─────────────────────────────┤
      │ внутренняя служебная область│
#3000 ├─────────────────────────────┤ SECBU: FAT sector
#3200 ├─────────────────────────────┤ LOBU: sector/data
#3400 ├─────────────────────────────┤ LOBU2: second sector
#3600 ├─────────────────────────────┤
#37F8 │ iterator state              │
#3800 ├─────────────────────────────┤ driver JP table
#3848 │ stream/BPB/ENTRY state      │
#4000 └─────────────────────────────┘
```

Важные следствия:

- перечисление каталога уничтожает `#0000..#1FFF` этой физической страницы;
- `SECBU/LOBU/LOBU2`, текущая ENTRY и поток глобальны внутри одной панели;
- файловые вызовы не реентерабельны;
- указатель в одном из этих буферов нельзя сохранять через другую операцию;
- внешний плагин должен держать свои структуры в своей странице и пользоваться
  обёртками `#6006`.

## 5. FAT32 ENTRY и имена

Текущая короткая запись имеет стандартные 32 байта FAT:

| Offset | Поле |
|---:|---|
| `+0..+10` | SFN 8.3 |
| `+11` | Атрибуты |
| `+13` | Create tenth |
| `+14/+16` | Create time/date |
| `+18` | Access date |
| `+20` | Старшие 16 бит первого кластера |
| `+22/+24` | Write time/date |
| `+26` | Младшие 16 бит первого кластера |
| `+28` | Размер LE32 |

Публичные запросы имени используют форму:

```text
[type][name bytes][0]

type #00 = file
type #10 = directory
```

Текущий валидатор принимает до 255 байт, отвергает управляющие символы и
`"*/:<>?\|`. Конечные пробелы/точки удаляются. Пробел внутри имени включает
LFN. Начальные пробелы LFN нормализуются при создании и поиске, внутренние
остаются значимыми.

## 6. Потоковая модель

Поток хранит текущий кластер, LBA, сектор внутри кластера, EOC, обработчик I/O
и активный каталог.

```text
GFILE/GIPAG
     │
     ▼
cluster N, sector 0
     │ LOAD512 B sectors
     ├─► sector 1 ─► ... ─► sector SPC-1
     │                              │
     │                              ▼ CURIT
     └──────────────────────── next cluster
                                    │
                                    └─ EOC #0F
```

Результат нормального потока:

| Состояние | `A` | `CF` | Действие вызывающего |
|---|---:|---:|---|
| Запрос выполнен, цепочка продолжается | `#00` | 0 | Можно читать следующий блок |
| Встречен FAT EOC | `#0F` | 0 | Штатный физический конец цепочки |
| I/O/FAT error | `#FF` | 1 | Немедленно прекратить |

`#0F` — не логический EOF файла. Всегда ограничивайте полезные байты 32-битным
размером ENTRY/FENTRY.

Переход к следующему кластеру читает сектор FAT только при смене сектора
(один раз на 128 кластеров): `SECBU` страницы служит кэшем, а признак `FATTAG`
(`#3858`) сверяется с общим поколением FAT. Поколение сбрасывают запись FAT,
монтирование, смена и инициализация драйвера и начало чтения каталога;
подробности — в разделе «Контракт потоков» `source/CORE32_API.md`.

`SAVE512` пишет только уже выделенную цепочку. Он не создаёт кластер и не
изменяет размер. Для роста есть APPEND или FILEX.

## 7. Публичные файловые сценарии плагина

### 7.1 Найти → выбрать → прочитать

```text
FENTRY 59  [#00,"FILE",0]
   │ NZ, DE:HL=size
   ▼
GFILE 62
   │
   ▼
LOAD512 48  (HL=buffer, B=sectors)
```

```asm
        LD      HL,Query
        LD      A,59
        CALL    #6006
        JR      Z,.not_found
        LD      (SizeLo),HL
        LD      (SizeHi),DE

        LD      A,62
        CALL    #6006

        LD      HL,Buffer
        LD      B,1
        LD      A,48
        CALL    #6006
        JR      C,.io_error
```

### 7.2 Создать → записать существующую цепочку

```text
MKFILE 72 [attr,size32,name,0]
   │ Z; поток поставлен в начало созданного файла
   ▼
SAVE512 49
```

Если размер не кратен 512, последний сектор всё равно существует целиком; код
должен определить содержимое его хвоста. Для нового пустого файла создайте
`size=0`, затем используйте APPEND/WRITE_AT вместо SAVE512.

### 7.3 Перечислить каталог

```text
STREAM 57, D=#FE       clone panel stream
ADIR 56, A'=1          reset enumerator
NXTETY2 58             repeat until Z
```

Выход API 58 имеет переменный формат: включённые маской size/date/time, затем
`entry_flag`, имя и ноль. Перед передачей записи в FENTRY/DELFL оставьте в
флаге только bit 4 (`AND #10`).

### 7.4 Создать каталог и войти

```text
MKDIR 73 [name,0]
  │ Z
  ▼
FENTRY 59 [#10,name,0]
  │ NZ
  ▼
GDIR 63
```

В исходном потоке панели GDIR запрещён: сначала клонируйте поток. Если цель —
изменить видимую панель, завершите плагин с `A=3` и позвольте менеджеру самому
перечитать каталоги обеих панелей, сохранив активную.

### 7.5 Удалить каталог

API 75 не проверяет, пуст ли каталог. Безопасный порядок:

1. FENTRY каталога.
2. Клонировать поток и выполнить GDIR.
3. NXTETY2 убедиться, что кроме `.`/`..` записей нет.
4. Вернуться в родительский поток.
5. DELFL с type `#10`.

### 7.6 Перед первым DOS-вызовом: памятка начинающему

Публичный DOS API вызывается тем же способом, что остальной API WC:

```asm
        ; 1. Заполнить все входные регистры и буферы.
        ; 2. Последним загрузить номер функции в A.
        LD      A,59                  ; десятичный номер FENTRY
        CALL    #6006
        ; 3. Сразу проверить документированный флаг.
        JR      Z,.not_found
```

Основные обозначения:

```text
DE:HL       32-битное число: DE — старшие 16 бит, HL — младшие
Z           zero flag установлен
NZ          zero flag сброшен
CF          carry flag; для потока CF=1 означает ошибку
[type,name,0]
             байт #00/#10, байты имени, завершающий ноль
buffer end  адрес сразу после буфера, а не адрес последнего байта
```

Если функции нужен входной `A`, его передают через `A'`, потому что основной
`A` занят номером API:

```asm
        LD      A,1                   ; подкоманда ADIR: reset iterator
        EX      AF,AF'
        LD      A,56                  ; номер API
        CALL    #6006
```

Самые безопасные места для данных обычного плагина — его текущая страница
`#8000..#BFFF`. Не помещайте запрос или имя в `#C000`: многие вызовы сами
переключают это окно. Не храните рабочие данные в `#0000..#3FFF`, если плагин
переключает окно API 78/80. FILEX вообще принимает только `#8000..#BFFF`.

### 7.7 API 48 `LOAD512`: последовательное чтение

Назначение: прочитать один или несколько 512-байтовых секторов из уже
выбранного файлового потока.

Перед вызовом поток должен указывать на файл:

- при запуске плагина по расширению WC уже позиционировал его;
- после API 59 `FENTRY` нужно вызвать API 62 `GFILE`;
- для исходного файла, переданного плагину, можно повторно вызвать API 50.

| Параметр | Значение |
|---|---|
| `HL` | Начало выходного буфера |
| `B` | Число блоков по 512 байт |
| Выход `HL` | Адрес сразу за обработанными блоками |
| Выход `A=0, CF=0` | Запрос завершён, цепочка ещё не доказанно закончилась |
| Выход `A=#0F, CF=0` | Встречен физический EOC FAT |
| Выход `A=#FF, CF=1` | Ошибка чтения/FAT |

```asm
        LD      HL,Buffer
        LD      B,2                   ; 1024 байта
        LD      A,48
        CALL    #6006
        JR      C,.read_error
        LD      (NextBuffer),HL
```

Нельзя считать, что все 1024 байта полезны: сначала сохраните размер из
FENTRY и обрабатывайте только `min(request, bytes_left)`. Не задавайте блок,
который пересекает `#FFFF→#0000`; разделите его. Вызов теряет состояние
FindNext, поэтому перечисление каталога после него нужно начать заново.

### 7.8 API 49 `SAVE512`: последовательная запись без роста

Назначение: записать данные в уже существующие секторы выбранной FAT-цепочки.

| Параметр | Значение |
|---|---|
| `HL` | Исходный буфер |
| `B` | Число блоков по 512 байт |
| Выход | Как LOAD512: новый HL, потоковый A/CF |

```asm
        LD      HL,Buffer
        LD      B,1
        LD      A,49
        CALL    #6006
        JR      C,.write_error
```

Критически важно: SAVE512 не выделяет кластеры и не меняет поле размера. Его
можно применять после MKFILE с заранее заданным ненулевым размером либо для
перезаписи существующего файла в пределах его цепочки. Запись за логический
EOF через SAVE512 создаёт несогласованные скрытые данные; для этого используйте
APPEND или WRITE_AT.

Статус конца цепочки ограничивает только физически выделенные кластеры, а не
логический EOF. Поэтому последний вызов должен передавать в `B` ровно
`ceil(bytes_left/512)`, а не полный 32-секторный буфер. Иначе маленький файл на
крупном кластере без необходимости запишет до 16 КиБ кластерного хвоста.

Штатный `WCFX.COPYF` следует этому правилу: сохраняет 32-битный размер из
`FENTRY`, обрабатывает полные блоки по 16 КиБ и завершает копирование точным
числом секторов последнего блока. Для файла 541 байт это два сектора независимо
от того, выделила FAT под файл кластер 4, 32 или 64 КиБ.

### 7.9 API 50 `GIPAGPL`: вернуть исходный файл плагина

API 50 берёт кластер из кэша выбранного менеджером объекта `#7F28` и ставит
поток на его первый сектор.

```asm
        LD      A,50
        CALL    #6006
```

Входных регистров нет. Используйте его, если другой вызов сдвинул поток файла,
который WC передал плагину. Для произвольного файла, найденного вашим FENTRY,
правильный вызов — API 62 GFILE, а не API 50.

### 7.10 API 51 `TENTRY`: получить 32 байта FAT ENTRY

| Параметр | Значение |
|---|---|
| `DE` | Выходной буфер минимум 32 байта |
| Выход | 32 байта скопированы, `DE` продвинут LDIR |

```asm
        LD      DE,EntryCopy
        LD      A,51
        CALL    #6006
```

Из ENTRY можно прочитать атрибут, timestamps, first cluster и size. Копируйте
её сразу: внутренний экземпляр общий и будет заменён следующим FENTRY/GETEN.
Не меняйте полученную копию в надежде изменить диск — это только снимок.

Времена в ENTRY — как на носителе, без проверки календаря. Штампы для показа
или передачи дальше (FTP, SMB) берите у FILEX GET_METADATA (10.3): там штамп,
которого нет в календаре, уже заменён на 2026-01-01 00:00. API 51 копирует
снимок ENTRY, сохранённый WC при FENTRY, и контекст APPEND/FILEX не трогает.
Прямой вход ядра `#4036 TENTRY` (8.14) — другое: он заново запоминает
положение записи по альтернативному `BC`.

### 7.11 API 52 `CHTOSEP`: разложить цепочку в LBA

Назначение: получить последовательность физических LBA32 всех секторов файла,
переданного менеджером.

| Параметр | Значение |
|---|---|
| `DE` | Начало массива четырёхбайтовых LBA |
| `BC` | Адрес сразу после массива |
| Источник цепочки | Сохранённый кластер объекта `#7F28` |

```asm
        LD      DE,SectorList
        LD      BC,SectorListEnd
        LD      A,52
        CALL    #6006
```

Это исторический низкоуровневый вызов без удобного возвращаемого счётчика и с
грубой проверкой границы по кластерам. Буфер должен быть рассчитан заранее из
размера файла и `sectors_per_cluster`; оставляйте место как минимум для
полного последнего кластера. Для обычного чтения используйте LOAD512, а для
позиционного — READ_AT.

### 7.12 API 53 и 55: зарезервированы

Оба номера ведут в пустой `RET`:

```asm
        LD      A,53                  ; ничего не делает
        CALL    #6006
```

Они не являются TENTRYN/TMRKNXT и не должны использоваться как feature probe.
API 76/77 находятся на собственных номерах и не заменяют эти значения.

### 7.13 API 54 `TMRKFL`: отмеченные объекты панели

API работает с внутренним индексом панели и требует исходный `IX`, полученный
при входе в плагин.

Режим подсчёта:

```asm
        LD      HL,0
        LD      A,54
        CALL    #6006
        JR      Z,.none_marked
        ; BC = число отмеченных объектов
```

Режим получения N-го отмеченного объекта:

```asm
        LD      HL,1                   ; первый отмеченный
        LD      DE,NameBuffer          ; до #BFFF, место до 256 байт
        LD      A,54
        CALL    #6006
        JR      NZ,.not_found          ; для этого API Z = имя получено
```

При `HL=1..2047` bit 7 регистра H имеет специальное значение. Если он сброшен,
успешный вызов также позиционирует файловый поток на начало объекта. Если нужен
только заголовок без смены потока, установите bit 7 и передайте номер в
остальных 15 битах. Каталоги и файлы определяются по внутреннему флагу записи.

### 7.14 API 56 `ADIR`: состояние активного каталога

Подкоманда передаётся через `A'`:

| `A'` | Действие |
|---:|---|
| `0` | Позиционировать активный каталог как поток с начала |
| `1` | Сбросить счётчики FindNext/NXTETY2 и восстановить активный каталог |

```asm
        LD      A,1
        EX      AF,AF'
        LD      A,56
        CALL    #6006
```

Вызывайте подкоманду 1 перед первым API 58 и после любой операции, которая
сбрасывает iterator: MKFILE, MKDIR, LOAD512, SAVE512 или FENTRY.

### 7.15 API 57 `STREAM`: создать и переключить поток

Поток — сохранённая копия драйвера, FAT geometry, каталога и текущей позиции.
WC предоставляет два пользовательских потока, 0 и 1, на физических страницах
`#F3/#F4`; исходный поток панели сначала нужно клонировать.

Специальные команды:

```asm
        LD      D,#FE                 ; clone panel stream → 0 и 1
        LD      A,57
        CALL    #6006

        LD      D,#FF                 ; root текущего клонированного потока
        LD      A,57
        CALL    #6006
```

Выбор существующего потока:

```asm
        LD      D,1
        LD      BC,#FFFF
        LD      A,57
        CALL    #6006                 ; флаги в этом режиме не определяют ошибку
```

Создание/пересоздание:

```asm
        LD      D,0                   ; номер потока
        LD      B,0                   ; SD-ZC
        LD      C,0                   ; раздел исторически не используется
        LD      A,57
        CALL    #6006
        JR      NZ,.mount_failed
```

Значения `B`: 0 SD-ZC, 1 Nemo master, 2 Nemo slave, 4 SMUC master, 5 SMUC
slave. Команда `D=#FD` выбирает INI-поток и каталог WC; при ошибке A=1 означает
устройство, A=2 каталог WC. Не вызывайте `D=#FF` или GDIR до клонирования.

### 7.16 API 58 `NXTETY2`: следующая запись каталога

Перед первым вызовом выполните ADIR с `A'=1`.

| Вход | Значение |
|---|---|
| `DE` | Начало выходного буфера |
| `A' bit7` | Только SFN вместо LFN |
| `A' bit6` | В полях bit4/bit3 время и дата изменения, а не создания (с 2026-09-26) |
| `A' bit4` | Включить время, 2 байта: создания, с bit6 — изменения |
| `A' bit3` | Включить дату, 2 байта: создания, с bit6 — изменения |
| `A' bit2` | Включить size, 4 байта |
| `A' bits1..0` | 0 всё, 1 файлы, 2 каталоги |

Выход:

```text
Z   конец каталога, буфер не содержит новой записи
NZ  [optional size][optional date][optional time][flag][name,0]
DE  адрес сразу после результата
```

`Z` бывает и при отказе чтения каталога: ядро ставит ноль в начало
непрочитанного, и перечисление кончается на последней прочитанной записи.
Отличает отказ `ABT` (`#384A` страницы, где шло перечисление) ≠0 сразу после
вызова, до следующего обмена с носителем. Так делает обход дерева F5/F8 WC.
Недопустимый первый кластер каталога (1, `#0FFFFFF0..#0FFFFFF7`) — тоже `Z` с
`ABT=#FE` (с 2026-09-26: прежде NXTINI после отказа GIPAG всё же звал
LOAD512, тот обнулял `ABT`, и каталог выглядел пустым). `ABT` не
долговечен: однократный отказ при чтении наперёд, после которого запись уже
прочитана, перечисление может выдать как `NZ`, а следующий обмен сбросит
признак; вызывающему, которому нужна полнота, надёжно лишь `Z` с `ABT`≠0.

Панель WC показывает и сортирует файлы по дате изменения, поэтому списку для
человека нужен bit6. Старое ядро bit6 не знает и отдаёт создание в той же
раскладке. Штамп, которого нет в календаре (месяц не 1..12, дня нет в месяце,
часы больше 23, минуты или секунды больше 59), отдаётся как 2026-01-01 00:00:
и дата, и время, даже если запрошено одно поле. Запись на носителе при этом не
меняется.

Пример только файлов с размером:

```asm
.next:
        LD      DE,FindBuffer
        LD      A,%00000101          ; size + files
        EX      AF,AF'
        LD      A,58
        CALL    #6006
        JR      Z,.done
        ; FindBuffer+0..3 size, +4 type, +5 name
        JR      .next
```

Функция использует `#0000..#1FFF` файловой страницы. Результат копируйте до
следующего файлового вызова. Для последующей функции имени нормализуйте flag:
`AND #10`.

### 7.17 API 59 `FENTRY`: найти файл, каталог или путь

Это центральная поисковая операция. `HL` указывает на запрос:

```asm
Query:  DB      #00,"DIR\SUB\FILE.BIN",0
        ; slash и backslash распознаются как разделители пути
```

| Выход | Значение |
|---|---|
| `Z` | Объект/компонент пути не найден |
| `NZ` | Объект найден |
| `DE:HL` при NZ | 32-битный размер последнего объекта |

Успешный FENTRY также:

- сохраняет кластер найденного объекта для GFILE/GDIR;
- копирует его ENTRY в менеджер;
- создаёт новый контекст APPEND/FILEX;
- при пути временно переходит через компоненты и затем восстанавливает исходный
  активный каталог.

Неуспешный FENTRY не очищает прежний APPEND-контекст. Поэтому всегда проверяйте
Z перед API 76/77. FENTRY сбрасывает iterator API 58.

### 7.18 API 60 `LOAD256`: поток по 256 байт

Параметры аналогичны LOAD512:

| Вход | Значение |
|---|---|
| `HL` | Буфер |
| `B` | Число 256-байтовых порций |

Вызов предназначался видеопроигрывателю и передаёт обмен драйверному RDD256.
Nemo, SMUC и ZC его реализуют; SD-NGS возвращается без чтения. Для переносимого
плагина используйте LOAD512 и самостоятельно разделяйте сектор.

### 7.19 API 61 `LOADNONE`: пропустить поток

`HL/B` подаются как LOAD512, но данные не копируются. Значим прежде всего `B`;
HL остаётся частью исторического ABI.

```asm
        LD      HL,0                   ; данные не требуются
        LD      B,8                    ; пропустить восемь секторов
        LD      A,61
        CALL    #6006
        JR      C,.stream_error
```

Это линейный seek: чтобы попасть на далёкий offset, ядро проходит FAT от
текущей позиции. Для нового кода с 32-битным смещением используйте FILEX
READ_AT/WRITE_AT.

### 7.20 API 62 `GFILE`: выбрать результат FENTRY как файл

```asm
        LD      HL,Query
        LD      A,59
        CALL    #6006
        JR      Z,.not_found

        LD      A,62
        CALL    #6006
        ; Следующий LOAD512 читает с начала найденного файла.
```

API использует сохранённый кластер последнего успешного FENTRY. Не вставляйте
между FENTRY и GFILE другой поиск, который заменит этот кластер.

### 7.21 API 63 `GDIR`: выбрать результат FENTRY как каталог

```asm
        LD      HL,DirQuery
        LD      A,59
        CALL    #6006
        JR      Z,.not_found
        LD      A,63
        CALL    #6006
```

После этого найденный cluster становится активным каталогом текущего потока.
Нельзя выполнять GDIR в живом потоке панели: менеджер потеряет свой каталог.
Сначала STREAM `D=#FE`, затем работайте в клоне.

### 7.22 API 72 `MKFILE`: создать файл

Входной блок:

```text
+0      attr
+1..+4  requested size LE32
+5..    name,0
```

```asm
Create:
        DB      #00
        DD      0                     ; настоящий пустой файл
        DB      "NEW.DAT",0

        LD      HL,Create
        LD      A,72
        CALL    #6006
        JR      NZ,.create_error      ; A = код
```

При `size=0` создаётся cluster=0 без FAT-цепочки. При положительном размере
MKFILE выделяет всю цепочку, но не заполняет пользовательские байты. После
успеха поток указывает на начало нового файла, ENTRY доступна через API 51.

Исторические ошибки:

```text
1 invalid long name       2 short-name generation failure
3 long name exists        4 short name exists
16 no space               255 unknown
```

### 7.23 API 73 `MKDIR`: создать каталог

Вход — только нуль-терминированное имя:

```asm
        LD      HL,DirName
        LD      A,73
        CALL    #6006
        JR      NZ,.mkdir_error

DirName: DB      "SAVES",0
```

CORE32 выделяет кластер, зануляет его и создаёт `.`/`..`. После успеха объект
позиционирован «как файл», но не становится активным каталогом. Для входа
выполните FENTRY с type `#10`, затем GDIR в клонированном потоке.

С 2026-09-25 тело каталога (сектор с `.`/`..` и обнулённый хвост кластера)
пишется до записи в родителе; при отказе записи тела цепочка освобождается, и
в родителе ничего не появляется (MKDIR_ENTRY расширения). Освобождение —
DELCHA: код ошибки сохраняется, отказ самой записи FAT не проверяется, и
тогда могут остаться потерянные кластеры (так при любом «цепочка
освобождается» ниже, у MKDIR и MKFILE). Прежде запись
публиковалась первой, и отказ записи тела оставлял каталог с мусором
свободного кластера.

Отказ носителя при записи в родителе неоднозначен: сектор мог лечь, хоть
драйвер и вернул ошибку. Тогда имя ищется заново — по NXTBU, то есть в том
виде, в каком его записал SVHDFL (исходный текст «new » дал бы запись «NEW» и
не нашёлся бы): запись есть и указывает на новый кластер — каталог создан,
выход Z; поиск прошёл и записи нет — цепочка освобождается; поиск не удался
или нашлась запись с чужим кластером — цепочка остаётся (потерянные
кластеры), а не освобождается под живой записью.
Отказ по имени или месту (ABT=0) — цепочка освобождается, как прежде. Код
отказа носителя при записи каталога — `A=#FF` («UNKNOWN ERROR!!» в F7),
прежде он совпадал с кодом недопустимого имени (1). Отказ записи FAT при
выделении цепочки (MKSG) — тоже `#FF` (IO_RESULT, с 2026-09-26), и отказ
чтения FAT при поиске свободного кластера — `#FF` (MKSG_CHECKED, прежде 16 —
«Not Enough Space!»).
Так же с 2026-09-25 поступает MKFILE (#4039, API 72): прежде `JP NZ,DELCHA`
освобождал цепочку и под легшей записью.

### 7.24 API 74 `RENAME`: переименовать в том же каталоге

```asm
OldName: DB      #00,"OLD.TXT",0
NewName: DB      "NEW.TXT",0

        LD      HL,OldName
        LD      DE,NewName
        LD      A,74
        CALL    #6006
        JR      Z,.failed             ; not found или collision
        ; NZ = success
```

Первый запрос содержит type, второй — только новое имя. Этот исторический
вызов работает в активном каталоге. Для переноса между каталогами и явного
REPLACE используйте FILEX MOVE_RENAME.

Если прежнюю запись удалить не удалось, её короткая запись перечитывается по
месту, запомненному при первом поиске (сектор и смещение, с 2026-09-25).

Код в `A` при `Z` (его показывает окно F6 WC): `8` — источник не найден либо
его поиск не прочитал каталог (тогда `CF=1`, как у исходного ядра); код
SVHDFL (1–4 — имя, 16 — нет места) — новую запись не писали; `0` или `#0F` —
отказ носителя, не переименовано, новой записи нет; `#FF` — исход неясен:
откат не удался или новую запись не проверить, на цепочке могут остаться обе
записи. `A=0` не значит «всё как было»: если удаление прежней легло на
носитель, а её сектор не перечитался, откат оставляет цепочку без ссылок
(потерянные кластеры, данные никому не отданы), а при частичном удалении у
прежней записи уже стёрто длинное имя.
Помечена удалённой (#E5) — удаление всё же легло на носитель: новая остаётся,
выход NZ, откат не снимает последнюю ссылку на цепочку. На месте, сектор не
читается или место неизвестно — только что созданная запись удаляется, выход
Z: потерянная цепочка лучше двух записей на одной. Поиск по прежнему имени
для этого не годится: удаление пишет секторы с LFN раньше сектора SFN, и при
отказе последнего длинное имя уже стёрто, а короткая запись жива. Атрибуты
R/H/S/A переименованного объекта сохраняются, если новую запись удалось
найти, её сектор перечитать и записать: при сбое на любом из этих шагов
переименование уже состоялось (выход NZ), а атрибут может остаться урезанным
до бита каталога (запись атрибута, легшая с ответом «ошибка», его всё же
сохраняет). Сектор прежней записи перечитывается до трёх раз; не удался и
откат (новую удалить не вышло) — выход Z, `A=#FF`.

Запись нового имени (SVHDFL) отказала от носителя (ABT≠0) — она могла лечь, и
тогда на цепочке уже две записи. Новое имя ищется по NXTBU: есть и смотрит на
цепочку прежней — переименование доводится (прежняя удаляется); нет — «не
переименовано»; поиск не удался или кластер чужой — «не переименовано»,
`A=#FF`. Отказ по имени (занято, недопустимо) носителя не касается: новую
запись не писали.

Короткое имя длинного файла (с 2026-09-25): расширение 8.3 кончается на конце
имени и на недопустимом в 8.3 знаке. Прежде оно копировалось до трёх знаков без
остановки: у «README.md» было «MD»+#00, у однобуквенного — ещё и байт буфера
за концом имени (так в исходном WC; касалось всего, что создаёт записи: F5,
F6, F7, MKFILE плагинов). Основа 8.3 (8 знаков подряд) у имени короче восьми
тоже брала байты за его концом — остатки прежнего имени в буфере вызывающего
(«A» → «AZPRIV~1»): теперь копия имени в NXTBU после нормализации дополняется
нулями, и недостающие знаки основы — случайные допустимые, как и прежде для
недопустимых знаков.

Длинное имя при чтении каталога (NXTETY2) собирается не длиннее 255 знаков:
повреждённый каталог с 20 записями LFN по 13 знаков без терминатора (260)
прежде писал за 256-байтовое поле имени вызывающего.

### 7.25 API 75 `DELFL`: удалить файл или каталог

```asm
DeleteQuery:
        DB      #00,"TEMP.BIN",0

        LD      HL,DeleteQuery
        LD      A,75
        CALL    #6006
        JR      Z,.not_found_or_failed
        ; исторически NZ = удалено
```

Функция удаляет directory entry и освобождает цепочку. Она не запрещает
удаление непустого каталога. Для каталога сначала отдельно докажите пустоту.
`Z` — объект не найден либо поиск не прочитал каталог (A=8; во втором случае
CF=1), не удалось записать каталог (A=0) или, с
2026-09-25, запись уже удалена, а цепочку освободить не удалось (A=0):
прежде этот случай возвращал NZ «успех». После любой записи носителя не
трактуйте один `Z` как полную транзакционную гарантию. Если плагин удалил
каталог и вернул код 3, соседняя панель перечитывается с проверкой, не
стояла ли она в удалённом каталоге.

### 7.26 API 76 и 77

API 76 APPEND и API 77 FILEX являются такими же публичными DOS-вызовами, как
исторические функции выше. Их полные блоки, коды и примеры находятся в
[разделе APPEND](#9-api-76-append) и [разделе FILEX](#10-api-77-filex).

## 8. Внутренняя таблица `#4000`

Таблица содержит 31 трёхбайтовый `JP`. Она нужна коду WC, а не обычному
плагину.

| Адрес | Offset | Имя | Контракт |
|---:|---:|---|---|
| `#4000` | `+#00` | reserved | Пустой RET; SELDEV находится в `#3800` |
| `#4003` | `+#03` | `DEVINI` | Инициализировать драйвер, обычно Z=успех |
| `#4006` | `+#06` | reserved | Пустой RET; REINI находится в `#3806` |
| `#4009` | `+#09` | `HDD` | Найти FAT32 и заполнить geometry |
| `#400C` | `+#0C` | `RDD` | `DE:HL=LBA`, `BC=buffer`, `A=sectors`; Z/NZ по ABT |
| `#400F` | `+#0F` | `SDD` | То же для записи |
| `#4012` | `+#12` | `GIPAG` | `HL` → cluster32, ноль=root |
| `#4015` | `+#15` | `LOAD512` | `HL=buffer`, `B=sectors`, потоковое чтение |
| `#4018` | `+#18` | `SAVE512` | Потоковая запись существующей цепочки |
| `#401B` | `+#1B` | `DOS_SWP` | `A=0..6`, выбрать/распаковать драйвер |
| `#401E` | `+#1E` | `GLSTCAT` | Копирует cluster32 из `HL` в `LSTCAT` |
| `#4021` | `+#21` | `TLSTCAT` | Копирует текущий `LSTCAT` в четыре байта по `DE` |
| `#4024` | `+#24` | `SRHFCL` | Найти свободный кластер; DE:HL/Z или CF=1 |
| `#4027` | `+#27` | `APPEND` | Внутренний вход публичного API 76 |

Исторические имена `GLSTCAT/TLSTCAT` и `GENTRY/TENTRY` легко прочитать
наоборот. Ориентируйтесь на направление фактического `LDIR`, указанное в
таблице.

### 8.1 Как пользоваться внутренними входами

Внутренний вызов допустим, только когда:

1. нужная panel/stream page подключена в `#0000`;
2. CORE32 установлен по `#4000`;
3. драйвер выбран и том смонтирован, если функция работает с носителем;
4. все указатели относятся к памяти, которая останется видимой во время
   вызова;
5. на каждом пути возврата страница `#0000` будет восстановлена.

В отличие от публичного API здесь основной `A` не занят номером функции:
параметры передаются прямо в обычных регистрах, а адрес выбирается самим
операндом `CALL #40xx`.

### 8.2 `#4000` и `#4006`: пустые слоты

Оба выполняют только RET. Они оставлены для сохранения трёхбайтовой нумерации.
Настоящие драйверные SELDEV/REINI находятся по `#3800/#3806` уже внутри
подключённой файловой страницы.

### 8.3 `#4003 DEVINI`

Инициализирует текущий распакованный драйвер.

```asm
        CALL    #4003
        JR      NZ,.device_not_ready
```

Параметров общего уровня нет. Обычно `Z` означает готовность. Конкретный
драйвер может изменить большинство регистров, поэтому сохраняйте нужные сами.
DEVINI не ищет FAT32 — после него нужен HDD.

### 8.4 `#4009 HDD`

Ищет MBR/superfloppy FAT32, читает BPB и заполняет все geometry variables.

```asm
        CALL    #4009
        JR      NZ,.fat32_not_found
```

Перед вызовом драйвер должен быть выбран и DEVINI должен завершиться успешно.
HDD использует LOBU, сбрасывает current cluster/catalog/stream, FSTFRC и
iterator. `Z` означает, что файловые операции можно начинать.

### 8.5 `#400C RDD` и `#400F SDD`: абсолютные сектора

Это прямой блочный доступ без FAT-потока.

```asm
        LD      DE,#0000
        LD      HL,#1234              ; LBA = #00001234
        LD      BC,Buffer             ; адрес буфера
        LD      A,1                   ; один сектор
        CALL    #400C                 ; RDD
        JR      NZ,.media_error
```

SDD имеет те же параметры и пишет данные. Функции вызывают XPOZI, затем
SAFE_RDDSE/SAFE_SDDSE. Возвращаемый `A` равен общему `ABT`: ноль/Z — успех,
неноль/NZ — отказ. Это опасный raw I/O: он не знает границ раздела, FAT и
файлов. Не используйте его в прикладном плагине.

Об отказе знает только драйвер, который ставит `ABT`. Штатные драйверы
`boot.$C` (Nemo, SD-ZC, SD-NGS, SMUC) его не ставят никогда: SD-ZC при
ошибке чтения ждёт без предела, а отвергнутую картой или запрещённую
защитой запись молча считает выполненной. Поэтому всё описанное здесь про
отказы носителя — откаты RENAME, MKDIR/MKFILE, F5, APPEND, FILEX, проверки
ENTRY_LANDED — действует с драйвером, сообщающим ошибки; со штатными
драйверами эти ветки не срабатывают, а отказ записи остаётся незамеченным.
Штатная сборка такого драйвера не содержит: экспериментальный SD-ZC из
`source/DSDZC.ASM` рассчитан на особую сборку расширения (номера шлюза в нём
зашиты числами), `build.ps1` её не делает, и сообщает ли он ошибки на деле,
не проверялось.

### 8.6 `#4012 GIPAG`

`HL` указывает на четырёхбайтовый номер кластера:

```asm
Cluster:
        DD      5

        LD      HL,Cluster
        CALL    #4012
        JR      NZ,.bad_or_eoc
```

Нулевой cluster означает root. GIPAG сбрасывает `NSDC/EOC`, запоминает текущий
кластер, вычисляет первый data LBA и вызывает драйверный XPOZI. На успехе Z.
Передача EOC/reserved/bad cluster является ошибкой контекста.

### 8.7 `#4015 LOAD512` и `#4018 SAVE512`

Прямой потоковый ABI совпадает с публичными API 48/49: `HL=buffer`, `B=count`.
Но прямой вход не выполняет плагинную трансляцию страниц. Буфер должен быть
видим при текущей карте памяти.

LOAD512 временно использует `NW0=SAFE_RDDSE`. SAVE512 меняет его на
SAFE_SDDSE, затем общий эпилог возвращает обработчик чтения. Из-за глобального
NW0 оба входа нельзя вкладывать или вызывать параллельно.

### 8.8 `#401B DOS_SWP`

Принимает `A=0..6`, выбирает packed driver, распаковывает его по `#3800` и
вызывает SELDEV. Подробная нумерация находится в
[руководстве драйверов](03-drivers.md#9-dos_swp).

```asm
        LD      A,1                   ; первый SD-ZC
        CALL    #401B
        CALL    #4003
        JR      NZ,.no_device
        CALL    #4009
        JR      NZ,.no_fat32
```

Распаковка заменяет общее состояние по `#3848`, поэтому старый поток после
DOS_SWP недействителен.

### 8.9 `#401E GLSTCAT` и `#4021 TLSTCAT`

Несмотря на названия, направление такое:

```asm
        ; SET current catalog
        LD      HL,ClusterValue       ; HL указывает на 4 байта
        CALL    #401E

        ; GET current catalog
        LD      DE,ClusterCopy        ; DE указывает на 4 байта
        CALL    #4021
```

GLSTCAT копирует четыре байта в `LSTCAT` и сбрасывает iterator. TLSTCAT копирует
`LSTCAT` наружу. Cluster 0 означает root при последующем GIPAG.

### 8.10 `#4024 SRHFCL`

Ищет свободный data cluster, начиная с `FSTFRC`, с одним циклическим обходом
допустимого диапазона.

При монтировании диапазон `FSI_Nxt_Free` проверяется, затем единственным чтением
FAT подтверждается, что указанный кластер действительно свободен. Занятое,
неизвестное или недопустимое значение не запускает холодный поиск от кластера 2:
read-only RAM-курсор устанавливается в точку 15/16 области данных. Если там нет
свободного места, обычный обход доходит до конца и один раз возвращается к
кластеру 2, поэтому допустимый диапазон всё равно проверяется полностью.

```text
success: CF=0, Z, DE:HL = cluster
failure: CF=1, свободного кластера или корректного FAT-доступа нет
```

Это building block аллокатора, а не функция резервирования: найденная FAT
запись ещё не становится занятой сама по себе. Прикладному коду нужен MKFILE,
MKDIR, APPEND или FILEX.

### 8.11 `#4027 APPEND` и `#402D FILEX_GATE`

Это внутренние цели публичных API 76/77. Они ожидают уже подключённую panel
page. FILEX_GATE дополнительно подключает зарегистрированную страницу
провайдера в `#C000` и восстанавливает её. Не вызывайте provider runtime
`#C010` напрямую.

### 8.12 `#402A MKSG`

Создаёт FAT-цепочку под положительный размер `DE:HL`:

```asm
        LD      DE,0
        LD      HL,4096
        CALL    #402A
        JR      NZ,.allocation_failed
        ; первый cluster находится во внутреннем FCTS
```

Нулевой размер этому внутреннему входу запрещён. Он собирает список кластеров в
GENBU, связывает FAT и обновляет FSTFRC. Успех — `Z` и `CF=1` (конец
BUtoFAT). Если места не хватает, возвращает `NZ/A=16` и пытается освободить
уже собранную часть. Тот же код 16 — при отказе чтения FAT во время поиска
свободного кластера (после частичного выделения освобождение ещё и
сбрасывает `ABT`). MKDIR и APPEND зовут MKSG через MKSG_CHECKED расширения и
отдают в этом случае `#FF` (с 2026-09-26). MKFILE с 2026-09-27 зовёт MKSG
сам, вне шлюза расширения, а итог разбирает ALLOCATE_FILE тем же правилом:
внутри шлюза прерывания выключены, и выделение файла в гигабайт (~4900
тактов на кластер) шло при DI минуту и дольше. MKDIR, APPEND и рост
каталога (DIR_GROW) с того же дня ищут место тоже при прерываниях и странице
вызывающего — через резидентный блок `CORE_MKSG`/`CORE_SRHFCL` (раздел 2).
Каждая запись FAT по-прежнему проверяется коротким вызовом
шлюза (~2330 тактов); прерывания обслуживаются между ними. Обычно вызывайте MKFILE, который правильно обрабатывает size=0. После успешного выделения найденная
позиция остаётся в FSTFRC текущего сеанса; MKFILE не выполняет отдельную запись
FSInfo, поскольку этот дополнительный I/O зависал на реальной SD-ZC.

### 8.13 `#4030 RFRH`

Проверяет сигнатуры FSInfo и безопасно обновляет его. На успехе Z, при плохих
сигнатурах или I/O — NZ, причём плохой сектор не перезаписывается. Это
внутренняя часть commit, а не команда точного пересчёта всего свободного места.

### 8.14 `#4033 GENTRY` и `#4036 TENTRY`

```asm
        LD      HL,EntrySource
        CALL    #4033                ; 32 bytes: caller → internal ENTRY

        LD      DE,EntryDestination
        CALL    #4036                ; 32 bytes: internal ENTRY → caller
```

TENTRY дополнительно сохраняет APPEND context (SFN, directory sector/offset,
size/cluster). Поэтому это не просто memcpy. Оба используют LDIR и изменяют
регистры/обычные флаги пересылки; TENTRY отдельно восстанавливает заявленные
флаги менеджера вокруг копии. Времена в записи оба переносят как есть, без
проверки календаря (нормализует только API 58 и FILEX GET_METADATA).

### 8.15 `#4039 MKFILE`

Вход `HL` указывает на `[attr,size32,name,0]`. На успехе Z; для положительного
размера `DE:HL` возвращает/делает доступным первый cluster, ENTRY заполнена.
Нулевой файл создаётся без цепочки. Цепочку выделяет MKSG, с 2026-09-27 —
прямо из MKFILE, при прерываниях вызывающего (8.12); хвост MKFILE (SVHDFL)
стоит за MKDIR — вход MKDIR `#4D5B` закреплён. Внутренний вызывающий обязан сам передать
актуальную ENTRY/current directory context, что публичная обёртка API 72 делает
автоматически. Отказ носителя при записи в родителе (с 2026-09-25): запись
ищется заново (ID_ENTRY_LANDED, запрос — нормализованный NXTBU); легла с нашим
кластером — успех, нет — цепочка освобождается (`A=#FF`), неизвестно —
цепочка остаётся (`A=#FF`), см. 7.23.

### 8.16 `#403C MKDIR`

`HL` указывает на `name,0`. Выделяет cluster, пишет `.`/`..` и зануляет хвост
кластера, затем создаёт directory entry (тело — до публикации, с 2026-09-25;
сама процедура — MKDIR_ENTRY расширения, вход прежний). Z — успех, NZ/A —
ошибка (16 — нет места, 1–4 — имя, из них 2 — исчерпаны суффиксы ~N
короткого имени; #FF — отказ носителя при записи каталога и при записи FAT
во время выделения цепочки (MKSG): расширение отдаёт вместо сырого кода
драйвера #FF, F7 пишет «UNKNOWN ERROR!!»; прежде код 1 давал «Long Name is
not valid!»); при отказе записи FAT цепочка освобождается
(попытка: при отказе записи FAT могут остаться потерянные кластеры), кроме отказа
носителя, после которого не удалось выяснить, легла ли запись в родителе
(см. 7.23). После вызова iterator и часть секторных
буферов недействительны.

### 8.17 `#403F DELFL`

`HL` указывает на `[type,name,0]`. Находит SFN/LFN, освобождает цепочку и
помечает записи удалёнными. Не проверяет пустоту каталога. Исторический ABI не
даёт однозначного статуса для всех поздних ошибок записи, поэтому новый код не
должен использовать его как атомарную операцию.

### 8.18 `#4042 RENAME`

`HL` → `[type,old,0]`, `DE` → `new,0`. Работает внутри активного каталога.
Проверяет collision и создаёт новый набор LFN/SFN. Исторически NZ означает
успех, Z — источник не найден либо имя уже существует. С 2026-09-25 Z и при
отказе носителя: `A=0` или `#0F` — не переименовано, `#FF` — исход неясен;
`A=8` с `CF=1` — поиск источника не прочитал каталог (коды и оговорки — в
7.24).

### 8.19 `#4045 DLSG`

`HL` указывает на cluster32. Проходит FAT-цепочку и обнуляет каждую запись,
сбрасывает FSTFRC. У функции нет стабильного прикладного статуса; ошибки
SDDSE исторически могут быть видны только через ABT. Используется как часть
компенсации и удаления, не как публичная команда. Каждую ссылку проверяет
ID_CLASSIFY_DATA расширения: недопустимая (1, `#0FFFFFF0..#0FFFFFF7`), за
областью данных тома и, с 2026-09-27, кластер цепочки корня — остановка с
FAT_LINK_ERROR (`ABT=#FE`), освобождённое до неё записано. Таблицу кластеров
корня (до 768 — корень FAT32 при кластере от 4 КиБ целиком — с фильтром по
младшим 11 битам номера, чтобы не просматривать таблицу на каждый кластер) DLSG
строит в самом начале (ID_NOTE_FREED_CHAIN →
ROOT_BUILD): одно чтение сектора FAT на корень в один кластер; сектор FAT
корня не читается — DLSG не освобождает ничего. Прежде запись файла на
кластере корня (порча) F8 освобождала корень, на втором и следующих — хвост
корня с его именами.

### 8.20 `#4048 CHTOSE`

`HL` → cluster32, `DE` → массив LBA32, `BC` → адрес конца. Для каждого кластера
пишет `BSECPC` последовательных LBA, затем читает следующую FAT link. Буфер
должен вместить целый последний cluster. Отдельного count результата нет.

### 8.21 `#404B`: пустой слот

Пустой RET, сохранён для размера таблицы. Не является скрытой файловой
операцией.

### 8.22 `#404E SRHDRN`

Ищет имя/путь `HL → [type,name,0]` в текущем каталоге.

```text
Z   не найдено
NZ  найдено; internal ENTRY заполнена, DE:HL содержит first cluster/результат
```

Это нижний механизм FENTRY. Прямой вход не выполняет менеджерское сохранение
пути, кэша и APPEND context; для плагина нужен API 59.

### 8.23 `#4051 LOAD256` и `#4054 LOADNON`

Оба используют общий потоковый цикл с временным обработчиком:

- LOAD256: `DE=RDD256`, фактически читает 256-байтовые порции;
- LOADNON: `DE=Z0`, продвигает поток без копирования.

Вход `HL/B` и потоковые A/CF соответствуют историческим API 60/61. Эпилог
восстанавливает NW0 даже при ошибке.

### 8.24 `#4057 NXTETY` и `#405A NXTETY2`

Обе функции используют глобальный iterator и `#0000..#1FFF`.

- NXTETY принимает `DE` и выдаёт полную нормализованную запись переменной
  длины, которую использует панельный менеджер; у SFN файлов и каталогов
  конечное пробельное дополнение трёхбайтового расширения удаляется одинаково;
- NXTETY2 принимает дополнительно маску в обычном `A` и выдаёт документированный
  набор size/date/time/flag/name (bit6 маски — время и дата изменения вместо
  создания; штамп, которого нет в календаре, — 2026-01-01 00:00, см. 7.16).

NXTETY отдаёт время и дату изменения как на носителе: по ним панель WC
показывает строку информации и сортирует по дате, и замена на 2026-01-01
исказила бы и то и другое. Программе нужны API 58 или FILEX GET_METADATA.

`NZ` означает новую запись, `Z` — конец каталога либо отказ чтения (тогда
`ABT`≠0, см. 7.16). После GDIR/GLSTCAT iterator сброшен; после файлового I/O
его также следует сбросить явно.

Каталог читается в `#0000..#1FFF` по 8 КиБ, дальше — по 4 КиБ (NXMR). С
2026-07-16 до 2026-09-26 NXMR в конце цепочки отдавал `NZ` без новой записи:
полный каталог (записи до конца последнего кластера, нулевой нет) размером
8 КиБ, 12 КиБ и т. д. перечислялся без конца — панель набирала записи до
переполнения таблицы. Теперь там `Z`, как у нулевой записи.

Перед прямым вызовом рабочая panel page должна стоять в окне `#0000`. В
текущем менеджере это делает одноуровневая пара `CORE_PAGE_IN=#6B7A` и
`CORE_PAGE_OUT=#6B8B`. Она хранит только одну прежнюю страницу, поэтому
вложенный вход запрещён:

```asm
        CALL    #6B7A                ; current internal build only
        CALL    #4039                ; например, MKFILE
        PUSH    AF                   ; сохранить результат
        CALL    #6B8B
        POP     AF
```

Для нового внутреннего кода лучше вызывать именованные символы сборки, а не
фиксировать эти два адреса. Для плагина этот пример запрещён — используйте API
72.

## 9. API 76 APPEND

APPEND дописывает `0..#4000` байт в файл, последним успешно найденный API 59.

### 9.1 Обязательная последовательность

```text
FENTRY 59
   │
   ├─ Z ──► STOP: старый контекст всё ещё существует
   │
   └─ NZ
       ▼
APPEND 76 (HL=data, BC=length)
       │
       ├─ Z,A=0 ─► новый EOF опубликован
       └─ NZ,A=error ─► не повторять блок вслепую
```

`GFILE` перед APPEND не нужен. Успешный FENTRY сохраняет положение SFN и EOF.
Последовательные APPEND используют кэш последнего кластера и его базового LBA.

### 9.2 Буфер и результат

| Поле | Контракт |
|---|---|
| `HL` | Начало данных |
| `BC` | `0..#4000` байт |
| Диапазон | Весь `[HL,HL+BC)` внутри `#4000..#C000` |
| Успех | `Z`, `A=0`, HL сразу за данными при `BC>0` |
| Ошибка | `NZ`, код в A; фактическое число байт не возвращается |

`BC=0` всегда успешно и не проверяет контекст. Это не probe.

### 9.3 Внутренний commit

```text
проверить FENTRY context / вычислить EOF
        │
        ├─ при необходимости заранее выделить всю новую цепочку
        │
        ├─ записать данные (RMW неполных секторов)
        │
        ├─ связать старый хвост с новой цепочкой
        │
        ├─ обновить FSInfo
        │
        └─ последней записать SFN cluster + size32
```

Новая цепочка до commit остаётся отсоединённой. При последующей ошибке код
пытается вернуть прежний EOC, освободить новую цепочку и обновить FSInfo. Это
best-effort компенсация, а не журналируемая транзакция.

### 9.4 Коды APPEND

| Код | Значение |
|---:|---|
| `#20` | Нет действительного контекста FENTRY |
| `#21` | Неверный диапазон буфера |
| `#22` | Длина больше `#4000` |
| `#23` | SFN ENTRY изменилась после FENTRY |
| `#24` | Переполнение размера `#FFFFFFFF` |
| `#25` | Недопустимая/непрочитанная FAT-цепочка |
| `#26` | Объект является каталогом |
| `#27` | Внутренне противоречивый commit |
| `#2A` | Компенсирующий rollback сам завершился ошибкой |

Также наружу могут пройти `#10`, `#01` и другие ненулевые коды. Любой `NZ`
считается ошибкой. После неоднозначного сбоя заново выполните FENTRY и проверьте
реальный размер/содержимое перед решением о повторе.

## 10. API 77 FILEX

FILEX — версионируемый 32-байтовый интерфейс для позиционных операций. Его
провайдер `FILEX.WMF` должен быть первой активной строкой `[PLUGINS]`. Тип
`#06` при старте публикует свою страницу в резидентном шлюзе. Без провайдера
API возвращает `#15 NO_CONTEXT`.

### 10.1 Вызов

```asm
        LD      HL,FilexBlock
        LD      A,77
        CALL    #6006
        JR      Z,.ok                  ; только status #00
        ; A и block.status содержат один код.
```

Блок, имена, данные и выходные структуры должны целиком лежать в
`#8000..#BFFF`, не пересекать друг друга и не выходить за `#C000`. Максимум
одного READ_AT/WRITE_AT — `#4000` байт. AF/BC/DE/HL/IX разрушены, IY сохранён.

### 10.2 Блок версии 1

```text
offset  size  field
  0      1    size = 32
  1      1    version = 1
  2      1    operation 0..7
  3      1    flags
  4      4    offset / new EOF, LE32
  8      2    buffer
 10      2    length
 12      2    aux
 14      2    aux_length
 16      4    source_dir cluster
 20      4    dest_dir cluster
 24      4    result_count
 28      1    status
 29      1    result_flags
 30      2    reserved = 0
```

Перед каждым вызовом занулите все 32 байта. Это автоматически выполняет
требование к reserved и не оставляет result предыдущей операции.

### 10.3 Операции

| op | Имя | Нужно FENTRY | Поля | Результат |
|---:|---|---|---|---|
| 0 | `QUERY_CAPS` | Нет | flags=0 | `result_count.low=#FF`, `result_count+1` bit0 = GET_METADATA, result_flags=ABI 1 |
| 1 | `READ_AT` | Да | offset, buffer, length | result_count = реально прочитано |
| 2 | `WRITE_AT` | Да | offset, buffer, length | result_count = записано, файл при необходимости вырос |
| 3 | `SET_EOF32` | Да | offset = новый размер | result_count = итоговый EOF |
| 4 | `GET_FS_INFO` | Нет | buffer, length>=48 | Геометрия/FSInfo/label |
| 5 | `MOVE_RENAME` | Нет | два имени, два parent clusters, optional REPLACE | Перенос/переименование |
| 6 | `SET_METADATA` | Да | buffer, length>=16 | Атрибуты и FAT timestamps |
| 7 | `READ_FAT` | Нет | offset, buffer, length | Секторно выровненное окно используемой FAT |
| 8 | `GET_METADATA` | Да | buffer, length>=16 | Атрибут и FAT timestamps в структуре SET_METADATA (с 2026-09-26) |

#### READ_AT

- не прогоняет все предыдущие секторы через LOADNONE;
- вычисляет требуемый кластер/сектор напрямую;
- offset за EOF возвращает `EOF=#01`, `result_count=0`;
- частичное чтение до EOF возвращает `#01`, но result_count содержит префикс;
- нулевая длина возвращает OK.

#### WRITE_AT

- выполняет read-modify-write неполных секторов;
- если offset выше старого EOF, заполняет разрыв нулями;
- до первой изменяющей записи проверяет всё место для роста;
- новый размер публикуется после данных, FAT и FSInfo;
- перезаписанные байты внутри старого EOF при позднем I/O-сбое не откатываются.

#### SET_EOF32

```text
new EOF < old EOF   truncate + zero sector tail + detach/free chain tail
new EOF = old EOF   no-op
new EOF > old EOF   preflight space + allocate + zero extension + publish
new EOF = 0         empty file, first cluster 0
```

При truncate новая ENTRY публикуется до освобождения лишнего хвоста. Если
очистка после commit не завершилась, возвращается `#25 COMMITTED_CLEANUP`:
новый размер уже действителен.

#### MOVE_RENAME

Оба имени имеют формат `[type,name,0]` и переданную длину `3..257`. Parent
cluster `0` означает root. Для других каталогов вызывающий должен сохранить их
кластер из ENTRY/навигации.

`flags bit0=REPLACE` разрешает заменить существующее назначение. Типы должны
совпадать. Непустой каталог не заменяется; каталог нельзя перенести в своего
потомка. При смене родителя обновляется запись `..`. Отказ записи
перенаправленной SFN назначения (с 2026-09-26) откатывается: сектор
перечитывается, и если новая запись легла, прежняя запись назначения
возвращается; если не легла — возвращать нечего; статус `MEDIA`. Прежде
легшая с ответом «ошибка» запись оставляла на цепочке источника две записи,
а старая цепочка назначения терялась.

Имя источника или назначения с пробелом или точкой в конце, в том числе `.`
и `..` (с 2026-09-25), — `FILEX_STATUS_INVALID_NAME` до каких-либо изменений:
SVHDFL записывал его усечённым («NEW » → NEW), а поиск и откат MOVE шли по
исходному тексту и записи не находили — на объект оставались две ссылки даже
без сбоя носителя.

Откат (с 2026-09-25): признак «`..` изменён» ставится до записи сектора — при
отказе, после которого сектор всё же лёг, откат возвращает прежнего родителя
(вернуть неизменённый `..` безвредно). Ссылка назначения удаляется (или запись
назначения восстанавливается при REPLACE) только после того, как `..` вернулся;
не вернулся (или не удалось удалить саму ссылку назначения) — статус
`FILEX_STATUS_ROLLBACK`: откат не подтверждён. Обычно на объект остаются две
ссылки, но если удаление источника легло, а его сектор не перечитался, —
одна или ни одной; куда смотрит `..`, по статусу тоже не узнать. Прежде результат возврата `..` отбрасывался, и каталог
мог остаться в прежнем родителе с `..` на новый: подъём по `..` (рекурсивное
удаление) искал бы имя в чужом каталоге. Отказ самой записи ссылки назначения
тоже идёт через откат: ссылка могла лечь, и прежде на объект оставались обе
ссылки; до MOVE имени назначения не было, поэтому найденная по нему запись —
своя и удаляется.

Отказ удаления исходной ссылки тоже неоднозначен: запись могла лечь. Прежде
FILEX искал источник по имени и, не найдя, фиксировал перенос
(`COMMITTED_CLEANUP`). Но удаление пишет секторы LFN раньше сектора SFN: при
отказе последнего длинное имя уже стёрто, а короткая запись жива, и поиск её
не находит (как и при ошибке чтения) — на объект оставались две живые ссылки.
С 2026-09-25 сектор SFN источника перечитывается по месту, запомненному при
поиске (до трёх попыток): `#E5` — перенос зафиксирован (`COMMITTED_CLEANUP`);
запись жива или сектор не читается — `MEDIA` и откат. Если удаление всё же
легло, а перечитать не удалось, после отката ссылок на объект не остаётся
(потерянные кластеры) — так же, как у RENAME ядра: это лучше общей цепочки.

`flags bit1=CURRENT_DIR` означает, что оба имени находятся в уже активном
каталоге WildDOS. В этом режиме `source_dir` и `dest_dir` игнорируются.
Возможность объявляется битом `FILEX_CAP_MOVE_CURRENT_DIR`; старый провайдер
без этого бита продолжает принимать прежний явный cluster32 ABI.

#### SET_METADATA

16-байтовая структура:

| Offset | Поле |
|---:|---|
| 0 | size=16 |
| 1 | attr_mask |
| 2 | attr_value |
| 3 | time_mask: bit0 create, bit1 access, bit2 write |
| 4 | create_tenth |
| 5 | create_time LE16 |
| 7 | create_date LE16 |
| 9 | access_date LE16 |
| 11 | write_time LE16 |
| 13 | write_date LE16 |
| 15 | applied_attr, выход |

Разрешённые атрибуты mask `#27`: read-only, hidden, system, archive. С read-only
файла разрешено сначала снять сам read-only; остальные изменения до этого
возвращают `#18`.

С 2026-09-26 штамп программы, которого нет в календаре (месяц не 1..12, дня
нет в месяце, часы больше 23, минуты или секунды больше 59), на диск не
пишется: вместо него пишется текущий штамп часов ядра (сбитые часы —
2026-01-01 00:00), как у копии с неверной датой источника. Доли секунды
создания при этом — 0; их больше 199 — тоже 0. Дата до 1980 года в FAT не
кодируется: программе, у которой такая дата (например, у файла с ПК), стоит
передать дату 0 — WildDOS поставит текущую. Структура программы не меняется
(кроме applied_attr); что записано, покажет GET_METADATA.

#### GET_METADATA

Операция 8 (с 2026-09-26; есть, если в QUERY_CAPS `result_count+1` bit0 =
`FILEX_CAP2_GET_METADATA`) заполняет ту же 16-байтовую структуру по записи
последнего FENTRY и ничего не пишет: size=16, attr_mask=`#27`, attr_value и
applied_attr — атрибут записи, time_mask=%111, времена — поля записи.
Структуру можно без правки отдать в SET_METADATA. Штамп с носителя, которого
нет в календаре, отдаётся как 2026-01-01 00:00 (доли секунды создания тогда —
0, их больше 199 — тоже 0); запись на носителе не меняется. `result_count`=16,
`result_flags` — атрибут.

#### READ_FAT

Операция читает используемую копию FAT через тот же файловый контекст
WildCommander. При зеркалировании читается FAT0, а при отключённом
зеркалировании — копия, выбранная `BPB_ExtFlags`.

`offset` задаётся от начала FAT, а `length` и `offset` должны быть кратны
размеру сектора. Запрос не может выходить за границу FAT; фактически
прочитанное число байт возвращается в `result_count`.

### 10.4 GET_FS_INFO, 48 байт

| Offset | Размер | Поле |
|---:|---:|---|
| 0 | 1 | size=48 |
| 1 | 1 | version=1 |
| 2 | 1 | flags |
| 3 | 1 | sectors_per_cluster |
| 4 | 2 | bytes_per_sector=512 |
| 8 | 4 | total_clusters |
| 12 | 4 | free_clusters или `#FFFFFFFF` |
| 16 | 4 | serial |
| 20 | 12 | label 11 байт + ноль |
| 32 | 4 | total_sectors |
| 36 | 4 | next_free или `#FFFFFFFF` |
| 40 | 1 | FAT count |
| 41 | 1 | active FAT |
| 42 | 1 | BPB_ExtFlags low |
| 43 | 1 | media state |
| 44 | 4 | sectors per FAT |

Flags:

```text
bit0 MEDIA_PRESENT
bit1 WRITABLE
bit2 FREE_KNOWN
bit3 LABEL_VALID
bit4 WRITE_STATE_KNOWN
```

Если bit4 сброшен, состояние write-protect неизвестно; это не означает
«носитель доступен для записи».

## 11. Согласованность FAT32

CORE32 Improved придерживается следующих правил:

- при mirror mode изменения идут во все FAT;
- при `BPB_ExtFlags.bit7=1` используется только выбранная active FAT;
- старший зарезервированный полубайт FAT32 сохраняется при записи;
- обычный cluster, EOC `#0FFFFFF8..#0FFFFFFF` и reserved/bad диапазон
  `#0FFFFFF0..#0FFFFFF7` различаются;
- свободный cluster ищется только внутри реального data-cluster range;
- нулевой файл имеет size=0, cluster=0 и не получает цепочку;
- `FSI_Nxt_Free` принимается при монтировании только после проверки диапазона и
  нулевой записи FAT; иначе используется RAM-курсор 15/16 с полным циклическим
  обходом; MKFILE не записывает FSInfo автоматически, а найденный курсор
  остаётся в FSTFRC текущего сеанса;
- LFN удаляется только при правильной sequence/checksum, SFN — последней;
- при создании и переименовании SFN и LFN файлов/каталогов проверяются в общем
  пространстве имён без учёта регистра; кандидат SFN сравнивается и с LFN;
- суффиксы `~1`…`~999` сохраняют внутренние нули; исчерпание диапазона и ошибка
  чтения прекращают создание; ранее созданные имена не исправляются автоматически;
- с 2026-09-26 имя 8.3, которому длинное нужно только из-за заглавных букв
  (`boot.$C`, `ReadMe.txt`, `Файл.txt`), получает короткое без суффикса — само
  имя заглавными (cp866 тоже), если такого короткого в каталоге ещё нет
  (PLAIN_ALIAS расширения, вход LONG ядра; так делает и Windows). Имена длиннее
  8.3, с пробелом, лишней точкой или знаками `+,;=[]` получают `~n`, как прежде.
  Причина: ПЗУ ZX Evolution ищет `boot.$c` только по короткому `BOOT    $C`, а
  прежнее `BOOTx$~1` после замены файла из WC давало «boot.$c NOT FOUND!»;
- max LFN 255 байт может занимать три сектора каталога;
- полный каталог без маркера `#00` заканчивается по EOC, а не повторяет старый
  буфер.

## 12. Нереентерабельные глобальные объекты

```text
одновременно существует только один:

• NW0 stream handler
• directory iterator
• current ENTRY
• APPEND context/cache
• FILEX request/provider call
• SECBU/LOBU/LOBU2
```

Нельзя:

- вызывать файловый API из plugin INT-handler;
- начать вторую операцию до возврата первой;
- держать два параллельных APPEND-контекста;
- считать, что FENTRY одного файла не влияет на FILEX/APPEND другого;
- использовать флаги результата после вызова UI, который изменил `F`.

Для нескольких логических задач сериализуйте операции и перед каждой заново
выбирайте файл/поток.

## 13. Как расширять DOS API

Если функция помещается в существующий контракт, предпочтителен
версионируемый operation API 77:

```text
добавить op constant
   → расширить QUERY_CAPS
   → проверить block/version/flags/buffers
   → реализовать provider operation
   → определить стабильные status/result fields
   → сохранить старые op 0..6 без изменений
```

Не добавляйте ещё один случайный регистровый API для SEEK/TRUNCATE: FILEX уже
решает передачу offset32, длины, двух буферов и расширение версий.

Новый прямой элемент `#4000` потребует сдвига стабильной таблицы и всех
адресов — это худший вариант. Приватную тяжёлую реализацию можно разместить в
CORE32_EXT на странице Improved и вызвать через существующий шлюз, но её ID не
становится публичным для плагинов.
