**Обязательно обновить файлы:**

- `boot.$C`, `WC/FILEX.WMF` и `WC/PLM.WMF` — **вместе, из этого релиза**.
  `PLM.WMF` — новый: менеджер загрузки плагинов (о нём — первый раздел).
- `WC/SETUP.WMF` — новый: настройки WC.
- `WC/UNZIP.WMF`, `WC/FTVIEW.WMF`, `WC/VIDEO_PL.WMF`.

Свой `WC/wc.ini` сохраните, но в `[PLUGINS]` сразу за `FILEX.WMF` поставьте строки
`PLM.WMF` и `SETUP.WMF` — в этом порядке.

## Менеджер загрузки плагинов PLM

- **`PLM.WMF` (Plugin Loader Manager)** — новый плагин, который постоянно
  находится в памяти и загружает остальные плагины. Раньше WC при старте читал
  в память все плагины из `[PLUGINS]` и держал их там всё время. Теперь плагины
  лежат на диске, и PLM читает плагин в память, только когда его запускают.
  Сам PLM занимает одну страницу памяти (16 КиБ).
- Под плагины отведено 1008 КиБ памяти. После старта WC плагины занимают в ней
  две страницы вместо 55: свободно 976 КиБ.
- Запущенный плагин остаётся в памяти, и повторный запуск идёт без чтения с
  диска. Когда память кончается, из неё убирается плагин, который дольше всех не
  запускался.
- Раньше все плагины вместе должны были уместиться в 63 страницы памяти. Теперь
  такого предела нет: при старте WC только запоминает, какие плагины есть, а в
  память должен поместиться каждый плагин по отдельности. WC стартует быстрее:
  в эмуляторе — 1,9 с вместо 3,1 с.
- В меню F10 теперь только то, что запускается прямо из меню: заставки и
  плагины вроде ChkDsk, Create File, SETime, WC Setup — по алфавиту. Плагины,
  которые открывают файлы, в меню больше не показываются: просмотрщики,
  FT812 Viewer и TR-DOS Mounter запускаются клавишей Enter на нужном файле,
  TXT Editor — клавишей F4.
- Окно меню F10 всегда одной высоты: длинный список прокручивается стрелками,
  PgUp/PgDn, Home/End, справа — полоса прокрутки. Внизу окна видно, сколько
  памяти под плагины свободно. Клавиша DEL в меню больше не выгружает плагин из
  памяти.

## Настройки — плагин WC Setup

- Окно настроек по F9 убрано из ядра WC, клавиша F9 теперь свободна. Настройки
  открываются из меню F10, пункт «WC Setup» (`SETUP.WMF`).
- Первый экран — 12 настроек из секции `[SETUP]` файла `wc.ini`, включая
  настройки обеих панелей. Пробел или Enter меняет значение, F2 записывает
  `wc.ini`.
- WC Setup меняет в `wc.ini` только само значение: комментарии и порядок строк
  остаются как были. Если нужной настройки в файле нет, она дописывается в свою
  секцию.
- Tab — второй экран: список плагинов из каталога WC по группам: core —
  обязательные, auto — запускаются при старте, F10 — запускаются из меню,
  saver — заставки, file — открывают файлы. Внутри группы — по названию.
  - Пробел включает или выключает плагин. Выключенный остаётся в `wc.ini`
    строкой с «;» в начале, вместе со своими флагами.
  - Enter — правка флагов плагина, до 64 знаков; более длинные флаги правятся в
    самом `wc.ini`.
  - Включить можно только одну заставку. FILEX и PLM выключить нельзя.
- Пока изменения не записаны, заголовок окна красный и со звёздочкой. Если
  нажать Esc, WC Setup спросит «Save changed settings?»: YES — записать и выйти,
  NO — выйти без записи.
- `wc.ini` сохраняется надёжно: сначала пишется новый файл, и только потом он
  заменяет старый. Если запись не удалась, остаётся прежний `wc.ini`.
  Сообщения: «wc.ini saved» — записано, «wc.ini was NOT saved» — не записано,
  «wc.ini: check the disk» — проверьте диск. Если `wc.ini` не удалось
  прочитать — «wc.ini could not be read», и F2 ничего не записывает.
- Размер `wc.ini` — до 2559 байт.
- Если `wc.ini` нет, WC при старте пишет «No settings: press F10 and run WC
  Setup.» и загружает только FILEX, PLM и SETUP. WC Setup по F2 создаёт новый
  `wc.ini`.
- После выхода из WC Setup панели перечитываются.

## Время файлов

- Новые файлы и каталоги получают дату и время из часов Evo — и созданные по F5
  и F7, и созданные плагинами и редактором. Если часы сбиты (невозможная дата
  или время) или показывают год раньше 2026, ставится 2026-01-01 00:00.
- Копия по F5 получает дату и время оригинала — и у файлов, и у каталогов со
  всем содержимым. Если дата у оригинала испорчена, копия получает текущую.
- Переименование по F6 время не меняет. Когда программа дописывает или меняет
  файл, у него обновляется время изменения.
- Панель показывает и сортирует файлы по времени последнего изменения (раньше —
  по времени создания).
- **Ctrl+F5** — сортировка по дате, новые сверху; повторное нажатие выключает
  сортировку. То же можно выбрать в WC Setup («by date») или в `wc.ini`
  (`CSORT=4`).
- Под панелью — строка информации о файле под курсором: имя, размер (с
  пробелами между тысячами) или `<DIR>`, дата и время изменения. В 80 колонках
  дата — ДД.ММ.ГГ, в 90 — ДД.ММ.ГГГГ. Строка включена по умолчанию.

## Окно копирования и удаления (F5, F8)

- Копирование и удаление идут в одном окне на всю операцию. Раньше после Enter
  оставался диалог с кнопками [OK]/[CANCEL], а поверх него на каждый файл
  открывалось и закрывалось отдельное окно с полосой.
- Окно всегда по центру экрана, в любом текстовом режиме. В нём: заголовок
  «COPY» или «DELETE», пустая строка, сначала «Copying started...»
  («Deleting started...»), затем имя текущего файла, строка «<n of M>», пустая
  строка и полоса.
- «<n of M>» — номер текущего файла и сколько всего файлов в операции, считая
  файлы во вложенных каталогах. Чтобы их сосчитать, WC перед началом
  просматривает выбранные каталоги. Больше 9999 показывается как 9999; если
  каталог не удалось прочитать — «of ????».
- Полоса одна на всю операцию и только растёт.

## Копирование, переименование, создание каталога

- F5 каталога в самого себя или в свой подкаталог — отказ «Can't copy DIR into
  itself!», на диске ничего не меняется.
- Слишком глубокое дерево каталогов в F5 и F8 — отказ «DIR name too long/END of
  buffer».
- F6 сохраняет атрибуты файла: только чтение, скрытый, системный, архивный.
- F7 сообщает настоящую причину отказа: «Not Enough Space!» — нет места,
  «Name already exists!» — имя занято, «Long Name is not valid!» — недопустимое
  имя, «UNKNOWN ERROR!!» — ошибка диска.
- Короткие имена — как в Windows: если имя укладывается в 8.3 и отличается
  только большими и маленькими буквами (`boot.$C`, `ReadMe.txt`, `Файл.txt`),
  его короткое имя — то же имя большими буквами, без «~1». Поэтому `boot.$C`,
  скопированный через WC, загрузчик Evo находит.
- Защита от испорченной файловой системы. Перед входом в каталог и перед
  копированием файла WC проверяет его служебные записи и цепочку кластеров; если
  что-то не так, F5 и F8 останавливаются с «UNKNOWN ERROR!!» и чужие файлы не
  трогают. F8 никогда не освобождает кластеры корневого каталога и перед
  удалением проверяет, не занимают ли отмеченные объекты кластеры других файлов
  того же каталога. Каталог не может вырасти больше 4096 секторов — предел FAT32
  в 65536 записей.
- Во время долгого поиска свободного места на диске часы и клавиатура больше не
  замирают.

## Исправленные ошибки

**Порча данных**

- F8 записи каталога с испорченным номером кластера (0) удалял все файлы
  корневого каталога.
- Если файл на испорченном диске указывал на кластер корневого каталога, F8
  этого файла стирал корневой каталог — пропадали все имена.
- Если две записи указывали на одни и те же кластеры, F8 одной из них уничтожал
  данные другой. Теперь это отказ, если обе записи в одном каталоге.
- F5 каталога в самого себя копировал бесконечно, пока не кончится место.
- Ошибка чтения каталога при создании файла отрезала конец каталога вместе с
  чужими файлами.
- Новый кластер каталога подключался до очистки: в каталоге появлялись старые
  записи-«призраки», и F8 такого «призрака» уничтожал данные живого файла.
- Испорченная цепочка кластеров файла: F5 копировал вместо данных содержимое
  корневого каталога или старые данные из памяти, а копия могла получить тот же
  кластер, что и оригинал.
- Испорченная ссылка на кластер за концом раздела приводила к чтению и записи
  за его границей.
- После подключения диска большего размера на меньшем диске мог выделиться
  кластер за концом раздела.
- Если вторая панель стояла в удалённом каталоге, новые файлы в ней
  записывались бы в освободившееся место на диске.
- Короткое имя 8.3 у имён вроде `README.md` получало недопустимый байт или мусор,
  у коротких имён — остатки чужого имени.
- `boot.$C`, скопированный через WC, получал короткое имя `BOOTx$~1$C`, и
  загрузчик Evo писал «boot.$c NOT FOUND!».
- Длинное имя из испорченного каталога записывалось в память за границу поля
  имени.
- F6 сбрасывал атрибуты файла.
- FILEX MOVE (перенос через API) в имя с пробелом или точкой в конце оставлял
  каталог с двумя записями.

**Зависания и молчаливые отказы**

- Каталог, ссылающийся сам на себя, и зацикленные цепочки кластеров вешали F8,
  показ панели, поиск и создание файла.
- Полностью заполненный каталог ровно 8 КиБ (12 КиБ и т. д.) читался
  бесконечно — панель показывала 4095 записей мусора.
- Очень глубокое или зацикленное дерево каталогов переполняло служебную память
  F5 и F8.
- Ошибка чтения каталога внутри дерева принималась за его конец: F8 удалял
  подкаталог вместе с непросмотренными файлами (их место на диске терялось),
  F5 молча делал неполную копию.
- F8 дерева с подкаталогами обрывался на «DIR not found (src)» и оставлял часть
  дерева.
- F8 не проверял, удалился ли каталог; при ошибках удаления или поиска
  останавливался молча.
- F5 каталога с испорченным первым кластером молча создавал пустую копию.
- F5 не проверял ошибки чтения и записи: копия получала старые данные из
  памяти, а WC сообщал, что всё в порядке.
- WC бесконечно ждал отпускания клавиш, если сигнал отпускания терялся; теперь
  ждёт не больше ~1,5 с.
- Выделение места под большой файл и поиск свободного места при F7, дописывании
  в файл и росте каталога шли с выключенными прерываниями — до ~3 минут WC не
  отвечал.

**Ошибки диска** (действуют только с драйвером, который сообщает об ошибках;
штатные драйверы в `boot.$C` не сообщают)

- Переименование при ошибке удаления старой записи оставляло две записи на
  одних и тех же данных.
- Создание каталога записывало его в родительский каталог раньше, чем его
  содержимое; создание файла при неясном исходе записи освобождало место под
  живым файлом.
- Запись цепочки кластеров не проверяла ошибку чтения FAT; удаление файла
  скрывало ошибку освобождения места.
- Дописывание в файл при ошибке оставляло файл с новым размером на
  освобождённом месте.
- Откаты операций FILEX (перенос, замена, усечение) оставляли две записи на
  одних данных или неверный размер.
- UNZIP при ошибке удаления старого файла терял и старую, и новую версию.

**Сообщения**

- F7 на любую ошибку писал «DIR with same name already exists!».
- Ошибка диска выдавалась за «Long Name is not valid!», «Not Enough Space!»,
  «File not found» или «DIR not found» — теперь «UNKNOWN ERROR!!».
- Сортировка по размеру ставила файл в 256 байт раньше файла в 100 байт.
- Счётчик «<i of N>» при 10000 и больше показывал мусор.
- Полоса хода становилась полной ещё до того, как последняя порция данных
  записывалась с ошибкой.

## Запуск

- При старте, до первого чтения карты, WC приводит в покой шину SPI, через
  которую работают SD-карта и FT812: `#77=#03`, 16 байт `#FF` в порт `#57`,
  снова `#77=#03`. Это на случай, если Reset нажали посреди обмена с картой
  или FT812.
- Если загрузчик прочитал `boot.$C` не целиком, WC не запускается: красный
  бордюр и остановка.

## Плагины

- **FILEX** (файловые функции для плагинов): время изменения при записи и
  усечении файла; новая операция 8 GET_METADATA — атрибут и время файла;
  SET_METADATA вместо испорченной даты пишет текущую; перенос (MOVE_RENAME)
  отклоняет имена с пробелом или точкой в конце. Ставится только вместе с новым
  `boot.$C`.
- **UNZIP:** если при замене файла что-то пошло не так, распакованный файл не
  теряется — он получает своё имя или остаётся под временным именем
  `WCUZ0nn0.$$$`.
- **FTVIEW (FT812 Viewer):** больше не пункт меню F10 — открывается по Enter на
  файле; окно About убрано.
- **VIDEO_PL (Video Player v0.77):**
  - с платой VDAC2 ролик идёт на экран FT812: кадр увеличивается в 4 раза со
    сглаживанием и стоит по центру экрана 1024×768; темп кадров — как на
    TS-Conf, звук вровень с картинкой;
  - если FT812 не отвечает — «FT812 is not responding.», и ролик идёт на экран
    TS-Conf; без VDAC2 — как раньше;
  - звук MP3 играет NeoGS: если её нет — «NeoGS not found. No sound.», если
    MP3 не помещается в её память — «MP3 too large. No sound.»; ролик в обоих
    случаях идёт без звука;
  - звук начинается вместе с первым кадром.

## Для авторов плагинов

- Флаг +33 бит 0 в заголовке типа #06 — ранний вызов с A=#07.
- Бит 6 маски API 58 — время изменения вместо времени создания. API 58 и FILEX
  GET_METADATA отдают штамп вне календаря как 2026-01-01 00:00; запись на
  носителе не меняется.
- Конец перечисления API 58 из-за сбоя чтения отличается по ABT.

## Ограничения

- WC не обновляет счётчик свободного места в служебном секторе FAT32 (FSInfo):
  другие системы могут показать неверный объём свободного места.
- Защита F8 от общих кластеров работает только внутри одного каталога. Общие
  кластеры с файлами других каталогов, общий конец двух цепочек и очень большой
  корневой каталог (больше 768 кластеров при кластере 1–4 сектора) находит
  только проверка диска CHKDSK.
- С карты с кластером 64 КиБ `boot.$C` не загрузится.
- Если в операции больше 65535 файлов, счётчик останавливается на 65535, а
  полоса стоит полной.
- Проверки замедлили F5 и F8: в эмуляторе копирование 254 мелких файлов —
  142 с вместо 117, удаление — 50 с вместо 40. Перед копированием файла в 1 ГиБ
  (кластер 4 КиБ) проверка занимает около 25 с при 14 МГц.
- Копия по F5 не сохраняет атрибуты. F5 не перезаписывает существующий файл
  («Name already exists!»). Переименование, меняющее только большие и маленькие
  буквы, не выполняется. Когда диск полон, отказ приходит не сразу — на диске
  48 МБ около минуты.
- Файл, чьё короткое имя начинается с русской «х», WC по этому имени не находит
  и показывает с другим символом.
- Шина SPI приводится в покой только при старте WC, а не после выхода из
  плагинов и запуска SPG, TAP, SNA.
- Новая сборка не проверялась на настоящем ZX Evolution; запуск из TR-DOS и
  Mounter не проверялся.
