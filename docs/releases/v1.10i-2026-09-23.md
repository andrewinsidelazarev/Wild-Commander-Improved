## Файловое ядро

- **Кэш сектора FAT.** Потоковое чтение и запись файла (`LOAD512`, `SAVE512`,
  `LOADNON`, `LOAD256`) читали сектор FAT заново на каждом кластере. Теперь он
  читается один раз на 128 кластеров, а переход к следующему кластеру берётся
  из кэша — без обращения к карте. Кэш сбрасывают запись FAT, монтирование
  тома, смена и инициализация драйвера, начало чтения каталога и любое чтение
  FAT ядром, поэтому изменения на диске мимо него не проходят.
- **Что это даёт.** Длинные файлы проходятся заметно быстрее: в Unreal первая
  перемотка AVI на 52 МБ (кластер 4 КиБ) занимает 10,9 с вместо 29,9 с, а при
  воспроизведении сектор FAT читается около 0,5 раза в секунду вместо
  примерно 66. Выигрыш тем больше, чем длиннее файл и чем мельче кластер;
  на коротких файлах разницы нет.
- **API 61 `LOADNON` и API 60 `LOAD256`** (найдено при работе над плеером)
  проходили за вызов около 81 блока вместо заданного в `B`: `VIDEO_PL`
  пропускал 40,5 КиБ вместо одного сектора, `LOAD256` переполнял буфер.
  Ошибка была во всех релизах v1.10i с 16 августа.

## Видеоплеер FTView (FT812 Viewer v1.21)

В релизе 2026-09-19 FTView играл AVI только штатным `CMD_PLAYVIDEO` чипа — на весь экран, без управления. Теперь это видеоплеер.

- **Покадровое MJPEG AVI.** Кадр растягивается на весь экран 1024×768 с билинейным сглаживанием FT812: 4:3 (512×384) — ровно вдвое, 16:9 (512×288) — 1024×576 по центру. Следующий кадр декодируется заранее и показывается точно в срок.
- **Панель управления** поверх кадра на полупрозрачной полосе: полоса прогресса, текущее и общее время, подсказки клавиш, куда идёт звук. Видна 15 с после любой клавиши, на паузе и в конце ролика — всегда.
- **Звук на General Sound или FT812.** PCM 8 бит (araw) моно играет General Sound/NeoGS: плагин загружает в карту собственный драйвер через её ПЗУ, поток идёт конвейером по двум регистрам (5,4 мкс на байт на GS 12 МГц), частоты — до 37,5 кГц. Без GS звук идёт на звуковой блок FT812. Кадры идут по звуку, пауза держит позицию, перемотка начинает звук с целевого кадра. При выходе GS возвращается в ПЗУ. AVI с другим звуком (µ-law, ADPCM, 16 бит, стерео) играет штатный `CMD_PLAYVIDEO`.
- **Управление:** Space — пауза и продолжение (в конце ролика — просмотр сначала), Left/Right — ±10 с, Home — начало, PgUp/PgDn — соседний файл, Enter — список роликов, Esc — выход, любая клавиша — показать панель.
- **Любой MJPEG AVI** — без звука или со звуком PCM 8 бит (araw) — играет покадрово, с панелью и перемоткой. Но если файл сделан не FTViewConvert, таблицы перемотки в нём нет, и плеер строит её по индексу `idx1` при первой перемотке — на длинном ролике это долго (в Unreal на 52-мегабайтном ролике 6,7 с против 1,1 с с готовой таблицей). Следующие перемотки быстрые — 0,4 с. Позицию на SD плагин ставит сам, это работает и со старым ядром.
- **Список роликов (Enter):** MJPEG AVI из каталога ролика по алфавиту (латиница, затем кириллица), длинные имена, кириллица транслитом, подчёркивания — пробелами, без «.avi», длинное имя обрезается по ширине окна с «...». Курсор на текущем; Enter запускает выбранный (текущий — с начала), Esc — назад к ролику. Когда ролик доиграл, список открывается сам.
- **Сообщения:** AVI с видео не MJPEG (XVID, H.264…) сообщает «Unsupported video codec», а не показывает мусор; окна плагина закрываются любой клавишей; в «Cannot display file» видны номер сборки и причина отказа (Reason NN); About — «FT812 Viewer v1.21, (C)2026 INSiDE».
- **Поток с SD:** буфер EVO на 8 страниц (≈124 КБ) плюс 128 КБ media FIFO FT812, передача через DMA, на время видео — 14 МГц.
- Плагин — три банка кода, занимает 11 страниц пула плагинов вместо 10.

## FTViewConvert — перекодировщик видео для FTView (Windows x64)

Отдельный релиз: [FTViewConvert — 2026-09-23](https://github.com/andrewinsidelazarev/Wild-Commander-Improved/releases/tag/ftviewconvert-2026-09-23) (архив `FTViewConvert.zip`: программа, описание, лицензия ffmpeg, исходники). Установка не нужна: внутри — [FFmpeg](https://ffmpeg.org/), который делает всё перекодирование, — спасибо его разработчикам (сборка [gyan.dev](https://www.gyan.dev/ffmpeg/builds/), лицензия GNU GPL v3, [исходный код](https://ffmpeg.org/download.html)).

- **Таблица перемотки записывается в сам файл.** Первая перемотка в FTView идёт сразу, без долгого построения индекса: в Unreal на 52-мегабайтном ролике 1,1 с вместо 6,7 с.
- Любое видео → MJPEG AVI 24 кадра/с, около 2 Мбит/с — столько успевает читаться с SD на Evo; своя матрица квантования — меньше блочности при том же потоке.
- Разрешение по пропорциям исходника с учётом SAR и поворота видео с телефона, не больше 512×384 по площади и не больше самого исходника: 16:9 — 512×288, 4:3 — 512×384. Галочка **Crop 4:3** обрезает бока широкого кадра до 512×384 на весь экран.
- Звук PCM 8 бит моно 22 050 или 32 000 Гц; громкость нормализуется до 0 дБ, тихие записи — ещё до +2 дБ через мягкий лимитер.
- Проверка прав записи до запуска с объяснением причины отказа, выбор папки результата, перетаскивание файла в окно, пакетный режим, сообщение «Video converted» по окончании.

## TXTVIEW2

- После FTView и других программ для FT812 строки состояния и подсказок выходили мусором: сброс чипа не очищает таблицу дескрипторов bitmap. Теперь просмотрщик сам приводит свои дескрипторы в порядок.
