# Wild Commander Improved: карта использования памяти

Этот документ отвечает на главный практический вопрос автора плагина или
драйвера: **какую память можно использовать, кто уже владеет каждым диапазоном
и что изменится во время вызова API**.

> Самое важное правило: адрес Z80 и номер физической страницы — разные вещи.
> Адрес `#8000` не называет конкретную RAM. Он означает окно, в которое в
> данный момент подключена одна из физических страниц по 16 КиБ.

## 1. Карта за тридцать секунд

```text
Логическое адресное пространство Z80                  Обычное состояние WC

 #FFFF +-------------------------------------------+
       | окно #C000: постоянно переключается       |  плагин / экран /
       | API 0, драйверы, файловые буферы, FILEX    |  временная страница
 #C000 +-------------------------------------------+
       | окно #8000: верх WC или страница плагина  |  обычно phys #02,
       | код плагина запускается через CALL #8000   |  при запуске — plugin
 #8000 +-------------------------------------------+
       | окно #4000: резидентное ядро и менеджер    |  phys #05
       | CORE32, стек/IM2, API #6006, код WC        |
 #4000 +-------------------------------------------+
       | окно #0000: состояние текущего WildDOS     |  обычно phys #F0/#F1,
       | каталог, секторные буферы, драйвер #3800   |  иногда plugin state
 #0000 +-------------------------------------------+
```

Для обычного плагина безопасная стратегия выглядит так:

```text
код и постоянные данные       -> страницы, заявленные в заголовке .WMF
рабочий буфер                 -> свободная область своей страницы #8000..#BFFF
ещё один буфер на 16 КиБ      -> дополнительная относительная страница плагина
файловые операции             -> только публичный CALL #6006
прямой OUT в порты страниц    -> не использовать
```

## 2. Термины: окно, страница и смещение

TS-Conf делит видимые Z80 64 КиБ на четыре окна по 16 КиБ. Физическая страница
также имеет размер 16 КиБ, поэтому любое её смещение равно младшим 14 битам
логического адреса.

| Окно | Диапазон адресов | Порт страницы | Тень WC |
|---:|---:|---:|---:|
| 0 | `#0000..#3FFF` | `#10AF` | `#6000` |
| 1 | `#4000..#7FFF` | `#11AF` | `#6001` |
| 2 | `#8000..#BFFF` | `#12AF` | `#6002` |
| 3 | `#C000..#FFFF` | `#13AF` | `#6003` |

Пример: физическая страница `#75`, подключённая к окну `#8000`, видна как
`#8000..#BFFF`. Байт по физическому смещению `#0123` читается по адресу
`#8123`.

```text
physical page #75                         logical window #8000

 offset #0000 -------------------------> address #8000
 offset #0123 -------------------------> address #8123
 offset #3FFF -------------------------> address #BFFF
```

Тени `#6000..#6003` — часть контракта менеджера. Если выполнить сырой
`OUT (#12AF),A`, аппаратура переключится, но WC продолжит считать, что в окне
остаётся старое значение из `#6002`. Следующее восстановление страницы станет
непредсказуемым. Плагин должен применять API 0, 65, 78–81 или межстраничный
вызов `#6028`.

## 3. Обычная раскладка окон

После инициализации основные резидентные части выглядят так:

| Окно | Типичная физическая страница | Владелец | Можно ли плагину писать |
|---:|---:|---|---|
| `#0000` | `#F0` или `#F1` | Состояние WildDOS левой/правой панели | Нет |
| `#4000` | `#05` | CORE32, стек, IM2, основной код WC | Нет |
| `#8000` | `#02` | Верхняя часть WC; при запуске заменяется страницей плагина | Только в своей подключённой странице |
| `#C000` | меняется | Плагины, экран, загрузчик, буфер или расширение | Только после осознанного подключения своей страницы |

Физические `#05` и `#02` вместе содержат непрерывный логический образ
Commander `#4000..#BFFF`. Поэтому переход границы `#7FFF/#8000` в исходнике WC
не означает переход к другому модулю API — это лишь граница двух окон MMU.

### 3.1 Что видит запущенный плагин

Загрузчик берёт относительную страницу из поля заголовка `.WMF +35`, подключает
её к `#8000` и выполняет `CALL #8000`.

```text
до запуска                          во время CALL #8000

#8000 -> phys #02 (сам WC)          #8000 -> phys (#61 + base + entry_page)
#C000 -> временная страница         #C000 -> задаётся плагином через API 0
```

Плагин не должен вычислять `#61 + base` самостоятельно. Относительный номер
`0..pages-1` передаётся API, а текущая база хранится менеджером.

### 3.2 Что происходит во время файлового вызова

Обёртки API 48–63 и 72–77 временно подключают рабочую страницу файлового
контекста к окну `#0000`. Предыдущая страница сохраняется в `#600C`, файловая
берётся из `#600B`, после вызова прежняя раскладка восстанавливается.

```text
плагин                диспетчер #6006                 WildDOS

CALL #6006  ------->  save page0 in #600C  ------->  code #4000..
                      map #600B at #0000               data #0000..
                      call #40xx                       driver #3800
RET         <-------  restore page0       <-------   flags/result
```

Это одна из причин не вызывать `#40xx` из обычного плагина напрямую: одна и та
же процедура кода CORE32 получит совершенно другие данные, если в `#0000`
подключена не та страница.

### 3.3 Что происходит в API 77 FILEX

FILEX специально разводит участников по трём окнам:

```text
#0000..#3FFF  текущий контекст WildDOS: каталог, FAT, драйвер
#4000..#7FFF  резидентный CORE32 и шлюз #402D
#8000..#BFFF  блок запроса FILEX и пользовательские буферы
#C000..#FFFF  код провайдера FILEX из его физической страницы
```

Поэтому блок запроса и все передаваемые FILEX буферы обязаны целиком лежать в
`#8000..#BFFF`. Адрес `#C000` для них недопустим: во время операции там уже
исполняется провайдер.

## 4. Детальная карта логических 64 КиБ

### 4.1 Окно `#0000..#3FFF`: изменяемое состояние WildDOS

CORE32 разделяет код и данные. Код постоянно находится по `#4000`, а данные
берутся из текущей физической страницы окна `#0000`.

| Диапазон | Назначение в странице WildDOS |
|---:|---|
| `#0000..#0FFF` | Нижняя половина буфера перечисления каталога |
| `#1000..#1FFF` | Верхняя половина буфера перечисления каталога |
| `#2000..#2FFF` | Не считать свободной: часть рабочего состояния/буферов вызывающего кода |
| `#3000..#31FF` | Один сектор FAT (`SECBU`) |
| `#3200..#33FF` | Секторный буфер `LOBU` |
| `#3400..#35FF` | Второй секторный буфер `LOBU2` |
| `#3600..#37F7` | Внутренняя рабочая область |
| `#37F8..#37FF` | Состояние итератора каталога `CGDE/CGHL/CGPZ/CGFL` |
| `#3800..#3847` | 24 трёхбайтовых входа текущего драйвера |
| `#3848..#3867` | Общие переменные драйвера и потока |
| `#3868..#3887` | Текущая 32-байтовая FAT directory entry |
| `#3888..#38CC+` | Геометрия FAT32, кластеры, позиции и состояние операций |
| остаток до `#3FFF` | Не является публичным буфером |

Две основные страницы состояния:

| Физическая страница | Назначение |
|---:|---|
| `#F0` | Контекст WildDOS левой панели |
| `#F1` | Контекст WildDOS правой панели |

API может временно использовать и страницу плагина как файловый контекст.
Признаком выбранного контекста служит `#600B`; полагаться только на `#F0/#F1`
внутри плагина нельзя.

> API `GEDPL` использует `#1000..#1447` текущей страницы окна `#0000`.
> Содержимое этого диапазона после переключения в основной текстовый режим
> сохранять нельзя.

### 4.2 Окно `#4000..#7FFF`: ядро и нижняя часть WC

```text
#4000 +----------------------------------------------------+
      | CORE32: таблица #4000 и весь код WildDOS           |
#5BF2 +----------------------------------------------------+
      | критическая область стека и IM2; не использовать   |
#6000 +----------------------------------------------------+
      | фиксированные тени страниц и публичный API         |
#6011 +----------------------------------------------------+
      | MD20: запуск, панели, диспетчер API                 |
#7143 +----------------------------------------------------+
      | PS2P: клавиатура и строковый ввод                   |
#7828 +----------------------------------------------------+
      | WCIF: окна, текст, интерфейс                        |
#7EA0 +----------------------------------------------------+
      | WCVLS: панели и общие структуры (продолжение выше)  |
#8000 +----------------------------------------------------+
```

Точные важные границы:

| Диапазон/адрес | Назначение |
|---:|---|
| `#4000..#5BF1` | Рабочий образ CORE32 |
| `#4000..#405C` | 31 строка внутренней JP-таблицы CORE32 |
| `#5AAA` | Распаковщик драйверов DEHR |
| `#5BF2` | Первый адрес после CORE32 |
| `#5BFF..#5C02` | Четыре байта таблицы IM2 |
| `SP=#5FFE` | Начальный стек WC; стек растёт к меньшим адресам |
| `#6000..#6010` | Фиксированное состояние менеджера и API |
| `#6006` | Публичный диспетчер API плагинов |
| `#6011..#7142` | MD20 |
| `#7143..#7827` | PS2P |
| `#7828..#7E9F` | WCIF |
| `#7EA0..#7FFF` | Начало WCVLS |

Диапазон `#5BF2..#6010` нельзя использовать как «дыру». Здесь находятся
рабочий стек, IM2 и фиксированные переменные непосредственно перед кодом WC.

### 4.3 Фиксированные ячейки `#6000..#6010`

| Адрес | Размер | Назначение |
|---:|---:|---|
| `#6000` | 1 | Тень страницы окна `#0000` |
| `#6001` | 1 | Тень страницы окна `#4000` |
| `#6002` | 1 | Тень страницы окна `#8000` |
| `#6003` | 1 | Тень страницы окна `#C000` |
| `#6004` | 1 | Флаг Esc плагинного менеджера |
| `#6005` | 1 | Флаг Enter |
| `#6006..#6008` | 3 | `JP` в публичный диспетчер API |
| `#6009..#600A` | 2 | Кадровый таймер |
| `#600B` | 1 | Активная рабочая страница файлового контекста |
| `#600C` | 1 | Временно сохранённая страница окна `#0000` |
| `#600D` | 1 | Конфигурация/тип видео |
| `#600E` | 1 | Высота текста: 25, 30 или 36 строк |
| `#600F` | 1 | Режим текстового экрана |
| `#6010` | 1 | Флаг обработки `wc.ini` |

Читать документированные значения можно. Записывать в них напрямую нельзя,
если конкретный API явно не требует обратного: эти ячейки одновременно
используются менеджером, обработчиком прерываний и файловыми обёртками.

### 4.4 Окно `#8000..#BFFF`: верх WC или рабочая страница плагина

В штатном состоянии здесь подключена физическая страница `#02` и продолжается
резидентный образ:

| Диапазон | Модуль/ресурс |
|---:|---|
| `#8000..#8530` | Продолжение WCVLS, начиная со структуры `F5WND=#8000` |
| `#8531..#9148` | WCFX: файловые команды менеджера |
| `#9149..#9B7B` | WCVW: просмотрщики и загрузчик плагинов |
| `#9B7C..#AB9E` | WCINI: конфигурация и пути |
| `#AB9F..#B39E` | Шрифт |
| `#B39F..#B4B5` | Ресурс DEHR1M |
| `#B4B6..#B59E` | Ресурс MLZ50F |
| `#B59F..#BFFF` | Установщик Improved, AUTOEXEC и упакованное расширение |

При запуске `.WMF` всё окно заменяется выбранной страницей плагина. Поэтому
плагин может хранить здесь код, структуры SOW и данные, но только в границах
собственной 16-КиБ страницы.

Полезные общие структуры WC в резидентной странице `#02`:

| Адрес | Назначение |
|---:|---|
| `#7EA0` | 36-байтовая левая панель `WINDOW` |
| `#7EC4` | 36-байтовая правая панель `WINDO2` |
| `#7F14..#7F1B` | Состояние загрузчика плагинов, база и указатели заголовков |
| `#7F28..#7F3B` | Кластеры/размеры текущей файловой операции |
| `#7F4C..#7F4E` | Флаги вызовов из IM2 |
| `#7F6B..#7F8A` | Текущая 32-байтовая directory entry менеджера |
| `#7FB7` | Окно ошибки `ERWND` |
| `#7FE2` | Окно прогресса `PBWND` |
| `#7FF4` | Диалог имени `MDWND` |
| `#8000` | Диалог копирования `F5WND` |

Это внутренняя карта WC, а не свободный ABI-буфер. Плагин получает нужные
значения через регистры запуска и публичные вызовы.

### 4.5 Окно `#C000..#FFFF`: общий переключаемый ресурс

В этом окне по очереди появляются:

- относительные страницы плагина через API 0;
- физические видеостраницы через API 65;
- временные секторные и загрузочные страницы WC;
- заголовки `.WMF` на физической странице `#60`;
- страница провайдера FILEX;
- исходный физический образ CORE32 только во время установки.

API 0 меняет отображение и не выдаёт отдельный «указатель». После него адрес
`#C000` уже относится к новой странице:

```asm
WLD     EQU #6006

        ; Подключить относительную страницу 1 нашего плагина к #C000.
        LD      A,1
        EX      AF,AF'
        XOR     A                      ; API 0 MNGC_PL
        CALL    WLD

        LD      HL,#C000               ; начало именно этой страницы
```

Если вызываемый код ожидает прежнюю страницу `#C000`, сохраните относительный
контекст в собственной логике или используйте `#6028`, который предназначен
для межстраничного вызова с восстановлением.

## 5. Карта физических страниц `#00..#FF`

```text
#00      основной текстовый экран
#01      шрифт/системный графический ресурс
#02      верхняя резидентная часть WC (#8000..#BFFF)
#03-#04  внутренние/непубличные
#05      CORE32 и нижняя часть WC (#4000..#7FFF)
#06-#0A  внутренние/непубличные
#0B-#13  девять страниц каталога левой панели
#14-#1C  девять страниц каталога правой панели
#1D      внутреннее/непубличное
#1E      backing page левой панели
#1F      backing page правой панели
#20-#5F  64 видеостраницы API 65/80/81
#60      цепочка 512-байтовых заголовков загруженных .WMF
#61-#9E  реально доступный пул загруженных плагинов (до 62 страниц)
#9F-#A0  граница/непубличный резерв; самовольно не занимать
#A1-#BF  временные страницы TAP/SNA/Z80
#C0-#E7  40 страниц RAM-диска TR-DOS Mounter
#E8-#EF  приватные расширения Wild Commander Improved
#F0-#FF  Commander и системные страницы
```

### 5.1 Верхние диапазоны — обязательный контракт

| Диапазон | Размер | Владелец |
|---:|---:|---|
| `#A1..#BF` | 31 страница | TAP/SNA Mounter |
| `#C0..#E7` | 40 страниц | TR-DOS Mounter |
| `#E8..#EF` | 8 страниц | Improved |
| `#F0..#FF` | 16 страниц | Commander/система |

CORE32_EXT установлен на странице `#E8`. Остальные страницы диапазона
Improved зарезервированы для совместимых расширений, но не становятся
автоматически свободным пулом плагина.

Для нового системного владельца верхней памяти сначала меняют единый контракт
`source/PHYSICAL_MEMORY_MAP.ASM`, затем проверяют все пересечения. Нельзя
просто выбрать «похожую на свободную» страницу между `#A1` и `#FF`.

### 5.2 Системные страницы, назначение которых известно

| Страница | Назначение |
|---:|---|
| `#F0` | WildDOS и состояние левой панели |
| `#F1` | WildDOS и состояние правой панели |
| `#F3..#F6` | Внутренние DMA/загрузочные рабочие страницы WC |
| `#F7` | Сохранённые пути и позиции панелей |
| `#F8..#FF` | Системный диапазон; не выделять плагинам |

На странице `#F7` логические смещения `#1000` и `#2000` используются для
состояния левой и правой панели. Это не те же данные, что каталожные страницы
`#0B..#1C`.

## 6. Пул плагинов

### 6.1 Как вычисляется физическая страница

Заголовок `.WMF +34` задаёт число страниц. Загрузчик выдаёт каждому плагину
непрерывный блок и хранит его относительную базу. Для понимания отладки можно
использовать формулу:

```text
physical_page = #61 + plugin_base + relative_page
```

Но в рабочем плагине формулу применять нельзя: передавайте только
`relative_page` в API 0, 78 или 79. Тогда конфигурация `[PLUGINS]` может менять
порядок модулей без пересборки кода.

Номинальная граница загрузчика — `#A0`, однако проверка требует, чтобы сумма
страниц была **меньше** `#3F`. Поэтому максимум равен 62 страницам, то есть
фактически используются `#61..#9E`; последняя номинальная `#9F` текущим
алгоритмом не выдаётся.

### 6.2 Текущее распределение из `exe/WC/wc.ini`

Строка с `CLOCK.WMF;PLASMATW.WMF;SCRSAVER.WMF` загружает только CLOCK:
точка с запятой начинает комментарий.

| Плагин | Страниц | Физический диапазон |
|---|---:|---:|
| FILEX | 1 | `#61` |
| MOUNTER | 4 | `#62..#65` |
| SETIME | 1 | `#66` |
| RE | 1 | `#67` |
| TXTEDIT | 2 | `#68..#69` |
| FILE_CR | 2 | `#6A..#6B` |
| TRDisp | 1 | `#6C` |
| TRDUMP | 1 | `#6D` |
| ROM_PROG | 1 | `#6E` |
| WPLAYER | 3 | `#6F..#71` |
| GSPLAYER | 2 | `#72..#73` |
| VIDEO_PL | 1 | `#74` |
| BMPV | 1 | `#75` |
| ILBMVIEW | 2 | `#76..#77` |
| FTVIEW | 1 | `#78` |
| GIFVIEW | 1 | `#79` |
| MCGSV | 1 | `#7A` |
| TAPM | 4 | `#7B..#7E` |
| COMPILER | 2 | `#7F..#80` |
| CLOCK | 6 | `#81..#86` |
| **Итого** | **38** | **`#61..#86`** |

После этой конфигурации следующая база — `#87`, а до лимита загрузчика
остаётся 24 страницы, или 384 КиБ. Это свободная ёмкость **пула загрузчика**,
а не разрешение обращаться к страницам `#87..#9E` напрямую.

### 6.3 Как добавить плагину постоянную память

Если нужны код плюс отдельный буфер 16 КиБ, заявите две страницы:

```asm
        ; Заголовок .WMF
        DB      2,0                 ; +34 pages=2, +35 entry_page=0
        DB      0,CodeSectors       ; относительная 0: код
        DB      1,0                 ; относительная 1: пустой постоянный буфер
        DS      4*2,0
```

Затем подключайте буфер относительным номером:

```asm
        LD      A,1
        EX      AF,AF'
        LD      A,79                ; API 79: page 1 -> #8000
        CALL    #6006
        ; Теперь #8000..#BFFF — наш буфер, но код текущей страницы исчез.
```

Последняя строка важна: после замены окна `#8000` нельзя продолжать выполнять
код, который находился в этом же окне. Для безопасного вызова процедуры на
другой странице используйте резидентный шлюз `#6028` либо исполняйте
переключатель из окна `#4000/#C000` по продуманному протоколу.

## 7. Где размещать буфер: таблица решений

| Задача | Рекомендуемая память | Почему |
|---|---|---|
| Структура SOW и короткие строки | Свободный хвост entry-page плагина в `#8000..#BFFF` | Постоянно видны во время обычного вызова |
| Большой постоянный буфер | Отдельная страница, заявленная в `.WMF +34` | Не пересекает другие плагины |
| `LOAD512/SAVE512` | Буфер своей подключённой страницы; не пересекать `#FFFF` | API работает секторами по 512 байт |
| `APPEND` | Обычно своя область `#8000..#BFFF`, длина `0..#4000` | Источник должен целиком лежать ниже `#C000` |
| Блок и буферы FILEX | Только `#8000..#BFFF` | `#C000` занят провайдером, `#0000` — DOS |
| Список каталога плагина | Собственный буфер; вызывать API 58 | Не занимать внутренние `#0000..#1FFF` напрямую |
| Данные между запусками плагина | Зарезервированная страница плагина | Выделение живёт, пока плагин загружен |
| Новый системный RAM-диск | Только после изменения общей physical map | Верхние страницы имеют владельцев |

Юридически допустимый адрес API ещё не означает, что память принадлежит
плагину. Например, APPEND принимает источник начиная с `#4000`, но область
`#4000..#7FFF` занята резидентным кодом WC. Её можно читать как источник лишь
если вы намеренно передаёте уже существующие неизменяемые байты, а записывать
туда свой буфер нельзя.

## 8. Границы и арифметика без переполнения

Для любого полуинтервала `[address,address+length)` проверяйте:

1. `length` разрешена конкретным API;
2. 16-битное сложение не переполнилось;
3. конечный адрес не вышел за разрешённое окно;
4. последний байт равен `end-1`, а сам `end` уже не принадлежит буферу.

### 8.1 Проверка буфера FILEX

```asm
; Вход: HL=адрес, BC=длина.
; Выход: CF=1 — диапазон не помещается в #8000..#BFFF.
CheckFilexBuffer:
        LD      A,H
        CP      #80
        JR      C,.bad
        CP      #C0
        JR      NC,.bad
        PUSH    HL
        ADD     HL,BC
        JR      C,.overflow
        LD      A,H
        CP      #C0
        JR      C,.ok
        JR      NZ,.overflow
        LD      A,L
        OR      A                    ; end может быть ровно #C000
        JR      NZ,.overflow
.ok:
        POP     HL
        OR      A                    ; CF=0 — диапазон допустим
        RET
.overflow:
        POP     HL
.bad:
        SCF
        RET
```

В реальном коде проще хранить блок FILEX и его буфер статически в одной
заявленной странице и закрепить границы `ASSERT` при сборке.

### 8.2 Проверка статической раскладки плагина

```asm
        DISP    #8000
PluginStart:
        ; ... код и данные ...

FilexBlock:
        DS      32
IoBuffer:
        DS      4096
PluginEnd:

        ASSERT  FilexBlock >= #8000
        ASSERT  PluginEnd <= #C000
        ASSERT  IoBuffer+4096 <= #C000
        ENT
```

Такие проверки лучше ручного подсчёта: ошибка становится ошибкой сборки, а не
повреждением памяти на компьютере пользователя.

## 9. Стек и прерывания

WC устанавливает `SP=#5FFE`; стек Z80 растёт вниз. Рядом находятся конец
CORE32 и таблица IM2 `#5BFF..#5C02`. Следствия:

- не размещайте данные в предполагаемом «свободном хвосте» перед `#6000`;
- не оставляйте несбалансированные `PUSH`;
- при временном собственном стеке запрещайте прерывания на время смены `SP`
  либо обеспечьте обработчику отдельный корректный стек;
- перед `RET` всегда восстановите исходный `SP` и режим прерываний;
- обработчик IM2 может вызывать резидентные плагины, часы и PS/2, поэтому
  самоподстановочный и файловый код не является автоматически повторно-входимым.

Минимальный безопасный шаблон локального стека внутри своей страницы:

```asm
SavedSP:
        DW      0

UseLocalStack:
        DI
        LD      (SavedSP),SP
        LD      SP,LocalStackTop
        EI
        ; ... работа без переключения страницы, содержащей стек ...
        DI
        LD      SP,(SavedSP)
        EI
        RET

        DS      128
LocalStackTop:
```

Если во время работы переключить страницу, в которой находится `SavedSP` или
сам локальный стек, возврат разрушится. Поэтому для большинства плагинов лучше
не менять стек вообще.

## 10. Частые ошибки памяти

### Ошибка 1. Физический номер зашит в код

```asm
        LD      A,#75
        OUT     (#12AF),A             ; плохо
```

Порядок `[PLUGINS]` изменится — страница `#75` начнёт принадлежать другому
модулю. Кроме того, тень `#6002` останется старой.

Правильно: относительный номер плюс API 79.

### Ошибка 2. Код переключил окно, из которого сам исполняется

```asm
        ; Этот код работает по #8100.
        LD      A,1
        ; API 79 прямо сейчас заменит страницу с продолжением кода.
```

Используйте `CALL #6028` или маленький переключатель в другом неизменяемом
окне.

### Ошибка 3. FILEX блок лежит по `#C000`

Шлюз подключит туда код провайдера и затрёт видимость блока до того, как тот
будет обработан. Блок и буферы должны быть в `#8000..#BFFF`.

### Ошибка 4. `LOAD512` переходит через `#FFFF`

Исторический поток не превращает адрес `#10000` в следующую физическую
страницу. Разбейте операцию так, чтобы каждый вызов целиком помещался в одном
видимом диапазоне.

### Ошибка 5. Плагин использует `#0000..#3FFF` как вечную память

Файловая обёртка меняет страницу окна `#0000`; указатель остаётся тем же, а
физические байты уже другие. Для постоянных данных резервируйте страницу WMF.

### Ошибка 6. «Свободная» верхняя страница занята Mounter

Диапазоны `#A1..#FF` разделены между TAP/SNA, Mounter, Improved и системой.
Новый владелец обязан пройти через общую карту, иначе повреждение проявится
только при запуске другого плагина.

## 11. Контрольный список автора плагина

- [ ] В `.WMF +34` заявлены все страницы кода и постоянных данных.
- [ ] Код использует относительные страницы, а не физические `#61..#9E`.
- [ ] Переключение выполняется через API или `#6028`, тени `#6000..#6003`
      остаются согласованными.
- [ ] Код не продолжает исполняться из только что переключённого окна.
- [ ] Все буферы имеют сборочные `ASSERT` на нижнюю и верхнюю границы.
- [ ] LOAD/SAVE не пересекают `#FFFF -> #0000`.
- [ ] APPEND получает источник ниже `#C000` и длину не больше `#4000`.
- [ ] FILEX блок и все его указатели лежат в `#8000..#BFFF`.
- [ ] Нет прямых записей во внутренние `#7Fxx`, `#38xx` и системные страницы.
- [ ] Стек сбалансирован; временная смена `SP` учитывает IM2 и paging.
- [ ] Для новой системной страницы изменён и проверен
      `PHYSICAL_MEMORY_MAP.ASM`.
