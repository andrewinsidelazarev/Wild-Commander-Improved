# Драйверы накопителей: ABI и разработка

Драйвер WildDOS — это сменный низкоуровневый модуль блочного устройства. Он
не знает имён файлов и FAT32: его задача — выбрать устройство, принять LBA и
переслать один или несколько блоков. CORE32 выполняет всё остальное.

## 1. Место драйвера в стеке

```text
плагин / панель
      │
      │ API #6006
      ▼
файловые обёртки WC
      │
      ▼
CORE32: FAT32, каталоги, цепочки, потоки
      │
      │ XPOZI + RDDSE/SDDSE
      ▼
driver runtime #3800
      │
      ├─ IDE Nemo
      ├─ SD Z-Controller
      ├─ SD через NGS
      └─ IDE SMUC
```

Плагин не вызывает `#3800` напрямую. Драйверный ABI предназначен для CORE32 и
кода менеджера, который устанавливает драйвер через `DOS_SWP`.

## 2. Физическая модель

```text
логическое окно Z80 #0000..#3FFF

#0000 ┌──────────────────────────────┐
      │ каталожные буферы            │
#2000 ├──────────────────────────────┤
      │ рабочая область CORE32       │
#3000 ├──────────────────────────────┤
      │ FAT + секторные буферы       │
#3800 ├──────────────────────────────┤
      │ JP-таблица драйвера          │ 72 байта
#3848 ├──────────────────────────────┤
      │ общее состояние CORE32       │
      │ + код/данные драйвера        │
#4000 └──────────────────────────────┘
```

Для левой панели это окно обычно отображает физическую страницу `#F0`, для
правой — `#F1`. Переключение панели тем самым переключает и драйвер, и весь его
контекст.

Упакованный драйвер хранится внутри CORE32. `DOS_SWP` распаковывает выбранный
образ по `#3800`; старый драйвер и его состояние полностью заменяются.

## 3. Таблица входов `#3800`

Таблица занимает 24 слота по три байта. Первые восемь определены, остальные 16
исторически были резервом. В SD-ZC часть резерва используется короткими
шлюзами к CORE32_EXT, но внешние номера первых восьми не меняются.

| Адрес | Offset | Имя | Вход | Результат |
|---:|---:|---|---|---|
| `#3800` | `+0` | `SELDEV` | `A` — вариант устройства | Выбирает master/slave или интерфейс; специфично для драйвера |
| `#3803` | `+3` | `DEVINI` | Нет общего параметра | `Z` — устройство готово, `NZ` — не найдено/ошибка |
| `#3806` | `+6` | `REINI` | Нет | Повторно применить выбор/состояние; может быть пустым `RET` |
| `#3809` | `+9` | `XPOZI` | `DE:HL` — LBA32 | Сохранить общую и приватную позицию |
| `#380C` | `+12` | `PROZ` | `DE:HL` — LBA32 | Обновить приватную позицию, не меняя общие `LTHL/LTDE` |
| `#380F` | `+15` | `RDDSE` | `HL` — буфер, `A` — число секторов 512 байт | Читает подряд, продвигает `HL`; ошибку записывает в `ABT` |
| `#3812` | `+18` | `SDDSE` | `HL` — буфер, `A` — число секторов 512 байт | Пишет подряд, продвигает `HL`; ошибку записывает в `ABT` |
| `#3815` | `+21` | `RDD256` | `HL` — буфер, `A` — число 256-байтовых блоков | Необязательный старый быстрый вход |

`DE:HL` в LBA означает `DE` — старшее слово, `HL` — младшее. Секторный размер
CORE32 фиксирован: 512 байт. Драйвер с иным физическим блоком обязан сам
представить интерфейс 512-байтовых логических секторов.

## 4. Общая область состояния

После 72-байтовой таблицы по `#3848` начинается layout, который должен совпасть
с `KERNEL.ASM`. Драйверный исходник повторяет эти объявления, потому что
распаковка одновременно устанавливает начальные значения CORE32.

| Адрес | Имя | Размер | Назначение |
|---:|---|---:|---|
| `#3848` | `NSDC` | 1 | Сектор внутри текущего кластера |
| `#3849` | `EOC` | 1 | Состояние конца FAT-цепочки |
| `#384A` | `ABT` | 1 | Единый код низкоуровневой ошибки |
| `#384B` | `BZN` | 1 | Остаток блоков текущего запроса |
| `#384C` | `NR0` | 2 | Размер текущей низкоуровневой порции |
| `#384E..` | — | — | Позиции потока и промежуточные значения |
| `#3868` | `ENTRY` | 32 | Текущая FAT32 directory entry |
| `#3888` | `FATFLAGS` | 1 | Младший байт BPB_ExtFlags |
| `#3889..` | — | — | BPB, FAT, root, FSInfo, текущие кластеры |
| до `RECCAT` | — | — | Текущий и сохранённый каталоги |

Точные адреса вычисляются в `source/KERNEL.ASM`. Не вставляйте приватную
переменную внутрь этого layout: весь код CORE32 обращается к фиксированным
offset.

Размещайте приватные данные/код драйвера после общей области и завершайте образ
до `#4000`. Полный runtime имеет не более `#0800` байт от `#3800` до границы
окна.

## 5. Контракт ошибки `ABT`

```text
перед I/O CORE32:  ABT = 0
                        │
                        ▼
                 CALL RDDSE/SDDSE
                        │
          ┌─────────────┴─────────────┐
          │                           │
     операция успешна            операция сорвана
       ABT остаётся 0             ABT = ненулевой код
          │                           │
        Z return                    NZ return
```

Обёртки `SAFE_RDDSE/SAFE_SDDSE` очищают `ABT`, вызывают драйвер, затем делают
`LD A,(ABT) / OR A`. Поэтому новый драйвер обязан сигнализировать отказ через
`ABT`, а не только через `CF`, статусный регистр контроллера или произвольный
ненулевой `A`.

Рекомендуемый эпилог:

```asm
.ok:
        XOR     A
        LD      (ABT),A
        RET

.io_error:
        LD      A,#01                ; внутренний ненулевой код драйвера
        LD      (ABT),A
        OR      A                    ; удобно и прямому вызывающему: NZ
        RET
```

Старые драйверы не всегда меняли `ABT`; обёртка трактует их возврат как успех.
Боевой SD-ZC сохраняет этот старый контракт и используется без runtime-патча.
Для нового драйвера не повторяйте историческую неопределённость.

Правила отказа:

- любой timeout, CRC/token error, ATA ERR/DF и недовыполненный сектор должны
  вернуть управление и установить `ABT`;
- не оставляйте chip select, DMA или контроллер в состоянии незавершённой
  транзакции;
- не продолжайте следующий сектор после первой ошибки;
- `HL` после ошибки может указывать за фактически переданной частью, но верхний
  API не сообщает частичное число; вызывающий должен считать весь запрос
  неуспешным;
- бесконечное ожидание статуса превращает ошибку носителя в зависание всего WC,
  поэтому каждый wait-loop нового драйвера должен иметь конечный бюджет.

## 6. Позиционирование

CORE32 использует две похожие операции:

```text
XPOZI(DE:HL)
  ├─ сохраняет LBA в общих LTHL/LTDE
  └─ подготавливает приватный BLKNUM/регистры

PROZ(DE:HL)
  └─ только подготавливает приватный BLKNUM/регистры
```

`RDDSE/SDDSE` читают позицию, ранее установленную одной из них. После I/O
CORE32 сам продвигает общую LBA потока; драйвер не должен тайно прибавлять к
`LTHL/LTDE`. Контроллер может внутренне перейти к следующему сектору в рамках
multi-block команды — это нормально.

Пример IDE-преобразования LBA28:

```text
sector number  = LBA bits 7..0
cylinder low   = LBA bits 15..8
cylinder high  = LBA bits 23..16
drive/head     = master/slave prefix | LBA bits 27..24
```

SDHC принимает LBA как номер блока; SDSC/MMC требует байтовый адрес. Это
различие определяется во время `DEVINI` и хранится в состоянии драйвера.

## 7. Многоблочный обмен и буфер

`A` задаёт число последовательных блоков, а `HL` — первый байт. Успешный
драйвер должен обработать ровно запрос и вернуть `HL`, продвинутый на
`512*A` для RDDSE/SDDSE или `256*A` для RDD256.

```text
HL before ──► [ sector 0 ][ sector 1 ] ... [ sector A-1 ] ──► HL after
               512 bytes   512 bytes          512 bytes
```

Не разрешайте физическому обмену молча перейти через `#FFFF→#0000`. Внешняя
обёртка плагинов требует делить такой запрос. Внутренний код также должен
подавать порции, помещающиеся в видимый адресный диапазон.

DMA можно использовать, если адрес и контроллер удовлетворяют требованиям
выравнивания. Обязательно оставьте PIO-путь для невыравненного буфера. Текущий
Nemo и ZC выбирают DMA для подходящих адресов, иначе выполняют портовый цикл.

Особый случай: приватный CORE32_EXT временно отображается в `#C000`. Перед
PIO-записью буфера из этого окна шлюз обязан вернуть исходную страницу, иначе
драйвер прочитает код расширения вместо пользовательских данных. Новый драйвер
не должен самостоятельно предполагать, какая физическая страница стоит в
`#C000`; он работает с данным логическим `HL`.

## 8. Встроенные драйверы

| Драйвер | Runtime | Интерфейс | `SELDEV` | `RDD256` | Важная особенность |
|---|---:|---|---|---|---|
| `DIDENEMO.ASM` | 959 байт | IDE Nemo | `A=0` master, иначе slave | Есть | ATA PIO/DMA, LBA28 |
| `DIDESMUC.ASM` | 903 байта | IDE SMUC | `A=0` master, иначе slave | Есть | Сначала включает SMUC через `#FFBA` |
| `DSDZC.ASM` | 1164 байта | SD Z-Controller | `A=0` первый, иначе второй | Есть | CMD18/CMD25, DMA/PIO, шлюзы конечного ожидания |
| `DSDNGS.ASM` | 1378 байт | NGS SD-service | выбор не делится на master/slave | Пустой `RET` | Загружает 1-КиБ службу в память NGS |

Порты и протоколы:

| Драйвер | Основные порты |
|---|---|
| Nemo | ATA-регистры `#10/#11`, `#30/#50/#70/#90/#B0/#D0/#F0` |
| SMUC | ATA-регистры `#D8BE/#F8BE..#FFBE`, config `#FFBA` |
| ZC | config `#77`, data `#57` |
| NGS | command `#BB`, data `#B3` |

SD-NGS не поддерживает API 60 `LOAD256`. Код верхнего уровня обязан либо
запретить этот путь, либо использовать обычный API 48.

## 9. Выбор драйвера через `DOS_SWP`

Внутренний вход `#401B` принимает:

```text
A=0  Nemo master
A=1  SD-ZC #1
A=2  SD-NGS
A=3  SMUC master
A=4  SMUC slave
A=5  Nemo slave
A=6  SD-ZC #2
```

```text
CALL #401B
   │
   ├─ выбрать packed block DR1..DR4
   ├─ распаковать в #3800
   ├─ применить runtime-расширение, если требуется
   └─ CALL #3800 SELDEV
```

`DOS_SWP` сохраняет `IX`, но остальное следует считать внутренним ABI. После
замены драйвера вызывают `#4003 DEVINI`, затем `#4009 HDD`, чтобы найти FAT32 и
заполнить BPB. Просто распакованный драйвер ещё не означает смонтированный том.

Обычный плагин не должен вызывать `#401B`: устройство панели выбирается в
`wc.ini`, а отдельный поток создаётся публичным API 57.

## 10. Каркас нового драйвера

```asm
        ORG     0
        DISP    #3800

DRIVER:
        JP      SELDEV
        JP      DEVINI
        JP      REINI
        JP      XPOZI
        JP      PROZ
        JP      RDDSE
        JP      SDDSE
        JP      RDD256

        ; 16 обязательных резервных слотов.
        DUP     16
        DS      3,0
        EDUP
        ASSERT  $ == #3848

; Ниже должна в точности следовать общая структура из KERNEL.ASM.
NSDC:   DS      1
EOC:    DS      1
ABT:    DS      1
        ; ... BZN, NR0, ENTRY, BPB/FAT, LSTCAT, RECCAT ...

; Приватные поля и код — только после последнего общего поля.
PRIVATE_LBA:    DS 4

SELDEV:
        ; Сохранить вариант устройства и перевести контроллер в idle.
        RET

DEVINI:
        ; Определить устройство, режим адресации и размер логического блока.
        XOR     A                      ; Z = готово
        RET

REINI:
        RET

XPOZI:
        LD      (LTHL),HL
        LD      (LTDE),DE
PROZ:
        LD      (PRIVATE_LBA),HL
        LD      (PRIVATE_LBA+2),DE
        RET

RDDSE:
        ; A секторов: дождаться с timeout, передать 512*A, продвинуть HL.
        ; При любом отказе записать ненулевой ABT и вернуться.
        RET

SDDSE:
        ; Симметричный путь записи.
        RET

RDD256:
        ; Реализовать либо явно документировать как неподдерживаемый.
        RET

DRIVER_END:
        ASSERT  DRIVER_END <= #4000
        ENT
```

На практике блок общих полей нельзя сокращать многоточием: скопируйте текущий
layout из `KERNEL.ASM` или вынесите его в общий include одновременно для ядра и
всех драйверов. Добавьте `ASSERT` хотя бы для `VALS=#3848`, `ENTRY=#3868`,
`ABT=#384A` и конечной границы.

## 11. Подключение нового драйвера к WC

```text
driver.asm
   │ assemble at logical #3800
   ▼
driver.bin
   │ Hrust pack + unpack byte comparison
   ▼
driver.CPD
   │ include in CORE32 + DOS_SWP mapping
   ▼
boot payload
   │
   ├─ добавить имя/номер в SDRV и wc.ini
   ├─ сохранить panel.device mapping
   └─ обновить проверки размера/символов
```

Последовательность изменений:

1. Реализовать таблицу и общий layout без изменения адресов.
2. Ассемблировать runtime с `DISP #3800`; убедиться, что конец ниже `#4000`.
3. Упаковать Hrust и распаковать обратно; байты должны совпасть с runtime.
4. Добавить packed block в конец CORE32 так, чтобы не вытеснить `DEHR` и
   фиксированные шлюзы.
5. Расширить выбор в `DOS_SWP` либо заменить существующий вариант осознанно.
6. Добавить строку настройки панели и согласовать числовой device ID.
7. Проверить `DEVINI → HDD → RDD/SDD` на отдельном тестовом образе, затем уже
   файловые операции.

`build.ps1` сейчас заново собирает четыре исходника, проверяет точный размер и
SHA-256 их runtime. Для нового драйвера добавьте аналогичный элемент в
`DriverChecks`, чтобы исходник не превратился в необязательную копию.

## 12. Диагностика по слоям

| Симптом | Первый уровень поиска |
|---|---|
| `DEVINI` сразу NZ | SELDEV, порты, reset/identify, выбранный master/slave |
| `DEVINI` Z, но `HDD` NZ | чтение LBA0, адресация SDSC/SDHC, размер 512, MBR/BPB |
| Чтение работает, запись портит соседний сектор | число блоков, продвижение HL, LBA, stop token/flush |
| Ошибка носителя превращается в зависание | wait-loop без timeout |
| Ошибка возвращается как успех | драйвер не записал `ABT` |
| DMA работает только на части адресов | отсутствует PIO fallback или неверное выравнивание |
| Левая панель работает, правая нет | драйвер хранит состояние вне панельной страницы |
| API 60 ничего не читает на NGS | `RDD256` этого драйвера пустой |

## 13. Файлы-источники

- `source/KERNEL.ASM` — фиксированная таблица и общий layout.
- `source/CORE32.ASM` — `RDD`, `SDD`, безопасные обёртки и `DOS_SWP`.
- `source/DIDENEMO.ASM` — полный пример ATA/Nemo.
- `source/DIDESMUC.ASM` — ATA через SMUC.
- `source/DSDZC.ASM` — SD multi-block, DMA и конечные шлюзы ожидания.
- `source/DSDNGS.ASM` — host/service-протокол NGS.
- `source/DEHR2.ASM` — распаковщик runtime.
- `build.ps1` — сборка, размеры, хэши и упаковка.
