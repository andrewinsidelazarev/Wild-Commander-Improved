# Плагины и полный публичный API Wild Commander

Этот документ отвечает на практический вопрос: как написать `.WMF`-плагин и
как вызвать каждую публичную функцию Wild Commander. Он описывает всю таблицу
API `0..86`, а не только новые API 76 и 77.

## 1. Главный контракт

Публичная точка входа одна:

```asm
WLD     EQU #6006

        LD      A,номер_API
        CALL    WLD
```

Номер API всегда передаётся в основном `A`. Если целевой функции одновременно
нужно собственное входное значение `A`, это значение заранее кладётся в `A'`:

```asm
        LD      A,значение_для_функции
        EX      AF,AF'
        LD      A,номер_API
        CALL    WLD
```

Диспетчер `#6006` выбирает двухбайтовый адрес из таблицы, выполняет
`EX AF,AF'` и передаёт управление функции через `RET`. Поэтому переданное в
`A'` значение становится обычным `A` уже внутри функции. Возвращаемый обычный
`A` и флаги приходят вызывающему коду без обратного обмена.

Удобные макросы:

```asm
WLD     EQU #6006

        MACRO WC_CALL api
        LD      A,api
        CALL    WLD
        ENDM

        ; Перед вызовом значение функции должно находиться в A.
        MACRO WC_CALL_A api
        EX      AF,AF'
        LD      A,api
        CALL    WLD
        ENDM
```

Номера без `#` в этом руководстве десятичные. Например, API `78` имеет
машинный номер `#4E`. Запись `LD A,#78` вызовет совсем другой, несуществующий
элемент за таблицей. Это одна из ошибок старых C-заголовков.

Диспетчер как минимум разрушает альтернативный `BC`. Сохранять остальные
регистры следует только там, где это прямо обещано конкретной функцией. Флаги
результата проверяются сразу:

```asm
        LD      A,59                 ; FENTRY
        CALL    WLD
        JR      Z,.not_found         ; до OR/CP/INC и других команд
```

## 2. Как WC запускает плагин

WC отображает выбранную страницу плагина в окно `#8000..#BFFF` и выполняет:

```asm
        CALL    #8000
```

На входе:

| Регистр | Значение |
|---|---|
| `A` | Тип запуска: `#00`, `#01`, `#02`, `#03`, `#04`, `#06`, `#12` или `#14` |
| `DE:HL` | 32-битный размер выбранного файла, `DE` — старшее слово |
| `BC` | Адрес нуль-терминированного имени при типах `#00`, `#04`, `#14` |
| `IX` | Адрес 36-байтовой структуры активной панели |
| `A'` | Индекс совпавшего расширения `0..31`, только для типа `#00` |
| `DE'` | Число объектов панели, включая `..`, для `#00/#04/#12/#14` |
| `HL'` | Номер переданного объекта от 1, для `#00/#04/#12/#14` |

Типы запуска:

| Код | Причина |
|---:|---|
| `#00` | Файл передан по совпавшему расширению |
| `#01` | Немедленный запуск после ручной загрузки плагина по Enter |
| `#02` | Таймер экранной заставки |
| `#03` | Меню плагинов F10 |
| `#04` | Меню выбора просмотрщика Shift+F3/Shift+Enter |
| `#06` | Одноразовый автозапуск из `[PLUGINS]` при старте WC |
| `#12` | Команда F2 |
| `#14` | Команда F4 |

Если плагину понадобится исходный `IX`, сохраните его до первого вызова кода,
который использует IX:

```asm
PluginEntry:
        PUSH    IX
        ; ... работа плагина ...
        POP     IX
        XOR     A
        RET
```

Значение `A` при возврате:

| `A` | Действие WC |
|---:|---|
| `0` | Обычный выход |
| `1` | Файл не распознан; попробовать следующий обработчик, только для `#00` |
| `2` | Передать следующий файл, только для `#00` |
| `3` | Перечитать панель; недоступно для `#01/#02` |
| `4` | Передать предыдущий файл, только для `#00` |

При входе может быть включён любой видеорежим. API 15 `GEDPL` переводит WC в
основной текстовый режим, но уничтожает `#1000..#1447` текущей страницы окна
`#0000`. Для файлового просмотрщика сначала определите формат, затем вызывайте
`GEDPL`; так неизвестный файл можно вернуть следующему обработчику без мигания
экрана.

### 2.1 Тип плагина и причина запуска — не одно и то же

Байт заголовка `.WMF +197` задаёт **условия регистрации плагина**. Регистр `A`
при `CALL #8000` сообщает **фактическую причину конкретного запуска**. У
составных типов эти числа различаются: например, плагин типа `#15` получает
`A=#03` из F10, `A=#04` из меню просмотрщиков и `A=#14` по F4.

Полная матрица типов:

| `.WMF +197` | Когда WC вызывает плагин | Фактический `A` на входе |
|---:|---|---|
| `#00` | Только при совпадении расширения | `#00` |
| `#01` | Сразу после ручной загрузки самого `.WMF` по Enter | `#01` |
| `#02` | По таймеру заставки или из F10 | `#02` / `#03` |
| `#03` | Из меню плагинов F10 | `#03` |
| `#04` | Из меню просмотрщиков Shift+F3/Shift+Enter | `#04` |
| `#05` | Из F10 или из меню просмотрщиков | `#03` / `#04` |
| `#06` | Один раз при старте, если строка находится в `[PLUGINS]` | `#06` |
| `#11` | Из F10 или по F2 | `#03` / `#12` |
| `#12` | По F2 | `#12` |
| `#13` | Из F10 или по F4 | `#03` / `#14` |
| `#14` | По F4 | `#14` |
| `#15` | Из F10, меню просмотрщиков или по F4 | `#03` / `#04` / `#14` |

Блок расширений `+64..+159` действует независимо от `+197`. Если в нём есть
расширение, любой из перечисленных типов дополнительно может получить файл с
`A=#00`. Чтобы плагин никогда не запускался по расширению, заполните все 96
байт блока нулями.

### 2.2 Жизненный цикл автозапуска `#06`

```text
wc.ini: [PLUGINS]
        │
        ▼
загрузчик выделяет страницы и сохраняет 512-байтовый заголовок
        │ тип #06 пока только зарегистрирован
        ▼
GEDZ → DEF: интерфейс WC уже построен
        │
        ▼
AX_RUN просматривает заголовки в порядке [PLUGINS]
        │
        ├─ подключает entry-page
        ├─ CALL #8000, A=#06
        ├─ возвращает прежнюю страницу окна #C000
        └─ удаляет этот заголовок и сдвигает следующие
        │
        ▼
PATH восстанавливает каталоги и позиции обеих панелей
```

Контракт `#06`:

- проход выполняется ровно один раз при старте; ручная загрузка такого `.WMF`
  позднее не запускает проход повторно;
- несколько модулей `#06` выполняются по порядку строк `[PLUGINS]`;
- на входе гарантирован `A=#06`; файловые `BC`, `DE:HL` и альтернативные
  регистры для этого типа использовать нельзя;
- код возврата плагина не трактуется как переход по файлам или обновление
  панели: после `RET` заголовок в любом случае удаляется;
- выделенные физические страницы не перемещаются и не выдаются другим
  плагинам до завершения сеанса WC;
- удалённый заголовок больше не участвует в F10, меню просмотрщиков,
  F2/F4 и маршрутизации расширений;
- окно `#C000` после всего прохода восстанавливается перед вызовом `PATH`.

Тип предназначен для резидентного установщика или провайдера. `FILEX.WMF`
публикует страницу провайдера в шлюзе API 77, поэтому стоит первой активной
строкой `[PLUGINS]`. После удаления заголовка FILEX не виден пользователю, но
его зарезервированная страница продолжает обслуживать вызовы.

## 3. Формат `.WMF`

Первые 512 байт файла — заголовок. Затем последовательно лежат блоки, которые
загрузчик копирует в выделенные плагину 16-КиБ страницы.

### 3.1 Поля заголовка

| Offset | Длина | Поле |
|---:|---:|---|
| `+0` | 16 | Нули/резерв |
| `+16` | 16 | Строго `WildCommanderMDL` |
| `+32` | 1 | Версия формата; загрузчик принимает `#02..#10`, текущая максимальная `#10` |
| `+33` | 1 | Резерв, ноль |
| `+34` | 1 | Число резервируемых 16-КиБ страниц |
| `+35` | 1 | Относительная страница, отображаемая в `#8000` перед `CALL #8000` |
| `+36` | 12 | Шесть пар `[относительная_страница, число_секторов_по_512]` |
| `+48` | 15 | Резерв, нули |
| `+63` | 1 | Маршрутизация расширений по Enter/F3 |
| `+64` | 96 | 32 расширения по три заглавных байта, без точек |
| `+160` | 1 | Ноль |
| `+161` | 4 | Максимальный размер принимаемого файла, LE32 |
| `+165` | 32 | Имя плагина, дополненное пробелами |
| `+197` | 1 | Условие запуска |
| `+198` | 6 | Подпись F2 или F4 для подходящих типов |
| `+204` | 24 | Подпись в меню просмотрщиков |
| `+228` | 32 | Резерв, нули |
| `+260` | 252 | Схема параметров из `wc.ini` |

Биты `+63`:

- bit 0 = 0: запуск по Enter и F3;
- bit 0 = 1, bit 1 = 0: только Enter;
- bit 0 = 1, bit 1 = 1: только F3.

Условия `+197`:

| Код | Запуск |
|---:|---|
| `#00` | Только по расширению |
| `#01` | Сразу после ручной загрузки |
| `#02` | Таймер и F10 |
| `#03` | F10 |
| `#04` | Меню просмотрщиков |
| `#05` | F10 и меню просмотрщиков |
| `#06` | Один раз при старте из `[PLUGINS]` |
| `#11` | F10 и F2 |
| `#12` | F2 |
| `#13` | F10 и F4 |
| `#14` | F4 |
| `#15` | F10, меню просмотрщиков и F4 |

Наличие расширений действует независимо от `+197`: даже меню-плагин можно
одновременно зарегистрировать как файловый обработчик.

### 3.2 Минимальный одностраничный заголовок

```asm
        DEVICE ZXSPECTRUM128
        ORG     0

PluginFile:
        DS      16,0
        DB      "WildCommanderMDL"
        DB      #10,0                 ; версия, резерв
        DB      1,0                   ; одна страница, entry page 0
        DB      0,(PluginEnd-PluginCode+511)/512
        DS      5*2,0                 ; ещё пять пустых описателей
        DS      15,0
        DB      0                     ; Enter и F3
        DB      "TXT"                 ; расширение 0
        DS      31*3,0
        DB      0
        DD      #FFFFFFFF             ; без ограничения размера
PluginName:
        DB      "Example viewer"
        DS      32-($-PluginName)," "
        DB      #00                   ; обработчик расширения
        DS      6,0
        DS      24,0
        DS      32,0
        DS      252,0
        ASSERT  $ == 512

        DISP    #8000
PluginCode:
        ; Здесь находится точка CALL #8000.
        XOR     A
        RET
PluginEnd:
        ENT

        SAVEBIN "EXAMPLE.WMF",PluginFile,PluginEnd-PluginFile
```

Каждая непустая пара в `+36` загружает очередной блок файла в указанную
относительную страницу, начиная с `#C000`. Для обычной полной страницы размер
равен 32 секторам. Не допускайте перехода одного блока через `#FFFF`.

### 3.3 Распределение страниц

Заголовки находятся на физической странице `#60`, код и данные плагинов — в
пуле `#61..#9F`. Поле `+34` резервирует страницы на всё время, пока плагин
загружен; не загруженные из файла страницы можно использовать как постоянные
буферы. Сумма страниц всех загруженных плагинов должна быть меньше 63, то есть
фактический предел загрузчика — 62 страницы (992 КиБ).

API 0/78/79 принимает относительный номер внутри выделенного блоку. Плагину не
нужно знать фактическую физическую страницу.

Тип `#06` выполняется после инициализации интерфейса, но до восстановления
путей панелей. Его 512-байтовый заголовок после вызова удаляется из списка меню;
выделенные страницы остаются. Это позволяет установить резидентный провайдер,
как делает `FILEX.WMF`.

## 4. Резидентные адреса и страницы

| Адрес | Назначение |
|---:|---|
| `#6000..#6003` | Тени физических страниц окон `#0000/#4000/#8000/#C000` |
| `#6004` | Флаг Esc менеджера плагина; это не `ABT` файлового ядра |
| `#6005` | Флаг Enter |
| `#6006` | Публичный диспетчер API |
| `#6009..#600A` | Кадровый таймер |
| `#600D` | Тип/версия видеоконфигурации |
| `#600E` | Высота текстового экрана: 25, 30 или 36 |
| `#6020` | Переключить страницу плагина и выполнить `JP (HL)` |
| `#6028` | Переключить страницу, выполнить `CALL (HL)` и восстановить страницу |

Вызов кода другой страницы:

```asm
        LD      A,2                   ; относительная страница плагина
        LD      HL,#8120              ; процедура собрана для окна #8000
        CALL    #6028
        ; #6028 сохраняет все регистры, кроме A и HL.
```

`#6020` — безвозвратный межстраничный переход. Возвращаться после него можно
только по протоколу самого плагина. Для обычного вызова используйте `#6028`.

## 5. Окно SOW

API интерфейса принимает `IX` на структуру окна. Она должна находиться в
постоянно доступной памяти плагина: `#8000..#BFFF` или `#0000..#3FFF`.

| Offset | Размер | Назначение |
|---:|---:|---|
| `+0` | 1 | bit 7 — тень; bit 6 — курсор во всю ширину; bit 4 — инверсный заголовок; bits 3..0 — тип рамки/содержимого |
| `+1` | 1 | Маска цвета курсора |
| `+2/+3` | 1+1 | X/Y; `255` означает центрирование и заменяется вычисленным значением |
| `+4/+5` | 1+1 | Ширина/высота; `0` означает весь экран и заменяется значением |
| `+6` | 1 | Цвет paper+ink |
| `+7` | 1 | Обязательно ноль |
| `+8` | 2 | Буфер фона: `#FFFF` — не сохранять; `#0000` — менеджер назначит при выводе |
| `+10/+11` | 1+1 | Разделители, смещение от нижнего края; ноль отключает |
| `+12` | 1 | Позиция курсора от 1 для меню |
| `+13` | 1 | Нижний ограничитель меню |
| `+14/+15` | 1+1 | Цвет курсора и цвет под ним |

Низкие четыре бита `+0`:

| Тип | Содержимое |
|---:|---|
| `0/3/6` | Обычное окно, три варианта рамки |
| `1/4/7` | Заголовки и текст без курсора |
| `2/5/8` | Заголовки и текст с курсором |

Для типов `1/4/7` слова `+12`, `+14`, `+16` — указатели верхнего заголовка,
нижнего заголовка и текста. Для `2/5/8` те же указатели лежат в `+16`, `+18`,
`+20`, потому что `+12..+15` заняты курсором.

Правильная пара показа и удаления:

```asm
        LD      IX,Dialog
        WC_CALL 1                    ; PRWOW
        ; ... цикл диалога ...
        LD      IX,Dialog
        WC_CALL 2                    ; RRESB
```

Не копируйте SOW после `PRWOW`: центрированные координаты, размеры и адрес
буфера уже могли быть изменены менеджером.

### 5.1 Разметка текста

API 11/12 и текстовые поля SOW понимают управляющие байты:

| Последовательность | Значение |
|---|---|
| `#00` | Конец строки/абзаца |
| `#00,#00` | Разделитель сообщений для MEZZ |
| `#FE,low,high` | Ссылка на другую строку |
| `#0B,x` | Сдвиг вправо на `x` |
| `#0C,y` | Сдвиг вниз на `y` без сброса X/цвета |
| `#0D` | Новая строка |
| `#0E` | Центрировать следующую строку |
| `#09` | Поменять paper и ink местами |
| `#01..#08` | Цвет ink |
| две команды `#01..#08` | Последовательно задают paper и ink |

### 5.2 Какие вызовы образуют интерфейс плагина

Интерфейс — не одна процедура, а небольшой набор слоёв:

```text
API 15 GEDPL                         привести экран к основному TXT
      │
      ▼
API 1 PRWOW                         показать SOW и сохранить фон
      │
      ├─ API 3/4                     простой текст и его цвет
      ├─ API 11/12                   размеченный текст/сообщения
      ├─ API 5                       получить экранный адрес
      ├─ API 6/7                     нарисовать/стереть курсор
      ├─ API 8/9/10                  вопрос, редактор строки, HEX
      └─ API 16..47,85               клавиатура и ожидание
      │
      ▼
API 2 RRESB                         убрать окно и восстановить фон
```

| Задача интерфейса | Вызовы |
|---|---|
| Перейти в интерфейс WC | API 15 `GEDPL` |
| Показать и закрыть окно | API 1 `PRWOW`, API 2 `RRESB` |
| Печатать и красить точный диапазон | API 3 `PRSRW`, затем API 4 `PRIAT` |
| Печатать строки с разметкой | API 11 `TXTPR`, API 12 `MEZZ` |
| Управлять курсором окна | API 5 `GADRW`, 6 `CURSOR`, 7 `CURSER` |
| Получить подтверждение/строку/HEX | API 8 `YN`, 9 `ISTR`, 10 `NORK` |
| Опросить клавиши | API 16–47 и 85 |
| Переключить страницу плагина | API 0, 78, 79 или резидент `#6028` |
| Работать со своим видео | API 64–71, 80, 81 |
| Узнать параметры `wc.ini` | API 83 `PRM_PL` |
| Восстановить стандартные цвета | API 84 `DEFPRM` |
| Получить текущую конфигурацию видео | API 86 `GVCONFIG` |

Полный минимальный цикл модального окна:

```asm
WLD     EQU #6006

ShowDialog:
        LD      A,15                  ; GEDPL: основной текстовый интерфейс
        CALL    WLD

        LD      IX,Dialog
        LD      A,1                   ; PRWOW
        CALL    WLD

.wait:
        EI
        HALT                          ; один опрос на кадр

        LD      A,22                  ; Enter
        CALL    WLD
        JR      NZ,.accepted

        LD      A,23                  ; Esc
        CALL    WLD
        JR      Z,.wait
        XOR     A                     ; результат диалога: отмена
        JR      .close

.accepted:
        LD      A,1                   ; результат диалога: принято
.close:
        LD      (DialogResult),A
        LD      IX,Dialog
        LD      A,2                   ; RRESB
        CALL    WLD
        LD      A,(DialogResult)
        RET

DialogResult:
        DB      0

Dialog:
        DB      4+16+128,0            ; рамка 2, inverse title, shadow
        DB      255,255               ; центрировать X/Y
        DB      42,7                  ; width/height
        DB      %01011111,0           ; цвет, обязательный ноль
        DW      #0000                 ; PRWOW назначит буфер фона
        DB      0,0                   ; без разделителей
        DW      DialogTitle
        DW      DialogBottom
        DW      DialogText

DialogTitle:
        DB      #0E,#09,"EXAMPLE",0
DialogBottom:
        DB      #0E,"ENTER - OK, ESC - CANCEL",0
DialogText:
        DB      #0B,2,"Plugin interface is active",0
```

`PRWOW` изменяет вычисляемые поля SOW, поэтому структура должна лежать в
доступной до `RRESB` памяти. Не переключайте страницу `#8000`, содержащую
`Dialog`, пока окно открыто. Для меню с курсором используйте тип SOW `2/5/8` и
вызывайте API 6 каждый кадр, а API 7 перед окончательным удалением курсора.

### 6.1 Базовые страницы и интерфейс: 0–15

| API dec/hex | Имя | Вход | Выход и замечания |
|---:|---|---|---|

| `7/#07` | `CURSER` | `IX` → SOW | Стирает курсор, восстанавливая фон |

| `9/#09` | `ISTR` | Подкоманда в `A'`, остальные параметры ниже | Строковый редактор; состояние глобально, один редактор за раз |

| `13/#0D` | `DMAPL` | Подкоманда `A'`, параметры DMA | Настройка и запуск DMA, см. ниже |

Подкоманды API 9 `ISTR`:

- `A'=#FF`: редактор типа 0; `HL` — экранная строка, `D=CURMAX`,
  `E=CURNOW`;
- `A'=0`: один кадр обработки клавиатуры;
- `A'=1`: завершить, стереть курсор, вернуть адрес строки в `HL`;
- `A'=#FD`: редактор типа 2; `HL` — буфер, `HL'` — его размер, `D/E` —
  Y/X, `B=CURMAX`, `C=CURNOW`;
- `A'=2`: вывести буфер типа 2, вызывается каждый кадр вместе с `0`;
- `A'=#FE`: инициализировать индикаторы INS/OVR, ENG/RUS, CAPS; `H` выбирает
  верхний/нижний заголовок, `L=#FF`;
- `A'=3`: обновить индикаторы;
- `A'=#FC`: опросить CAPS/INS/CTRL+SHIFT; нельзя в тот же кадр с подкомандой 0.

Подкоманды API 13 `DMAPL`:

| `A'` | Операция |
|---:|---|
| `#00` | Source=`B:HL`, destination=`C:DE` |
| `#01/#02` | Установить только source / destination |
| `#03/#04` | Source / destination из текущего окна: `HL` и `B=0..3` |
| `#05` | `B` → DMA_T: значение 0 означает один burst |
| `#06` | `B` → DMA_N: 255 соответствует 512 байтам |
| `#07` | Одновременно DMA_T=`B`, DMA_N=`C` |
| `#08/#09` | SourceAlign / DestinationAlign = `C` |
| `#0A` | AlignSize = `C`: 0 для 16c, 1 для 256c |
| `#0B` | `E` AlignSize, `H` SourceAlign, `L` DestinationAlign |
| `#FC` | RAM→RAM с ожиданием |
| `#FB` | BLT→RAM с ожиданием |
| `#FA` | FILL с ожиданием |
| `#F9` | RAM→CRAM с ожиданием |
| `#F8` | RAM→SFILE с ожиданием |
| `#FD` | RAM→RAM без ожидания, align=0 |
| `#FE` | RAM→RAM с ожиданием, align=0 |
| `#FF` | Ждать готовности DMA |

Для `#00..#02` bit 7 номера страницы выбирает страницу плагина, а сброшенный
bit 7 — видеостраницу; bits 6..0 содержат номер.

### 6.3 Файлы, каталоги и потоки: 48–63, 72–77

Эти функции сами подключают рабочую файловую страницу. Плагину не следует
вызывать `#40xx` или вручную менять `#600B/#600C`.

| API dec/hex | Имя | Контракт |
|---:|---|---|
| `48/#30` | `LOAD512` | `HL` = буфер, `B` = блоки по 512; возвращает новый `HL`, `A=0/#0F/#FF`, при ошибке `CF=1` |
| `49/#31` | `SAVE512` | Как LOAD512, но пишет существующую цепочку; не расширяет файл и не меняет размер |
| `50/#32` | `GIPAGPL` | Позиционирует поток на начало файла, переданного менеджером |
| `51/#33` | `TENTRY` | `DE` → 32-байтовый буфер; копирует текущую FAT ENTRY |
| `52/#34` | `CHTOSEP` | `DE` = начало массива LBA32, `BC` = исключающий конец |
| `53/#35` | reserved | Пустой `RET` |
| `54/#36` | `TMRKFL` | `IX` = панель, `HL` = номер 1..2047, `DE` = буфер имени `#8000..#BFFF`; `HL=0` считает отмеченные в `BC` |
| `55/#37` | reserved | Пустой `RET` |
| `56/#38` | `ADIR` | `A'=0` позиционировать начало активного каталога; `A'=1` сбросить FindNext |
| `57/#39` | `STREAM` | Создание, клонирование и переключение потоков, см. ниже |
| `58/#3A` | `NXTETY2` | `DE` = выход, маска в `A'`; `NZ` = запись, `Z` = конец |
| `59/#3B` | `FENTRY` | `HL` → `[тип,имя,0]`; `NZ` найдено, размер в `DE:HL`; `Z` не найдено |
| `60/#3C` | `LOAD256` | Потоковое чтение через драйверный 256-байтовый вход; не каждый драйвер поддерживает |
| `61/#3D` | `LOADNONE` | Линейно пропустить `B` секторов, параметры как LOAD512 |
| `62/#3E` | `GFILE` | После успешного FENTRY выбрать найденный файл и поставить поток в начало |
| `63/#3F` | `GDIR` | После FENTRY сделать найденный каталог активным; не использовать в исходном потоке панели |
| `72/#48` | `MKFILE` | `HL` → `[attr,size_le32,name,0]`; `Z` создан, `NZ` ошибка, код в `A` |
| `73/#49` | `MKDIR` | `HL` → `[name,0]`; `Z` создан, `NZ` ошибка |
| `74/#4A` | `RENAME` | `HL` → `[тип,старое,0]`, `DE` → `[новое,0]`; `NZ` успех |
| `75/#4B` | `DELFL` | `HL` → `[тип,имя,0]`; исторически `NZ` означает удалено |
| `76/#4C` | `APPEND` | После FENTRY: `HL` = данные в `#4000..#BFFF`, `BC=0..#4000`; `Z/A=0` успех |
| `77/#4D` | `FILEX` | `HL` → 32-байтовый блок в `#8000..#BFFF`; позиционный расширенный API |

Формат имени для поиска/удаления/переименования:

```asm
FileName:
        DB      #00,"LOG.TXT",0       ; #00 файл
DirName:
        DB      #10,"GAMES",0         ; #10 каталог
```

Маска API 58:

- bit 7 — только короткие имена;
- bit 4 — добавить create time;
- bit 3 — добавить create date;
- bit 2 — добавить size;
- bits 1..0: 0 любой объект, 1 файл, 2 каталог.

При `NZ` API 58 последовательно пишет включённые поля, затем байт типа записи,
имя длиной 1..255 и ноль. Она использует `#0000..#1FFF` файловой страницы и
теряет позицию после MKFILE/MKDIR/LOAD512/SAVE512/FENTRY. После таких операций
перезапустите перечисление через API 56, подкоманду 1.

Подкоманды API 57 `STREAM`:

| `D` | Действие |
|---:|---|
| `#FF` | Сделать root активным; допустимо только после клонирования |
| `#FE` | Клонировать поток панели в 0 и 1, выбрать поток 0 |
| `#FD` | Выбрать служебный INI-поток и каталог `WC` |
| `0/1` | При `BC=#FFFF` выбрать существующий поток; иначе создать: `B` устройство, `C` раздел |

Для создания потока `B`: 0 SD-ZC, 1 Nemo master, 2 Nemo slave, 4 SMUC master,
5 SMUC slave; поле раздела исторически не учитывается. Возврат `NZ` означает,
что устройство/раздел не найден. Для `D=#FD` код `A=1` — устройство не
найдено, `A=2` — нет каталога `WC`.

| API dec/hex | Имя | Вход/действие |
|---:|---|---|
| `64/#40` | `MNGV_PL` | `A'=0` основной TXT; `1..4` выбрать банк видеобуфера `#20/#30/#40/#50` |
| `65/#41` | `MNGCVPL` | `A'=0..63` отобразить видеостраницу в `#C000` |
| `66/#42` | `GVmod` | `A'`: bits 7..6 разрешение, bits 1..0 ZX/16c/256c/TXT |
| `67/#43` | `GYoff` | `HL=0..511`, вертикальное смещение |
| `68/#44` | `GXoff` | `HL=0..511`, горизонтальное смещение |
| `69/#45` | `GVtm` | `C=0..63`, страница TileMap |
| `70/#46` | `GVtl` | `B bit0` = плоскость 0/1, `C=0..63`, TileGraphics |
| `71/#47` | `GVsgp` | `C=0..63`, SpriteGraphics |
| `80/#50` | `MNG0VPL` | `A'=0..63`, видеостраница в `#0000` |
| `81/#51` | `MNG8VPL` | `A'=0..63`, видеостраница в `#8000` |

Код режима API 66:

- bits 7..6: `00` 256×192, `01` 320×200, `10` 320×240, `11` 360×288;
- bit 5 `nogfx`, bit 4 `notsu`;
- bits 1..0: `00` ZX, `01` 16 цветов, `10` 256 цветов, `11` TXT.

API 80 заменяет окно `#0000`, где файловая страница использует
`#2000..#3FFF`. Пока оно переключено, нельзя передавать файловому API ни
структуры, ни буферы из `#0000..#7FFF`. Публичные файловые обёртки временно
переключают страницы, но адрес данных при этом не начинает указывать на прежнюю
память.

### 6.5 Поздние служебные функции: 78–86

| API dec/hex | Имя | Контракт |
|---:|---|---|
| `78/#4E` | `MNG0_PL` | `A'=0..63`, страница плагина в `#0000` |
| `79/#4F` | `MNG8_PL` | `A'=0..63`, страница плагина в `#8000` |
| `80/#50` | `MNG0VPL` | Видеостраница в `#0000` |
| `81/#51` | `MNG8VPL` | Видеостраница в `#8000` |
| `82/#52` | reserved | Пустой `RET` |
| `83/#53` | `PRM_PL` | `A'=1..8`; `NZ` и `A=1..10` — выбранная опция, `Z` — параметра нет |
| `84/#54` | `SCRLWOW` | `IX`, `D/E=Y/X`, `B/C=height/width`, режим в `A'` |
| `85/#55` | `INS_KEY` | `NZ` при Insert |
| `86/#56` | `INT_PL` | Настроить подавление INT или обработчик плагина |

API 84, bits `A'`:

- bit 7 — переносить атрибуты вместе с символами;
- bit 6 — очищать освободившийся край;
- bits 5..2 — шаг 1..16 символов;
- bits 1..0: 0 вниз, 1 вверх; вправо/влево в текущей реализации отключены.

API 86:

- `A'=0` — отключить все INT-функции WC на время работы плагина;
- `A'=1` — отключить обновление часов;
- `A'=2` — отключить опрос PS/2;
- `A'=#FF`, `HL=#8000..#BFFE` — зарегистрировать обработчик плагина.

Все настройки API 86 восстанавливаются при выходе из плагина. Обработчик
должен находиться на странице плагина, оставаться отображаемым по контракту WC,
быть коротким и не вызывать нереентерабельный файловый API.

## 7. Готовые рецепты

### 7.1 Найти и прочитать файл

```asm
        LD      HL,Query
        LD      A,59                  ; FENTRY
        CALL    WLD
        JR      Z,.not_found

        LD      A,62                  ; GFILE: поток в начало найденного файла
        CALL    WLD

        LD      HL,Buffer
        LD      B,1                   ; один сектор
        LD      A,48                  ; LOAD512
        CALL    WLD
        JR      C,.io_error
        ; A=#0F означает физический конец FAT-цепочки.
        ; Логический объём полезных байтов берётся из размера DE:HL FENTRY.
        RET

Query:  DB      #00,"DATA.BIN",0
Buffer: DS      512
```

Не читайте файл «до `#0F`» без учёта размера: последний кластер обычно
содержит padding после логического EOF.

### 7.2 Перечислить каталог, не ломая поток панели

```asm
        LD      D,#FE                 ; клонировать поток панели
        LD      A,57
        CALL    WLD

        LD      A,1                   ; reset FindNext активного каталога
        EX      AF,AF'
        LD      A,56
        CALL    WLD

.next:
        LD      DE,EntryBuffer
        LD      A,%00000100           ; размер + любой тип
        EX      AF,AF'
        LD      A,58
        CALL    WLD
        JR      Z,.done
        ; Разобрать [size32][flag][name,0].
        JR      .next
.done:
```

### 7.3 Создать файл заданного размера

```asm
CreateBlock:
        DB      #00                   ; атрибуты
        DD      0                     ; пустой файл, cluster=0
        DB      "NEW.TXT",0

        LD      HL,CreateBlock
        LD      A,72
        CALL    WLD
        JR      NZ,.create_error
```

Для непустого файла API 72 заранее создаёт цепочку нужного размера, но не
записывает пользовательские данные. API 49 записывает только уже существующую
цепочку. Для безопасного роста существующего файла используйте API 76 или 77.

### 7.4 Дописать данные через APPEND

```asm
        LD      HL,Target
        LD      A,59                  ; обязательно свежий успешный FENTRY
        CALL    WLD
        JR      Z,.not_found

        LD      HL,Data
        LD      BC,DataEnd-Data       ; 0..#4000
        LD      A,76
        CALL    WLD
        JR      NZ,.append_error      ; A = код
        ; Z и A=0: данные и новый размер опубликованы.

Target: DB      #00,"LOG.TXT",0
Data:   DB      "line",13,10
DataEnd:
```

Весь `[HL,HL+BC)` должен лежать в `#4000..#C000`. Неуспешный FENTRY не очищает
старый APPEND-контекст, поэтому игнорировать его `Z` опасно. `BC=0` — только
пустая операция, не проверка контекста.

### 7.5 Позиционное чтение через FILEX

Сначала нужен успешный API 59 для файла. Затем:

```asm
        LD      HL,FilexBlock
        LD      A,77
        CALL    WLD
        JR      Z,.complete
        CP      #01                   ; EOF может содержать прочитанный префикс
        JR      Z,.partial_or_eof
        JR      .filex_error

FilexBlock:
        DB      32,1                  ; size, version
        DB      1,0                   ; READ_AT, flags
        DD      #00123456             ; offset LE32
        DW      Buffer
        DW      512
        DW      0,0                   ; aux, aux_length
        DD      0,0                   ; source_dir, dest_dir
        DD      0                     ; result_count
        DB      0,0                   ; status, result_flags
        DW      0                     ; reserved
Buffer: DS      512
```

Блок и все его буферы должны целиком лежать в `#8000..#BFFF`, не пересекаться
между собой и не выходить за `#C000`. Перед каждым вызовом блок лучше полностью
занулять, затем заполнять используемые поля. Полный контракт FILEX находится в
[руководстве DOS](04-dos-layer.md#10-api-77-filex).

### 7.6 Попросить менеджер обновить панель

Если плагин изменил содержимое каталога и завершил все операции:

```asm
        LD      A,3
        RET
```

Не пытайтесь вручную править внутренний массив панели: перестроение перечитает
каталог, пересортирует индекс и согласует курсор.

## 8. Параметры плагина в `wc.ini`

В `+260` лежит последовательность записей:

```text
[record_length]
[default_option]
[parameter_name in lowercase]
[option_count]
[option_1,0][option_2,0]...[option_n,0]
```

Нулевой `record_length` завершает таблицу. Загрузчик распознаёт до восьми
параметров плагина, имя передаётся с дефисом, например:

```ini
[PLUGINS]
MYPLUGIN.WMF -loading=fast -cache=off
```

API 83 получает выбранную опцию по индексу параметра `1..8`; номер опции
начинается с 1. Если параметр не указан в `wc.ini`, возвращается default.

## 9. Ограничения, которые должен учитывать плагин

- API не реентерабелен. Не запускайте файловую операцию из INT-обработчика или
  внутри другой файловой операции.
- `IX` активной панели — входной объект менеджера. Не храните его как вечный
  указатель после возврата в WC и не меняйте внутренние поля без изменения
  самого менеджера.
- API 48/49 не должны получать блок, который переходит через
  `#FFFF→#0000`; разбивайте такой диапазон на два вызова.
- `SAVE512` не увеличивает файл. Для роста есть APPEND и FILEX.
- API 75 не защищает от удаления непустого каталога. Сначала перечислите его.
- `LOAD256` не реализован драйвером SD-NGS.
- `GEDPL` разрушает `#1000..#1447` подключённой страницы `#0000`.
- Структуры FILEX допускаются только в `#8000..#BFFF`.
- Исторические `wc_api.h/wc_h.h` содержат неверные поздние номера и устаревшие
  подписи. Числа следует брать из таблицы `PLUGIN_API_TABLE` в `MD20.ASM`, а
  FILEX-константы — из `CORE32_FILEX_API.ASM`.

## 10. Где смотреть рабочие примеры

- `source/plugins/PLUG01.ASM`, `PLUG02.ASM`, `PLUG03.ASM` — простые окна и
  вызовы интерфейса; их старые заголовки полезны как каркас, но версия формата
  там историческая.
- `source/plugins/txt_editor/TXTEDIT.ASM` — строковый ввод и текстовый UI.
- `source/plugins/bmpview/PLUGBP.ASM` — видеостраницы и графика.
- `source/plugins/multigigascreen/MCGSV.ASM` — переключение окон видеопамяти.
- `source/plugins/filex/FILEX.ASM` — корректный 512-байтовый заголовок и
  одноразовый тип `#06`.
- `source/plugins/READ_ME.TXT` — исходное историческое описание ABI.
